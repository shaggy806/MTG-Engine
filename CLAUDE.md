# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

MTG-Engine is a Magic: The Gathering rules engine (`engine/`) with an authoritative multiplayer
room server (`server/`) and a React web client (`client/`) — a real networked 2-4 player game
(Commander-capable), not a local hot-seat demo. The repo is an **npm workspaces monorepo**
(`workspaces: ["engine", "server", "client"]` in the root `package.json`, in that order so
`engine` builds first, then `server`).

- `engine/` — a TypeScript library package, ESM (`"type": "module"`), NodeNext resolution. Emits to `dist/` with declarations; `package.json` `exports`/`main`/`types` point there. No I/O, no UI — a pure state machine driven entirely through `dispatch`.
- `server/` — a Node + `ws` package: the authoritative multiplayer room host. Owns the one real `Game` instance per room, keyed by a room code; every connected device gets its own redacted `viewFor(seat)` pushed after each dispatch. Imports `engine` the same way `client` does.
- `client/` — a Vite + React 19 + TypeScript app: a **networked** client — each device is one seat, connected over WebSocket to a `server` room, never running a local `Game` or a controller loop itself. Imports `engine` (`"engine": "*"`, the workspace symlink) and consumes only its public seam — `Game`, `viewFor`, `legalActions`, `dispatch`, the `Action`/`LegalAction` types — indirectly, via the wire protocol `server` speaks. Needs `engine/dist/` built (`npm run build` does engine, then server, then client).

## Engine architecture (`engine/src/`)

Implemented — turn/step loop, casting + targeting + fizzle, LIFO stack, SBAs, full combat **with
first strike / double strike / trample / deathtouch / lifelink / menace**, activated abilities,
triggered abilities, the layers 6+7 continuous-effects pipeline, **tokens** (minted by
`create-token` effects, cease to exist once they leave the battlefield), **Auras & Equipment**
(attach on resolution / via an `attach` effect, a static `"attached"` scope, sorcery-speed-only
abilities, and an Aura fall-off SBA), **Commander** (cast from the command zone with an
escalating `{2}` tax, **commander replacement as the owner's choice** (rule 903.9a — when a
commander is put into a hidden zone the game pauses on a `commander-replacement` decision;
`AutomaticController` says "command zone"), commander combat damage tracked toward a 21-damage
loss, the legend rule keeping the oldest of two same-named legendary permanents a player
controls), **mulligans** (an opt-in London
mulligan — see `GameConfig.mulligans` — draw 7, shuffle back and redraw as many times as wanted,
then bottom one card per mulligan taken), **2-4 players** (attackers choose any non-eliminated
opponent; `declare-blockers` asks each attacked defender in turn, one at a time; APNAP trigger
ordering rotates through every non-active player, not just "the one other player"), **every
decision as a dispatched action** (`declare-attackers` / `declare-blockers` / `order-blockers` /
`discard` / `choose-from-zone` / `mulligan` / `put-on-bottom` alongside the priority actions;
`chooseTargets` for triggered-ability targets is the last synchronous controller callback),
**`legalActions(player)`** enumerating what is playable right now with per-slot target options,
and **`viewFor(player)`** producing a redacted, self-contained snapshot for one seat.
**Wave 1 additions** — `return-to-hand` / `exile` / `mill` / `discard` (targeted) one-shot
effects, a `sequence` effect combinator (Blightning), **`{X}` in a spell's mana cost** (chosen
at cast time via `cast-spell.xValue`, folded into generic when paid, stored on the stack object
as `GameObject.xValue`, exposed to effects as `ResolutionContext.x` / `EffectAmount = number | "x"`),
**sacrifice as an activated-ability cost** (`AbilityCost.sacrifice: "self" | "creature-you-control"`),
and a spell resolving into a decision owed by a *non-active* player (Mind Rot on an opponent —
`passPriority` now routes priority to `awaiting.player`).
**Wave 2 additions** — the `fight` effect (`{a, b, oneSided?}`); `counter` effect + the
`spell` / `creature-spell` / `noncreature-spell` target specs (`legalTargets` now enumerates
the stack); `proliferate` effect (simplified: proliferates *everything* eligible, no "choose
any number"); the `indestructible` / `hexproof` / `flash` keywords (SBA skip / opponent-target
block / instant-speed casting respectively); the `cast-spell` `TriggerSpec` (prowess); and the
`deals-combat-damage-to-player` `TriggerSpec` with `PendingTrigger.autoTargets` (a saboteur's
first target slot is auto-filled with the player it hit — `damage-dealt` now carries `combat`).
**Wave 3 (in progress)** — **layer 2 control-change** (modeled by reassigning
`GameObject.controller`, *not* a computed characteristic): the `gain-control` effect (Act of
Treason — `controlEndsAtCleanup` reverts it in cleanup), `CardDefinition.controlEnchanted` (Mind
Control — a `recomputeControl` SBA pass keeps a control-Aura's host under the Aura controller,
latest timestamp wins; `moveObject` reverts to owner on any zone change); and **layer 7b**
(`StaticAbility.setBasePtFromCount` — a `"self"` CDA sets base P/T from a live `CountSpec`,
before 7c/7d). **Not yet** — layers 1 (copy — Clone), 3–5 (text, **type-change**, colour),
replacement effects (so no "enters with X counters" — X creatures wait on this),
tutors/library search beyond `look-and-choose`, `ward`, dependency ordering, the first-strike
priority window, trample assignment as a *player* choice (it's auto-assigned), planeswalkers,
sagas, `{X}` in an activated-ability cost, the 903.9a choice modeled as a true *replacement*
(here it's made just *after* the commander lands, so a "when this dies" trigger on the commander
would still see the graveyard — no such commander in the pool), a player choice on which legendary permanent the legend
rule keeps (deterministic: oldest survives), simultaneous (rather than sequential per-player)
mulligan rounds.

- **`state.ts`** — `GameState` is one plain, `structuredClone`-able tree (no class instances, `Map`/`Set`, or functions inside it). Holds `rules` (`startingLife`, `openingHandSize`, `maxHandSize`, `maxLandsPerTurn`, `skipFirstDraw`), players, `objects` (card instances; `GameObject.kind` `"card"`|`"ability"`, `abilityKind`, `sourceObjectId`/`abilityIndex`, `counters`, `modifiers`; combat & counter/modifier fields cleared by `moveObject` on any zone change), `zones` (`perPlayer` library/hand/graveyard + `shared` battlefield/stack/exile/command as ordered `ObjectId[]`; stack top = last), `turn`, `priority`, `result`, `awaiting` (a discriminated `AwaitingDecision` — `attackers` / `blockers` / `order-blockers {attacker}` / `discard {count, fromEffect?}` — `fromEffect` distinguishes a Mind-Rot-style discard from the cleanup-step one — / `choose-from-zone {...}` / `mulligan {count}` / `mulligan-bottom {count}` / `commander-replacement {commander, movedTo}` (903.9a)), `pendingBlockerOrders` (multi-blocked attackers still needing a damage order, drained one `order-blockers` action at a time), `pendingBlockerDeclarations` (3+ player games: defending players still owed a declare-blockers turn this combat, drained one at a time the same way), `pendingTriggers` (fired triggers not yet on the stack), `pendingCommanderChoices` (commanders in a hidden zone whose owner hasn't picked yet — drained one `commander-replacement` action at a time by `promptCommanderChoice`), `eventLog`. `GameObject` also carries `markedByDeathtouch` (set when dealt damage by a deathtouch source; a lethal-damage SBA reads it; cleared with `damageMarked` on zone change and in cleanup), `summoningSick` (a boolean — set true on entering the battlefield, cleared in the controller's untap step; `hasSummoningSickness` just reads it, so a creature stays sick through the opponent's turn), `isToken` (rule 111 — a token-cleanup SBA deletes it once it's off the battlefield; never reset by `moveObject`, it's intrinsic), `attachedTo` (the permanent an Aura/Equipment is attached to, or `null`; reset to `null` on any zone change), `isCommander` (intrinsic like `isToken` — lets it be cast from the command zone with tax; when it's put into a hidden zone the owner is asked whether to move it to the command zone via a `commander-replacement` decision — no longer an automatic redirect), `controlEndsAtCleanup` (a temporary steal — Act of Treason — reverts `controller` to `owner` in cleanup; `moveObject` also reverts on any zone change), and `xValue` (the `{X}` chosen when this spell was cast — kept on the stack object and onto the permanent it becomes, `null` when no `{X}`; cleared by `moveObject` on a later zone change). `PlayerState` also carries `commanderCastCount` (times this player has cast their commander from the command zone — each one adds `{2}` generic to its cost next time) and `commanderDamageTaken` (a per-opponent-commander running total; 21+ from the same commander is a loss). Also exports pure selectors.
- **`game.ts`** — `Game` owns the single mutable `GameState` and is the **only** writer. `dispatch(action)`: `pass-priority` / `play-land` / `cast-spell` / `activate-ability` / `declare-attackers` / `declare-blockers` / `order-blockers` / `discard` / `choose-from-zone` / `mulligan` / `put-on-bottom` / `commander-replacement`. Multi-blocked attackers are queued in `pendingBlockerOrders` and drained one `order-blockers` action each by `promptNextBlockerOrder`; in a 3-4 player game, `declareBlockersStep` first queues every attacked defender (turn order starting after the active player) into `pendingBlockerDeclarations` and `promptNextBlockerDeclaration` drains that one `declare-blockers` action at a time, skipping anyone with no eligible blocker, before falling through to the blocker-ordering queue. `legalDefenders(attacker)` (any non-eliminated player besides the attacker) replaces the old single hard-coded "the other player" — `whyCannotAttack` and `legalActions`'s `"attackers"` branch both just check membership in it now. `advance()` / `advanceUntil(pred)` run `tick()`. `emit()` appends the event **and** runs `detectTriggers` (scans battlefield permanents' `triggered` list against the event, queues matches to `pendingTriggers`). `prepareForPriority(player)` — the pre-priority routine used by `enterStep`, `afterPlayerAction`, and post-resolution: loop { SBAs; `placePendingTriggers` (APNAP: active player's triggers first, then each other player's in turn order — a real rotation, not just "the one other player") } until stable, then grant priority. Mana **auto-paid** via `manaSources`/`tapManaSource`; `castingCostOf` adds the commander tax (`commanderTax(player) = 2 * commanderCastCount`) on top of a commander's printed cost when casting from the command zone. Ability objects (activated or triggered) are minted onto the stack by `mintAbilityObject` and `delete`d from `state.objects` when they resolve. All P/T reads (combat, SBAs) go through `characteristicsOf`. `combatDamageStep` runs two passes when any combatant has first/double strike (`dealCombatDamage("first")` → SBAs → `"regular"`; folded into one step, no priority window). Blocked-attacker assignment auto-assigns lethal down `blockedBy` (lethal = 1 with deathtouch), then a trampler sends the rest to the defending player; `dealCombatDamage` also increments the target's `commanderDamageTaken` when the source is a commander. `dealDamage` applies deathtouch marking + lifelink (both general — work for burn, not just combat). `createTokens(controller, tokenName, count)` mints token `GameObject`s straight onto the battlefield (same shape as `playLand`/casting, `isToken: true`); `attachPermanent(source, target)` sets `attachedTo` and is how Equip-like effects attach. `resolveTopOfStack` auto-attaches an Aura (`def.subtypes.includes("Aura")`) to its spell target right after it enters the battlefield. `moveObject` records a `pendingCommanderChoices` entry when a commander is put into hand/library/graveyard/exile; `prepareForPriority` drains that queue via `promptCommanderChoice` (sets `awaiting`, hands the owner priority — works even for a non-active player), and `applyCommanderChoice` moves it to the command zone or leaves it (903.9a). `beginMulligans`/`advanceMulligans`/`applyMulligan`/`applyPutOnBottom` drive the opt-in mulligan phase (`GameConfig.mulligans`, default off so every existing `Game.create` caller is unaffected) before turn 1 begins. Wave 1: `castSpell` takes an `xValue` (validated ≤ `maxAffordableX`, folded into `castingCostOf`'s generic, stored on the object); `activateAbility` takes a `sacrifice` and moves the victim to the graveyard as part of paying the cost, before the ability is minted; `returnToHandByEffect` / `exileByEffect` / `millByEffect` / `discardByEffect` back the new effects (a `discardByEffect` sets `awaiting {fromEffect:true}` when the hand is too big to auto-discard); after a resolution, `passPriority` grants priority to `awaiting?.player ?? activePlayer` so a decision owed by a *non-active* player (Mind Rot) is reachable. `runStateBasedActions` first runs `recomputeControl` (layer 2 — a permanent is controlled by its owner unless `controlEndsAtCleanup` or an attached `controlEnchanted` Aura says otherwise), then sweeps: an Aura whose host is gone goes to the graveyard (reason `"no longer attached to a legal permanent"`); Equipment in the same spot just clears `attachedTo` and stays; a token off the battlefield is deleted from `state.objects` outright (rule 704.5d); a player controlling 2+ same-named legendary permanents keeps only the one they've controlled longest (704.5j, no player choice modeled) and destroys the rest; 21+ combined damage from one commander is a loss.
- **`actions.ts`** — the `Action` union (priority actions plus `declare-attackers` / `declare-blockers` / `order-blockers` / `discard` / `choose-from-zone` / `mulligan` / `put-on-bottom` / `commander-replacement {toCommandZone}`; `cast-spell` carries optional `xValue`, `activate-ability` optional `sacrifice: ObjectId`), the `AttackerDeclaration` (`{attacker, defender}`, `defender` any legal opponent — not fixed to "the" opponent) / `BlockerDeclaration` payloads, and `LegalAction` (what `legalActions` returns; `"declare-attackers"` carries `defenders: readonly PlayerId[]`, every legal opponent an attacker could be declared against; the `declare-blockers` variant carries `menaceAttackers` — block them with 0 or 2+ creatures; `cast-spell` carries `xCost: { maxX }` for an X spell — the largest X currently affordable; `activate-ability` carries `sacrifice: { choices }` when the cost is a `"creature-you-control"` sacrifice). Kept out of `game.ts` to avoid a cycle with `controller.ts`.
- **`view.ts`** — `viewFor(state, registry, viewer, opts)` / `game.viewFor(player)` → a `PlayerView`: your hand in full, every other player's as a count, libraries as counts only, battlefield/stack/graveyards public with **computed** power/toughness/keywords baked in (plus `isToken`/`attachedTo`/`isCommander`/`xValue`), so a client needs neither the registry nor the layer system. Also exposes `startingPlayer` (who the "highroll" — see `GameConfig.startingPlayer` — picked to go first; fixed for the whole game, unlike `activePlayer`, which changes turn to turn). `PublicPlayerInfo` (per player) exposes `commanderDamageTaken` and `commanderCastCount` (the latter is how a client can display the current commander tax, since the engine never bakes an adjusted cost into a card's own `manaCost` string). `{ revealAll: true }` for a spectator/debug view.
- **`turn.ts`** — `Phase`/`Step` string-literal unions (no `enum`), `TURN_SEQUENCE`, `nextStep`, `stepUsesPriority` (false only for untap/cleanup), `isMainPhase`.
- **`events.ts`** — discriminated `GameEvent` union (the audit log). `emit()` takes `GameEventInput` (no `seq`). `permanent-attached {source, target}` fires whenever an Aura/Equipment attaches; `mulligan-taken`/`hand-kept`/`cards-put-on-bottom` cover the mulligan phase; Wave 1 added `permanent-returned-to-hand` / `permanent-exiled` / `permanent-sacrificed` / `cards-milled`, and `spell-cast` now carries `x` (the chosen `{X}`, or `null`); Wave 2 added `spell-countered` / `permanent-destroy-prevented`, and `damage-dealt` carries `combat`; Wave 3 added `control-changed {object, controller, untilEndOfTurn}`; the 903.9a choice added `commander-zone-decision {object, toCommandZone, from}`. Both log formatters (`scripts/format.mjs`, `client/src/format.ts`) render them.
- **`cards.ts`** — `CardDefinition` is **declarative** (`effect`, `keywords`, `activated`, `triggered`, `static: StaticAbility[]`, `supertypes` for `"legendary"`/`"basic"`/etc.) with an imperative `resolve(ctx)` hatch. `StaticAbility` = `{ affects: AffectSpec, grantPt?, grantKeywords?, setBasePtFromCount? }` (the last is a layer-7b CDA — only with `affects: "self"`); `AffectSpec` = `"self"` / `"creatures-you-control"` (`+ excludeSelf? / subtype?` for lords) / `"attached"` (the permanent the source is attached to — how Auras/Equipment grant their bonus). An Aura with `controlEnchanted: true` (Mind Control) grants its controller control of the enchanted permanent. Basic lands carry a synthesized `{T}: Add {C}`. The `Keyword` union covers `flying`/`reach`/`haste`/`vigilance`/`defender`/`first-strike`/`double-strike`/`trample`/`deathtouch`/`lifelink`/`menace` (all wired into combat) plus `indestructible` (SBAs / `destroyByEffect` skip it — but 0 toughness still kills it), `hexproof` (`isLegalTarget` blocks a target whose controller isn't the source's controller), and `flash` (instant-speed casting). An Aura is `types: ["enchantment"], subtypes: ["Aura"]` (`resolveTopOfStack` special-cases the `"Aura"` subtype for auto-attach and `runStateBasedActions` for fall-off); Equipment is `types: ["artifact"], subtypes: ["Equipment"]` plus an `Equip {cost}` activated ability (`effect: {kind:"attach", target:0}`, `targets: ["creature-you-control"]`, `sorcerySpeed: true`) — nothing else marks a card as an Aura/Equipment. A token is just a `CardDefinition` like any other (e.g. `"Soldier Token"`), registered the same way and minted via `createTokens`/`create-token`, not cast. A commander is any `CardDefinition` named by a `DeckList.commander` — `supertypes: ["legendary"]` is customary but not itself what makes a card a commander; only two exist in the pool today (`Ureni of the Unwritten`, `Ashmark, Mardu Vanguard`). `CardRegistry` resolves name → definition (environment, not serialized). `landProduces(def)`, `hasKeyword(def, kw)`, `defineCard(draft)`. **`cards.ts` is now a thin re-export barrel** — the content lives in `cards/`: `cards/define.ts` (the `CardDefinition`/`CardDraft` shape + `defineCard`/`hasKeyword`), `cards/helpers.ts` (`basicLand`, `manaTapAbility`, `landProduces`), `cards/registry.ts` (`CardRegistry`, `createDefaultRegistry`), and **one file per card** under `cards/pool/` (real cards + basics) and `cards/tokens/` (each a `export default defineCard({…})`). `cards/generated.ts` is the codegen'd barrel that imports every card file into `BUILTIN_CARDS` — regenerated by `scripts/gen-cards.mjs` (`npm run gen:cards -w engine`, also a `prebuild`/`pretypecheck` step; the file is checked in). `cards/pool.test.ts` fails if a card file isn't wired into `generated.ts`. To add a card: drop a new file in `cards/pool/`, run `gen:cards` (or `build`/`typecheck`).
- **`abilities.ts`** — `ActivatedAbility` (`cost: {mana, tap, sacrifice?}` — `sacrifice` is `"self"` or `"creature-you-control"`, rule 602.1a/118.12; optional `sorcerySpeed` — Equip-like abilities that function only as a sorcery, rule 602.3), `TriggeredAbility` (`trigger: TriggerSpec` — `enters-battlefield` / `dies` / `attacks` / `deals-combat-damage-to-player` (auto-targets the damaged player) / `step-begins {step}` / `cast-spell {who, noncreatureOnly?}` (prowess) / `predicate` escape hatch), `isManaAbility` (also excludes anything with a sacrifice cost).
- **`effects.ts`** — `EffectSpec` vocab (`sequence {effects}` — apply several in order sharing targets+X; `damage` (`amount: EffectAmount = number | "x"`), `add-mana`, `draw`, `gain-life`, `tap`, `untap`, `destroy`, `fight {a, b, oneSided?}`, `counter {target}` (a spell on the stack), `gain-control {target, untilEndOfTurn}` (Act of Treason), `return-to-hand {target}`, `exile {target}`, `mill {target, amount}`, `discard {target, amount}` (target player's own choice unless it's the effect's controller), `modify-pt`, `add-counter`, `proliferate` (proliferates every eligible permanent — the "choose any number" clause isn't modeled), `grant-keyword`, `create-token {token, count}`, `attach {target}`, `look-and-choose {zone, count, min, max, destination, leftover, filter?}` — a general "reveal N, choose some" primitive powering Ureni's ETB, with `ZoneChoiceFilter` narrowing which revealed candidates are actually choosable without hiding any of them), `EffectApi` / `ResolutionContext` (`ctx.x` is the chosen `{X}`, 0 if none; `amountValue(amount, ctx)` resolves an `EffectAmount`), `applyEffectSpec`.
- **`characteristics.ts`** — `computeCharacteristics(state, registry, id)` / `game.characteristics(id)` → `{ power, toughness, keywords: Set, types, subtypes, controller }`. Folds printed → layer 6 (keyword grants from `static` abilities + modifiers) → **layer 7b** (a `"self"` static's `setBasePtFromCount` replaces base P/T with a live `countValue` — cards / creature-cards in all graveyards, lands you control) → layer 7c (counters) → layer 7d (P/T grants + modifiers), timestamp-ordered (`GameObject.timestamp`, from `state.timestampSeq`, set in `moveObject` on entering the battlefield). `staticAffects` resolves the `"attached"` scope as `source.attachedTo === target.id`. **Layers 1 and 3–5 and dependency ordering are not implemented.**
- **`target.ts`** / **`targeting.ts`** — `TargetRef` (player or object) and `TargetSpec` (`"any-target"` / `"creature"` / `"creature-you-control"` / `"creature-an-opponent-controls"` / `"player"` / `"creature-or-player"` / `"permanent"` / `"nonland-permanent"` / `"land"` / `"artifact-or-enchantment"` / `"creature-or-enchantment"` / `"spell"` / `"creature-spell"` / `"noncreature-spell"` — the last three are a card on the stack). `isLegalTarget` / `legalTargets` take a `forPlayer: PlayerId` (needed for `"creature-you-control"`, e.g. Equip, and for the hexproof check) alongside the registry, and enumerate every player in `turnOrder`, then the battlefield, then the stack. Checked on cast and again at resolution (all-illegal ⇒ fizzle).
- **`mana.ts`** — `Color`/`ManaType`/`ManaPool`, `parseManaCost` (`{2}{G}` / `{X}{R}` → `{generic, colored, x}`; `x` is the `{X}` count, kept separate from `generic` until an X value is chosen; no hybrid/Phyrexian/`{C}` yet), `manaValue` (counts `{X}` as 0).
- **`controller.ts`** — `PlayerController.act(view)` is the **single entry point**: when `view.state.awaiting` is set it must return that declaration, otherwise any legal priority action. `ControllerView` carries `state`, `player`, and `legalActions()`. The base classes implement `act` by delegating to `chooseDiscards` / `declareAttackers` / `declareBlockers` / `orderBlockers` / `chooseFromZone` / `mulligan` / `chooseBottomOfLibrary` / `commanderReplacement` (all reached via `answerAwaited` when `state.awaiting` is set); `chooseTargets` (triggered-ability targets) is the only method still called directly by the engine. `AutomaticController` passes, never attacks/blocks, and always keeps its opening hand (0 mulligans) — chosen specifically so adding mulligans didn't change any existing test's behavior. `ScriptedController` plays a `{action, when?}` queue plus assignable `*Fn` callbacks (what the tests use); `RandomController` picks uniformly from `legalActions()` — including a random `xValue` up to `xCost.maxX` and a random `sacrifice` from `sacrifice.choices` — and is the engine fuzzer (see `random-demo.mjs`).
- **`primitives.ts`** — branded `PlayerId`/`ObjectId`, seeded `Rng` (mulberry32; `rng.seed` = stream position), `shuffle`.
- **`auto-settle.ts`** — `isSettled(state)` (game-over, an `awaiting` declaration, or someone holding priority) / `autoSettle(game)`: cascades `advanceUntil(isSettled)` past every "dead" priority window (the holder's only legal action is `pass-priority`) in one go. `autoSettle` is what `RoomManager.create` calls once, right after `Game.create`, to settle a fresh room to its first real decision — `Room`'s own per-dispatch `settle()` deliberately does *not* call it mid-game (see `room.ts`): its loop advances `isSettled` one stopping point at a time instead, because auto-pass/skip-mana-only are per-seat, one-shot-per-call decisions that `autoSettle`'s uninterrupted cascade would blow straight past.

Snapshot/restore: `game.snapshot()` → `structuredClone(state)`; `Game.fromSnapshot(snap, env)` rebuilds (re-supply `registry`/`controllers` via `env`). Determinism: same seed + same controllers ⇒ identical replay.

## Server architecture (`server/src/`)

The authoritative multiplayer host. One process can run many rooms; each room owns exactly one
real `Game` and pushes every connected seat its own `viewFor` after each settle. Transport-agnostic
at the `Room` level (a `Connection` is just "something we can push a `ServerMessage` to"), so it's
unit-testable without a real WebSocket — `ws-server.ts` is the only place that touches `ws` itself.

- **`room.ts`** — `Room` wraps one `Game` plus a `Seat` per `turnOrder` entry (`clientToken`, `connection`, `autoPassUntil`, `skipManaOnly`, `displayName`). `claimSeat(player, clientToken, connection, displayName?)` binds a connection to a seat — a seat already claimed by a *different* token is rejected even while offline (so a dropped connection can't hand the seat to a stranger mid-reconnect; `ws-server.ts` follows a rejection with a fresh `room-joined`), the same token reclaims it; `displayName`, when given, is trimmed and capped at 20 characters and only overwrites what's already stored if it's non-empty (so a silent reconnect never blanks out a name chosen earlier). `dispatch(connection, action)` resolves which seat owns `connection` and forwards to `Game.dispatch`, then calls `settle()`. `settle()` (built on the engine's `isSettled` primitive, one stopping point at a time — deliberately *not* `autoSettle`, see `auto-settle.ts`) auto-passes a seat's own dead priority windows, windows where tapping for mana is the only option (if that seat opted into `skipManaOnly`), or an entire turn/until-my-turn stretch (if `requestPassTurn`/`requestAutoPass` armed it) — one settle-step per call, so a just-reached stopping point is never skipped over. `seatStatuses()` → `SeatStatus[]` for the wire.
- **`room-manager.ts`** — `RoomManager.create(config: GameConfig)` mints a room code, builds a `Game.create(config)`, and calls the engine's `autoSettle(game)` once to settle it to its first real decision (game over the instant it's created otherwise isn't possible, but with `mulligans: true` this correctly stops right at the first mulligan prompt rather than resolving it). `get(id)` looks a room up. No player-count assumption — it just forwards whatever `decks` array it's given.
- **`ws-server.ts`** — `attachRoomServer(wss, manager)` wires a `WebSocketServer` to a `RoomManager`: parses each connection's messages as `ClientMessage`s, dispatches to the matching `Room`/`RoomManager` call, and pushes `ServerMessage`s back (a `state` broadcast to every connected seat after `claim-seat`/`dispatch`/`pass-turn`/`auto-pass`/`toggle-mana-skip`). `create-room` clamps an optional `players` (2-4, default 2), slices `decks.ts`'s `SEATS` array to that many decks, and rolls a random `startingPlayer` among them (the "highroll") — independent of the shuffle `seed`, so it doesn't shift the deterministic draw order tests/replays rely on.
- **`protocol.ts`** — the wire protocol, duplicated (not imported) in `client/src/net/protocol.ts` since they're independent workspaces — keep the two in sync by hand. `ClientMessage`: `create-room {seed?, players?}`, `join-room`, `claim-seat {seat, clientToken, displayName?}`, `dispatch {action}`, `pass-turn`, `auto-pass`, `toggle-mana-skip`. `ServerMessage`: `room-created`, `room-joined {seats}`, `state {seat, view, actions, seats, autoPassing, skipManaOnly}`, `error`. `SeatStatus` carries `{player, claimed, online, displayName}`. Doesn't cover `/import-deck` (see `import-deck.ts` below) — that's a plain HTTP route, not a room-based WS message.
- **`decks.ts`** — `SEATS: SeatDeck[]`, up to four named seats (`ALICE`/`BOB`/`CAROL`/`DAVE`) in seating order, sliced by `create-room`'s `players` count. Alice (`Ureni of the Unwritten`) and Bob (`Ashmark, Mardu Vanguard`) have commanders; Carol and Dave are plain 40-card decks for now — there are no other legendary creatures in the card pool to give them one yet. `COMMANDERS`/`DECKS` re-derive Alice's/Bob's entries by name for tests that construct a `Game` directly rather than through a room.
- **`import-deck.ts`** — a decklist feasibility audit, unrelated to any room: `parseDecklistText(text)` parses a pasted plain-text decklist export (Moxfield's "Export" feature — `"N Card Name"`, optionally with a `"(SET) collector-number"` printing suffix and a `*F*`/`*E*` foil/etched marker; split-card names are tolerated too), and `evaluateDecklist(entries, registry)` cross-references each unique name against the engine's `CardRegistry` by exact match — implemented cards are reported straight from their local `CardDefinition` (no network call), everything else is looked up on Scryfall (`lookupScryfall`, with a `" // "`/front-face-name fallback for split cards) for its real mana cost/type line/Oracle text so a human can review feasibility. This is the only thing automated — it never guesses whether an unimplemented card *could* be. Scryfall calls are throttled well under its 10 req/sec limit with 429-aware retry (a first, tighter throttle attempt actually tripped a real rate-limit block partway through an 89-card deck). Wired up in `index.ts` as a plain `POST /import-deck` HTTP route (not the WS protocol) — `index.ts` now builds an explicit `http.Server` shared between that route and the `WebSocketServer`, instead of the `WebSocketServer` making its own internal one via `{ port }`. Live-fetching a Moxfield URL server-side was tried and abandoned (403s in testing) — pasted export text only.

`server/scripts/smoke.mjs` (`npm run smoke -w server`) is the server's own eyeball check — spins up
a real room server in-process, has two WebSocket clients create a room, claim both seats, and trade
passes, printing every pushed `state` message — the same role `engine/scripts/play.mjs` plays for
the engine alone.

## Client architecture (`client/src/`)

A **networked** client: each device is one seat, connected over WebSocket to a `server` room. It
never owns a `Game` or runs a controller loop itself — the human's choice is sent as a `dispatch`
message, and the server pushes back the settled `state` for every connected seat. 2-player rooms
render a classic vertical layout (opponent row above your own); 3-4 player rooms render a 2x2
quadrant grid instead, with you always bottom-left.

- **`net/useNetworkGame.ts`** — owns the WebSocket connection and the current seat's `PlayerView`/`actions`/`seats`; never runs a local `Game`. Reconnects with exponential backoff, and a previously-claimed seat (its `clientToken` in `sessionStorage`, keyed by room id — per-tab on purpose, so two seats claimed from two tabs of the same browser don't stomp each other) is reclaimed automatically on load. A claim is only written to `sessionStorage` once the server *confirms* it with a `state` (`pendingClaimRef`), so a rejected claim never poisons the auto-reclaim; a rejected claim also drops any stored token for the room, and the server answers a rejection with the error **plus** a fresh `room-joined` so the picker's seat list can't get stuck showing a taken seat as open. `opponents: readonly PlayerId[]` is every other seat *in turn order starting right after your own, wrapping around* — not raw `turnOrder` array order minus you, which only coincidentally matches "next player after you" when you happen to be seated first — so a seating layout can rely on "next opponent, then the next" regardless of where you actually sit. `createRoom(seed?, players?)`, `claimSeat(seat, displayName?)`, `dispatch(action)`, `passTurn()`/`autoPass()`/`toggleManaSkip()` (server-side standing preferences, mirrored back in `autoPassing`/`skipManaOnly`), `nameOf(id)` (card names, from `view.objects`).
- **`net/protocol.ts`** — mirrors `server/src/protocol.ts` exactly (see there for the message shapes); duplicated by hand since `server` and `client` are independent workspaces. Also carries `ImportedCardReport`, which instead mirrors `server/src/import-deck.ts`'s `CardReportEntry` — the response shape of the plain HTTP `/import-deck` route, not part of the room protocol above.
- **`App.tsx`** — `App` picks a screen off `NetworkGame.status`: `LobbyScreen` (create — with a 2/3/4-player picker — or join by code; also an "Import a decklist" link, unrelated to rooms — see below) → `SeatPickerScreen` (an optional "Your name" field and a single Join button that claims the next open seat, no per-seat button; a blank name defaults to `"Player N"` — N from that seat's position — rather than silently falling back to the seat's own Alice/Bob/... label) → `GameScreen` once a seat's claimed and a view has arrived. `GameScreen` renders the topbar (title, a "History" button toggling a popup around `<EventLog>`, room code, Leave), the seat banner, a dismissible "🎲 X won the highroll and goes first" banner while `view.turn.number === 0`, `<Table>`, and — as siblings, not part of `Table`'s own layout — the floating stack overlay (`<Stack>`, mounted only while `view.zones.stack.length > 0`) and that History popup. `Table` is keyed on `game.revision` in the parent so every in-progress selection resets when the game state moves on. It classifies `actions` into maps (land/cast by card, abilities by source) and a `mode` (`mulligan` → `commander-replacement` → `put-on-bottom` → `discard` → `order-blockers` → `attackers` → `blockers` → `choose-from-zone` → `choose-x` → `choose-sacrifice` → `targeting` → `priority`); click handlers build the matching `Action`. `commander-replacement` shows a "<commander> was put into your <zone> — move it to the command zone instead? [Command zone] [Leave in <zone>]" prompt (903.9a). `choose-x` (an X spell — a number input 0..`xCost.maxX` in the controls bar) and `choose-sacrifice` (a `"creature-you-control"` ability cost — one button per candidate; auto-resolves for a `"self"` cost or a single choice) run *before* target selection and thread `xValue` / `sacrifice` through the `Targeting` state into the dispatched action. A stack object (a spell being countered) isn't clickable on the board, so the `targeting` controls bar shows a "<name> (on the stack)" button per legal stack target. The discard control reads `view.awaiting.fromEffect` to say "Discard N cards" vs "Discard to hand size". `renderPlayerPanel(pid)` (works for opponents *and* your own seat — a commander's card tile it renders via `commandZoneTile` shows a "+N" tax badge once `commanderCastCount > 0`; also passes `wentFirst` for the persistent 🎲 badge) and `renderHandAndControls()` (the ability menu, `controls`, and your hand — including the mulligan/keep decision) are shared between the two layouts: `opponents.length === 1` (a 2-player game) keeps the classic pinned-top/board-rows/pinned-bottom structure; 2-3 opponents render a `.quadrant-grid` instead, with cells in a fixed `[opponents[0], opponents[1], seat, opponents[2]]` order (top-left, top-right, bottom-left-always-you, bottom-right — a 3-player game just leaves the last cell blank) and your hand/controls in a `.hand-strip` below the grid rather than inside your own cell. Either way, the whole page is one fixed-viewport-height flex column (not a scrolling document) — the banners and your hand-strip size to their own natural content and are always fully visible, while only the board area between them (`.table`) scrolls internally if there isn't room for everything (a card tile's height varies with its rules text, so no fixed pixel reservation could work reliably here). Opponent hands don't render on the board at all — `PlayerPanel`'s existing hand-count becomes a click target (`onOpenHand`, skipped for your own seat) opening the same `ZoneViewer` popup graveyard/exile browsing uses. Declaring an attacker against 2+ legal opponents supports a redirect: selecting a creature defaults it to the first legal opponent and focuses it (shown with a "?" marker); clicking a different opponent's panel while focused reassigns it — mirrors the blockers UI's own focus-then-click flow. Targeting: click highlighted `targetOptions[slot]` (a `CardTile` or a `PlayerPanel`); multi-slot picks accumulate then dispatch. **`setState` updaters must stay pure** — dispatch happens after `setTargeting`, not inside its updater (React double-invokes updaters in dev). Attackers/blockers/discard/order-blockers/mulligan/choose-from-zone: select-then-confirm (order-blockers = click the blockers in damage order, or "keep default"). `ImportDeckScreen` (reached from the lobby, not gated behind `NetworkGame` at all) POSTs pasted decklist text directly to the server's `/import-deck` HTTP endpoint with a plain `fetch` — bypasses `useNetworkGame`/the WS protocol entirely, since it has nothing to do with a room — and renders each card's implemented/not-yet/not-found badge plus (for anything not implemented) its Oracle text via `Symbols`.
- **`ui/`** — `CardTile` renders a full card face: title bar (name + mana cost pips, plus a `+N` tax marker via the optional `extraGenericCost` prop), Scryfall `art_crop` image (colour-tinted fallback on load error), a type line, a text box (keywords in bold + rules text, minus text that only restates the keywords), and a P/T box in the bottom-right corner like a real card. `ui/Symbols.tsx` + `ui/symbols.ts` turn `{…}` tokens (in costs and rules text) into small pips (`{T}` → ↻, colours, generic) — also reused (outside any game) by `ImportDeckScreen` to render a looked-up card's mana cost/Oracle text. Props: `highlight` = must-pick, `selected`, `activatable` = dashed marker, `badge` = ⚔/🛡/Commander/etc., `order` = damage-order ordinal, `stackCount` = land-stack size badge (`×N`, only shown when > 1), `compact` = shrink via CSS `zoom` (an attached Aura/Equipment nested under its host, or a non-top stack entry). Tiles are 138×190 (min-height — taller for a long rules-text card); tapped ones rotate 90° + scale to stay in their slot. `ZoneViewer` takes `ids` + a `resolve(id)` lookup (not a pre-resolved card list) so an id `resolve` can't find renders as a face-down placeholder instead of being silently dropped — needed for an opponent's hand, only partially knowable. Also `PhaseTrack`, `TurnBanner`, `PlayerPanel` (life/mana/zone counts; `targetable` for player targets; `wentFirst` for the highroll 🎲 badge; all three take an optional `seats` prop to resolve a player's chosen display name), `Stack` (the floating overlay described above), `EventLog` (compact `#seq — text` rows, auto-scroll, rendered inside the History popup).
- **`game/board.ts`** — pure layout logic, no React: `computeBoardEntries(view, pid)` turns one player's battlefield into the `BoardEntry[]` a board renders — permanents bucketed by `bucketOf` (single most-expansive type: an artifact creature buckets as creature), Auras/Equipment pulled out and nested as `attachments` on whatever they're `attachedTo`, and otherwise-identical untapped/tapped land stacks collapsed into one entry with `ids.length > 1`.
- **`format.ts`** — `describeEvent(event, nameOf)` / `describeTarget`, the TS sibling of `scripts/format.mjs`, for the event log. `playerLabel(id, seats?)` prefers a player's chosen `displayName` (looked up in the room's `SeatStatus[]`) and falls back to the seat id capitalized ("alice" → "Alice") when none is set or `seats` isn't passed. `seatClassOf` assigns one of four stable per-seat colors (`seat-a`..`seat-d`) by position in `turnOrder`, not table position, so a player reads as the same color on every device.
- A rejected `dispatch` (e.g. a lone blocker on a menace attacker) surfaces as `NetworkGame.error` → a dismissable red banner; the blockers UI also disables its confirm button while a menace attacker has exactly one blocker.
- Styling is one `App.css` — legible dark table, no UI library. Card art is the only network dependency (Scryfall, hotlink-friendly, browser-cached). Out of scope: animation, undo.

## Git workflow

- **Standing authorization to commit and push**: once a feature is working (build/lint/typecheck/tests clean, and — for anything UI-visible — checked live in the browser), commit it and push to `origin/main` without asking first each time. Split unrelated work into separate, logically-scoped commits the way the existing history does (see `git log`), rather than one giant commit. ## Toolchain notes

- **Module systems differ**: `engine`/`server` are ESM + NodeNext, so their own relative imports need explicit `.js` extensions (e.g. `import { x } from "./foo.js"` even though the file is `foo.ts`). `client` is ESM + bundler mode.
- **Engine/server TS config is `erasableSyntaxOnly`** (same as the client): **no `enum`, no `namespace`, no constructor parameter properties**. Use string-literal unions + `as const satisfies` tables instead. Also `verbatimModuleSyntax` → split `import type { … }` from value imports. `strict` + `noUnusedLocals`/`noUnusedParameters`.
- **Client TS config** (`client/tsconfig.app.json`) is strict bundler-mode: `verbatimModuleSyntax`, `erasableSyntaxOnly`, `noUnusedLocals`/`noUnusedParameters`, `allowImportingTsExtensions` (so relative imports include the `.tsx`/`.ts` extension, e.g. `import App from './App.tsx'`). `noEmit` — Vite does the transform.
- **Engine/server tsconfig excludes `src/**/*.test.ts`** from the build (tests are not emitted to `dist/`); vitest type-checks tests itself.
- **Shared dev deps are hoisted to the root** `package.json` (`typescript`, `@types/node`). Don't re-add them to a workspace unless a version needs to diverge.
- **Lint** is oxlint, not ESLint. Config in `client/.oxlintrc.json` (`react`, `typescript`, `oxc` plugins; `react/rules-of-hooks` errors).
- Assets in `client/public/` are referenced by absolute path (e.g. `/favicon.svg`); assets imported from `src/` go through Vite (the app currently imports none — `src/assets/` was removed with the starter template).
- **The server drives the engine synchronously.** `Game.dispatch()` itself fully resolves (the stack, no-priority turn-based actions) before returning; `Room.dispatch()` calls it and then its own `settle()` on top. There is no async and no controller callback in the human path. Every player decision is a `dispatch`ed action a room forwards and a client renders. The last synchronous controller callback, `chooseTargets` (for a triggered ability's targets), falls through to `AutomaticController` (first legal target); nothing in `server`/`client` ever hits it, since real seats are never driven by a `PlayerController` at all — only test/fuzz code (`ScriptedController`/`RandomController`) is.
- **Windows CRLF/LF drift**: editing an existing pure-LF source file on Windows can leave it with *mixed* line endings (untouched lines stay LF, lines the tool rewrites come out CRLF) — a real, observed issue on this machine, distinct from a file that's already consistently CRLF throughout (harmless). Before committing, if `git diff --stat` on an edited file looks disproportionate to the actual edits, check directly (`git cat-file -p HEAD:<path> | grep -c $'\r'` vs total line count) rather than trusting the diff size. Fix with `sed -i 's/\r$//' <path>`, rebuild/retest, then fold the fix into the same commit via `git commit --amend` if nothing's been pushed yet.
