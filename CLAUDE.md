# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

MTG-Engine is a Magic: The Gathering rules engine (`engine/`) with an authoritative multiplayer
room server (`server/`) and a React web client (`client/`) — a real networked 2-4 player game
(Commander-capable), not a local hot-seat demo. The repo is an **npm workspaces monorepo**
(`workspaces: ["engine", "server", "client"]` in the root `package.json`, in that order so
`engine` builds first, then `server`).

**`ROADMAP.md` is the plan of record and the history.** It carried an 11-phase plan for growing
the engine to a "baseline cardpool" (enough coverage for ordinary Commander decks). **All 11
phases are done**, plus a "needed-cards" P0–P8 long tail of card-driven engine passes. Don't
duplicate that history here — this file documents *current* shape only. Read ROADMAP's
*Architecture constraints* section before touching the engine, and read ROADMAP's *Where next*
for candidate future work (currently: a bulk card-authoring pass against a real Commander precon
— the pool is only ~170 cards). `git log` and `engine/src/cards/AUTHORING.md` are the other two
places to look for "why does this exist" — this file should stay a map of current architecture,
not a changelog.

- `engine/` — a TypeScript library package, ESM (`"type": "module"`), NodeNext resolution. Emits to `dist/` with declarations; `package.json` `exports`/`main`/`types` point there. No I/O, no UI — a pure state machine driven entirely through `dispatch`.
- `server/` — a Node + `ws` package: the authoritative multiplayer room host. Owns the one real `Game` instance per room, keyed by a room code; every connected device gets its own redacted `viewFor(seat)` pushed after each dispatch. Imports `engine` the same way `client` does.
- `client/` — a Vite + React 19 + TypeScript app: a **networked** client — each device is one seat, connected over WebSocket to a `server` room, never running a local `Game` or a controller loop itself. Imports `engine` (`"engine": "*"`, the workspace symlink) and consumes only its public seam — `Game`, `viewFor`, `legalActions`, `dispatch`, the `Action`/`LegalAction` types — indirectly, via the wire protocol `server` speaks. Needs `engine/dist/` built (`npm run build` does engine, then server, then client).

## Engine architecture (`engine/src/`)

### What's implemented

Full turn/step loop, casting + targeting + fizzle, a LIFO stack, SBAs, full combat (first
strike/double strike/trample/deathtouch/lifelink/menace, multi-blocker damage assignment as a
player choice, a first-strike priority window, must-be-blocked), activated/triggered abilities
(intervening-ifs, `{X}` costs, loyalty abilities), the full continuous-effects layer pipeline
(1 copy, 2 control, 3 text, 4 type-change, 5 colour, 6 keywords/ability-loss, 7 P/T incl. a CDA
layer), tokens (with a `stackCount` compaction scheme so a self-replicating generator can't blow
up object count — see "Token stacking" below), Auras & Equipment, Commander (command-zone casting
with tax, 903.9a replacement as an owner's choice, commander damage, Partner, the legend rule),
an opt-in simultaneous-mulligan phase, 2-4 player tables (APNAP ordering, per-defender blocker
declarations), a full replacement-effects pipeline (`replacements.ts`), modal/"you may"/targeted-
modal spells, mass effects (wraths, edicts) and tutors/scry/surveil, a rich effect vocabulary
(bounce/exile/mill/discard, fight, counter, control-change, clone, animate, text-change,
count-scaled and trigger-supplied amounts, token-for-target and token-copy effects, conditional
effects, sacrifice costs incl. filtered ones, additional costs & kicker), planeswalkers, alternate
casting zones (flashback, suspend, foretell, escape, disturb, adventure, MDFCs, transforming DFCs
+ Day/Night), extra turns/combats, cascade/storm/spell-copying, Sagas, the Monarch/Energy/Emblems,
damage-prevention shields, and a color-identity-aware Commander deck validator (`identity.ts`,
`server/src/deck-validation.ts`).

**Every player decision is a dispatched action**, never a synchronous controller callback —
`declare-attackers` / `declare-blockers` / `order-blockers` / `assign-combat-damage` / `discard` /
`choose-from-zone` / `mulligan` / `put-on-bottom` / `commander-replacement` /
`pay-life-for-untapped` / `choose-copy` / `choose-text` / `choose-modes` / `choose-targets` /
`sacrifice` / `scry` alongside the priority actions. `legalActions(player)` enumerates what's
playable right now with per-slot target options; `viewFor(player)` produces a redacted,
self-contained snapshot for one seat.

**Not modeled** (see ROADMAP for the full deferred list): Battles, phasing, dungeons/Initiative/
Ring, banding, Backgrounds/Companion, multi-replacement ordering (`choose-replacement-order`),
damage redirection to a third object, dependency ordering between static effects, a player choice
on which same-named legendary permanent the legend rule keeps (deterministic — oldest survives),
full text-change beyond a single creature-type word, snow *sources* (snow mana is generic today).

**Token stacking** (an engine resource-safety mechanism, not a rule — added after the fuzzer hung
on a self-replicating-token card): `GameObject.stackCount` lets one object stand in for many
fully interchangeable, still-pristine token copies instead of minting one object per copy.
`Game.mintTokenBatch` folds new batches into a matching existing stack; a fresh batch only
originates a stack past `STACK_ORIGIN_THRESHOLD` (8), so ordinary "create two tokens" cards are
untouched. Only tokens with no activated ability and only count-scalable, non-targeted triggered
abilities are ever stacked (`Game.isStackableTokenName`). `Game.splitOneFromStack` peels one off
into an ordinary object the instant anything singles it out (targeted effects, a chosen
sacrifice); `Game.materializeStack` expands a whole stack into real objects for combat (capped at
`MAX_MATERIALIZED` = 100 — attacking/blocking are optional, so declaring a legal subset is
allowed); `recompactTokens` (end of cleanup) folds untouched tokens back into stacks. See
`token-stacking.test.ts` and `random-demo.mjs` for the original repro.

### File map

- **`state.ts`** — `GameState` is one plain, `structuredClone`-able tree (no class instances, `Map`/`Set`, or functions inside it). Holds `rules` (`startingLife`, `openingHandSize`, `maxHandSize`, `maxLandsPerTurn`, `skipFirstDraw`), players, `objects` (card/ability instances — `GameObject.kind` `"card"`|`"ability"`, `abilityKind` `"activated"`|`"triggered"`|`"chapter"`, `counters`, `modifiers`, combat fields — all cleared by `moveObject` on any zone change), `zones` (`perPlayer` library/hand/graveyard + `shared` battlefield/stack/exile/command as ordered `ObjectId[]`; stack top = last), `turn`, `priority`, `result`, `awaiting` (a discriminated `AwaitingDecision` union — one variant per decision kind listed above, each carrying whatever context that decision needs, e.g. `assign-combat-damage {attacker, blockers, power, lethal, trample}`, `mulligan {player, hands}` where every player still deciding may act at once, `commander-replacement {commander, intendedZone}` raised *before* the move), plus a grab-bag of pending-decision queues (`pendingBlockerOrders`, `pendingBlockerDeclarations`, `pendingTriggers`, `pendingTargetedTrigger`, `pendingTargetedCast`, `pendingSuspendedCasts`, `deferredCommanderMove`, `pendingDestruction`, `pendingSacrifices`/`pendingSacrificeVictims`) that let a mass effect or multi-step decision resume correctly after a player answers something mid-resolution, turn-scoped state (`preventAllCombatDamage`, `preventionShields`, `combatDamage`, `extraTurns`, `extraCombats`, `spellsCastThisTurn`, `dayNight`, `monarch`, `emblems`), and `eventLog`. `PlayerState` carries `energy`, `commanderCastCounts` (per-commander tax, Partner-aware), `commanderDamageTaken`, `spellsCastThisTurn`. `GameObject` carries the full set of per-permanent flags the layer/effect system needs: `markedByDeathtouch`, `summoningSick`, `loyaltyActivatedThisTurn`, `attacking` (`PlayerId | ObjectId`), `isToken`, `attachedTo`, `isCommander`, `controlEndsAtCleanup`, `copyOf`, `faces`/`face` (multi-face cards — `faceName(object) = faces[face]`, `printedCardName(object) = copyOf ?? faceName(object)` is what every characteristic/ability read goes through), `modifiers` (a `PtModifier[]` spanning layers 3–7d), `xValue`, `chosenModes`, `kicked`, `castVia` + the alt-zone markers (`grantedFlashback`, `suspended`+`counters.time`, `hastyUntilItLeaves`, `foretold`+`foretoldOnTurn`), `isCopy`, `stormCount`, `onAdventure` — all cleared by `moveObject` on any zone change unless noted otherwise. Also exports pure selectors.
- **`game.ts`** — `Game` owns the single mutable `GameState` and is the **only** writer. `dispatch(action)` handles every `Action` variant (see `actions.ts`). Multi-blocked attackers queue in `pendingBlockerOrders`; a 3-4 player table queues attacked defenders in `pendingBlockerDeclarations`, drained one `declare-blockers`/`order-blockers` at a time. `legalDefenders(attacker)` returns every non-eliminated opponent plus their planeswalkers. `advance()`/`advanceUntil(pred)` run `tick()`. `emit()` appends an event and runs `detectTriggers` (matches against every battlefield permanent's `triggered` list, honouring intervening-ifs via `interveningIfMet`). `prepareForPriority(player)` is the pre-priority fixpoint loop: run SBAs, drain pending mass-effect/sacrifice queues, place pending triggers (APNAP order) — repeat until stable, then hand off priority (to `awaiting.player` if a decision got raised mid-loop). Mana is **auto-paid**: `manaSources` reports each permanent's `{T}: Add` abilities as `ManaOption` alternatives → `Game.payMana` = `resolveHybridCost` (hybrid/twobrid/Phyrexian → concrete cost + life) → `planManaPayment` (a greedy solver) → `executePayment` (taps/sacrifices sources, spends the pool, pays life); `castingCostOf` folds in commander tax and `costModification` statics. Ability objects are minted onto the stack by `mintAbilityObject` and deleted from `state.objects` on resolution. All P/T reads go through `characteristicsOf`. Combat damage runs through `combatDamageStep` → `runCombatDamageSubPass` (first-strike sub-pass, then regular, each followed by SBAs + a priority window when relevant) → `dealCombatDamage`, which takes a player-chosen `assign-combat-damage` split when one exists, else auto-assigns lethal down `blockedBy`; `dealDamage` runs deathtouch/lifelink, prevention shields, and Fog uniformly (for combat and burn alike) and returns the amount actually dealt. `createTokens`/`addCounter`/`entersBattlefieldReplacement` all honour replacement multipliers (Doubling Season). `moveObject` is the single zone-transition function: it applies enters-battlefield replacements, defers a commander's leave-the-battlefield move behind a `commander-replacement` decision (903.9a), redirects a graveyard-bound card to exile when a replacement or `castVia` says to, resets face/copy/modifier state on any move to a hidden zone, and emits `permanent-left-battlefield`/`permanent-destroyed` as appropriate. `runStateBasedActions` recomputes control (layer 2), sweeps fallen-off Auras, deletes dead tokens, enforces the legend rule and commander-damage loss, and sacrifices 0-loyalty planeswalkers / completed Sagas. `castSpell`/`activateAbility`/`whyCannot*` thread through `via` (alt cast zone), `face` (multi-face cards), `xValue`, `kicked`, `sacrifice` (additional/ability costs), and evaluate `costModification`/`ward`/protection/`StaticAbility.condition` gates. `castCardWithoutPaying` is the shared free-cast core for suspend/cascade. A triggered ability or suspended spell needing a real target choice parks in `pendingTargetedTrigger`/`pendingTargetedCast` and raises a `choose-targets` decision rather than picking synchronously.
- **`actions.ts`** — the `Action` union: the priority actions, plus `declare-attackers`/`declare-blockers`/`order-blockers`/`assign-combat-damage`/`discard`/`choose-from-zone`/`mulligan`/`put-on-bottom`/`commander-replacement`/`choose-copy`/`choose-text`/`choose-modes`/`choose-targets`/`sacrifice`/`scry`/`suspend`/`foretell`/`cycle`. `cast-spell` carries optional `xValue`, `via?: CastVia` (`"flashback"|"escape"|"foretell"|"disturb"|"adventure"|"suspend"|"cascade"`), `face?`, `modes?`, `kicked?`, `sacrifice?` (an additional cost); `activate-ability` carries optional `sacrifice`, `xValue`. `LegalAction` mirrors this — a castable/activatable option carries whatever context the client needs to build the action (`xCost: {maxX}`, `sacrifice: {choices}`, `castModal {...}`, `mustBlock`, etc.), and a card playable multiple ways (kicked/unkicked, multiple faces, via different alt-zones) is enumerated once per variant. Kept out of `game.ts` to avoid a cycle with `controller.ts`.
- **`view.ts`** — `viewFor(state, registry, viewer, opts)` / `game.viewFor(player)` → a `PlayerView`: your hand in full, other hands as counts, libraries as counts (except what a pending `choose-from-zone`/`scry` reveals to that player), battlefield/stack/graveyards public with **computed** characteristics baked in (power/toughness/keywords/types/subtypes/colors/restrictions/loyalty/`isToken`/`attachedTo`/`isCommander`/`xValue`/`copyOf`/`suspended`/`foretold`/`faceName`+`faces`/`stackCount`/`art`), so a client needs neither the registry nor the layer system. A foretold card in exile is redacted for everyone but its owner. `PlayerView` also carries `startingPlayer`, `dayNight`, `monarch`, `emblems`; `PublicPlayerInfo` carries `energy`, `commanderDamageTaken`, `commanderCastCounts`. `{ revealAll: true }` for a spectator/debug view.
- **`turn.ts`** — `Phase`/`Step` string-literal unions (no `enum`), `TURN_SEQUENCE`, `nextStep`, `stepUsesPriority` (false only for untap/cleanup), `isMainPhase`.
- **`events.ts`** — a discriminated `GameEvent` union (the audit log) covering every state change the engine makes — zone moves, damage, triggers, decisions, alt-cast events, combat, replacements, etc. Both log formatters (`scripts/format.mjs`, `client/src/format.ts`) render them; check there when you need the exact shape of a specific event.
- **`cards.ts`** — a thin re-export barrel; the real content lives in `cards/`: `cards/define.ts` (`CardDefinition`/`CardDraft` + `defineCard`/`hasKeyword`), `cards/helpers.ts` (`basicLand`, `manaTapAbility`, `addManaAbility`, land-toolkit builders — `entersTappedStatic`, `checkLandStatic`, `painLand`, `fetchLand`, `trikeland`, `shockLand` — `landProduces`), `cards/registry.ts` (`CardRegistry`, `createDefaultRegistry`), one file per card under `cards/pool/` (real cards + basics) and `cards/tokens/`. `CardDefinition` is **declarative** (`effect`, `keywords`, `activated`, `triggered`, `static: StaticAbility[]`, `supertypes`, `loyalty`, `chapters` for a Saga, `faces` for a multi-face card, `transform`/`disturb`/`adventure`/`suspend`/`foretell`/`flashback`/`escape`/`cycling`/`castModal`/`kicker`/`additionalCost`/`cantBeCountered`/`art`) with an imperative `resolve(ctx)` hatch. `cards/generated.ts` is the codegen'd barrel (`npm run gen:cards -w engine`, also a `prebuild`/`pretypecheck` step, checked in) — **to add a card, drop a new file in `cards/pool/` and run `gen:cards`**. `cards/pool.test.ts` fails if a card isn't wired into `generated.ts`. **`cards/AUTHORING.md` is the hand-authoring guide** — every field, the effect/target/ability/static vocab, worked examples, current limitations; read it before authoring a new card. `engine/src/sandbox.ts` — `createSandbox(cardName)` builds a solo `Game` with the card in hand/battlefield, lands, and target fodder for the card lab; `Game.debugSpawn(name, player, zone)` is the sanctioned white-box "put a card straight into a zone" helper, going through the real `moveObject`.
- **`identity.ts`** — `colorIdentityOf(def)` (rule 903.4 — a lexical `{…}`-symbol scan of the mana cost + all rules/ability text) + `withinIdentity`/`identityString`. Consumed by `server/src/deck-validation.ts`.
- **`filter.ts`** — `CardFilter` + `matchesFilter(state, registry, id, filter, { you })`: a pure predicate over an object + its *computed* characteristics (`type`/`types`/`notTypes`/`subtype`/`subtypes`/`supertype`/`name`/`colors`/`notColors`/`colorless`/`manaValue`/`power`/`toughness`/`controlledBy`/`ownedBy`/`keyword`/`tapped`/`token`, ANDed). Off the battlefield it degrades to printed values. The shared "which objects" vocabulary for mass effects, tutors, and filtered triggers — `ZoneChoiceFilter` is an alias. Answers type/subtype/colour clauses lazily via the self-contained `effectiveTypes`/`effectiveSubtypes`/`effectiveColors`; only a `power`/`toughness`/`keyword` clause needs the full characteristics fold (kept cheap deliberately — a `StaticAbility.condition` re-runs `matchesFilter` over the whole battlefield on every read).
- **`replacements.ts`** — `ReplacementSpec` (rule 614/616), a discriminated union on `StaticAbility.replacement`: `enters-battlefield { tapped?, tappedUnless?, counters?, transformed? }`, `would-create-token { multiplier }`, `would-add-counter { multiplier, counterKind? }`, `would-be-put-into-graveyard { instead: "exile", filter? }`, `would-draw { who: "opponent", instead: "you-draw" }`. Not modeled: multi-replacement ordering, damage redirection to a third object.
- **`abilities.ts`** — `ActivatedAbility` (`cost: {mana, tap, sacrifice?, payLife?, removeCounter?, payEnergy?}`, `sacrifice: "self" | "creature-you-control" | {filter: CardFilter}`, optional `sorcerySpeed`, optional `loyaltyCost`; `mana` may contain `{X}`). `TriggeredAbility` (`trigger: TriggerSpec` — `enters-battlefield`/`dies` (with `filter?`/`otherOnly?`), `leaves-battlefield`, `gains-life`, `loses-life {who}`, `attacks`, `sacrifice {who}`, `deals-combat-damage-to-player`, `step-begins {step}`, `cast-spell {who, noncreatureOnly?, firstEachTurn?}`, `this-cast`, `transforms {who, intoFront?, filter?}`, a `predicate` escape hatch; optional `condition?: StaticCondition` — an intervening-if, rule 603.4). `StaticAbility` also carries `restrictions: CombatRestriction[]`, `ward {mana?, payLife?}`, `costModification {applies, reduceGeneric?, increaseGeneric?}`, `protection {colors?, types?}`, `grantsActivated: ActivatedAbility[]`, `condition?: StaticCondition` (`controls {filter, atLeast}` / `opponent-controls {filter, atLeast}` / `your-turn` / `threshold` / `metalcraft`). `isManaAbility` permits a `sacrifice: "self"` or `payLife` cost, excludes `removeCounter`/loyalty/a non-self sacrifice.
- **`effects.ts`** — the `EffectSpec` vocabulary: `sequence`, `damage`/`draw`/`modify-pt`/`modify-pt-all`/`create-token`/`create-token-copy` `count` fields accept an `EffectAmount = number | "x" | {countOf: CardFilter} | {triggerValue: true}`; `add-mana` (`+ painToController?`), `gain-life`/`lose-life`, `tap`/`untap`/`untap-all`, `destroy`/`destroy-all`, `damage-all`, `fight {a, b, oneSided?}`, `counter {target}`, `gain-control {target, untilEndOfTurn}`, `return-to-hand`/`exile`/`exile-graveyard`/`mill`/`return-from-graveyard`/`discard`, `grant-keyword`/`grant-keyword-all`, `add-counter`/`proliferate`, `animate {target, power, toughness, addTypes, addSubtypes, setSubtypes?, setColors?, loseAbilities?, keywords?, duration}`, `change-text`, `grant-flashback`, `take-extra-turn`/`additional-combat`, `storm`/`cascade`/`copy-spell`, `create-token {token, count, who?: "you"|"target-controller"}`, `create-token-copy {of: "source"|"trigger-object"|slot, count, gainsHaste?, exileAtEndStep?, notLegendary?, basePt?}`, `conditional {condition, then, else?}`, `attach`, `transform`/`day-night`, `become-monarch`/`get-energy`/`create-emblem`, `prevent-all-combat-damage`/`prevent-damage`, `modal {minModes, maxModes, modes}`/`may {effect, prompt}` (non-targeted only — a targeted modal spell uses `CardDefinition.castModal` instead), `sacrifice {who, filter, count, exceptSource?}`, `sacrifice-source {then?}`, `search-library`, `scry`/`surveil`, `look-and-choose`. `EffectApi`/`ResolutionContext` (`ctx.x`, `amountValue`), `applyEffectSpec`.
- **`characteristics.ts`** — `computeCharacteristics(state, registry, id)` folds printed → layer 3 (text substitution) → layer 4 (type/subtype changes) → layer 5 (colour) → layer 6 (keyword grants/ability loss) → layer 7b (a `setBasePtFromCount` CDA, then `animate`'s `setPt`) → layer 7c (counters) → layer 7d (P/T grants/modifiers), timestamp-ordered. `Characteristics.restrictions`/`.protectionFrom` collect `StaticAbility.restrictions`/`.protection`. `staticAffects` resolves an `AffectSpec` scope (`"self"`/`"creatures-you-control"`/`"lands-you-control"`/`"attached"`, lord `subtype` clauses). Layer 1 (copy) is handled upstream via `printedCardName`. `staticConditionMet(state, registry, source, condition, opts?)` evaluates a `StaticAbility.condition` gate, checked *after* `staticAffects` confirms reachability, with a re-entrancy guard for mutually-conditional permanents. Dependency ordering between static effects is not implemented.
- **`target.ts`/`targeting.ts`** — `TargetRef` (player or object) and `TargetSpec` (`"any-target"`/`"creature"`/`"nonblack-creature"`/`"creature-you-control"`/`"creature-an-opponent-controls"`/`"player"`/`"opponent"`/`"creature-or-player"`/`"permanent"`/`"nonland-permanent"`/`"land"`/`"artifact-or-enchantment"`/`"creature-or-enchantment"`/`"spell"`/`"creature-spell"`/`"noncreature-spell"`/`"instant-or-sorcery-in-your-graveyard"`/`"instant-or-sorcery-spell"`). `isLegalTarget`/`legalTargets` take a `forPlayer` and an optional `TargetSource` (`{colors, types}`), and enforce protection (`protectionBlocks`, also used by `dealDamage`/`whyCannotBlock`/`attachPermanent`). Checked on cast and again at resolution (all-illegal ⇒ fizzle).
- **`mana.ts`** — `Color`/`ManaType`/`ManaPool`, `parseManaCost` (generic, `{X}`, `{C}` colorless, hybrid `{W/U}`, twobrid `{2/W}`, Phyrexian `{W/P}`, snow `{S}` folded into generic), `manaValue`, `poolTotal`.
- **`controller.ts`** — `PlayerController.act(view)` is the single entry point: when `view.state.awaiting` is set it must return that declaration, otherwise any legal priority action. `AutomaticController` always passes/keeps its hand. `ScriptedController` plays a queue plus assignable `*Fn` callbacks (what tests use). `RandomController` picks uniformly from `legalActions()` — the engine's fuzzer (see `random-demo.mjs`).
- **`primitives.ts`** — branded `PlayerId`/`ObjectId`, seeded `Rng` (mulberry32), `shuffle`.
- **`auto-settle.ts`** — `isSettled(state)` / `autoSettle(game)`: cascades past every "dead" priority window in one go. Used once by `RoomManager.create` to settle a fresh room to its first real decision; `Room`'s own per-dispatch `settle()` deliberately does *not* use it mid-game (per-seat auto-pass/skip-mana-only are one-shot-per-call).

Snapshot/restore: `game.snapshot()` → `structuredClone(state)`; `Game.fromSnapshot(snap, env)` rebuilds (re-supply `registry`/`controllers` via `env`). Determinism: same seed + same controllers ⇒ identical replay.

## Server architecture (`server/src/`)

The authoritative multiplayer host. One process can run many rooms; each room owns exactly one
real `Game` and pushes every connected seat its own `viewFor` after each settle. Transport-agnostic
at the `Room` level (a `Connection` is just "something we can push a `ServerMessage` to"), so it's
unit-testable without a real WebSocket — `ws-server.ts` is the only place that touches `ws` itself.

- **`room.ts`** — `Room` wraps one `Game` plus a `Seat` per `turnOrder` entry (`clientToken`, `connection`, `autoPassUntil`, `skipManaOnly`, `displayName`). `claimSeat(player, clientToken, connection, displayName?)` binds a connection to a seat — a token mismatch is rejected even while offline, the same token reclaims it. `dispatch(connection, action)` forwards to `Game.dispatch` then calls `settle()`, which auto-passes dead priority windows / mana-only windows / whole turns per-seat, one stopping point at a time (built on `isSettled`, deliberately not `autoSettle` — see `auto-settle.ts`). `seatStatuses()` → `SeatStatus[]` for the wire.
- **`room-manager.ts`** — `RoomManager.create(config: GameConfig)` mints a room code, builds a `Game.create(config)`, and calls `autoSettle(game)` once. `get(id)` looks a room up. No player-count assumption.
- **`ws-server.ts`** — `attachRoomServer(wss, manager)` wires a `WebSocketServer` to a `RoomManager`: parses messages as `ClientMessage`s, dispatches to the matching `Room`/`RoomManager` call, pushes `ServerMessage`s back. `create-room` clamps `players` (2-4, default 2) and rolls a random `startingPlayer` (the "highroll"), independent of the shuffle `seed`.
- **`protocol.ts`** — the wire protocol, duplicated (not imported) in `client/src/net/protocol.ts` — keep the two in sync by hand. `ClientMessage`: `create-room {seed?, players?}`, `join-room`, `claim-seat {seat, clientToken, displayName?}`, `dispatch {action}`, `pass-turn`, `auto-pass`, `toggle-mana-skip`. `ServerMessage`: `room-created`, `room-joined {seats}`, `state {seat, view, actions, seats, autoPassing, skipManaOnly}`, `error`. Doesn't cover `/import-deck` (a plain HTTP route, not a WS message).
- **`decks.ts`** — `SEATS: SeatDeck[]`, up to four named seats (`ALICE`/`BOB`/`CAROL`/`DAVE`) in seating order, sliced by `create-room`'s `players` count. Each is a ~60-card **deliberately-illegal "good stuff" pile** showing off a broad slice of the pool. Not run through `validateCommanderDeck`.
- **`deck-validation.ts`** — `validateCommanderDeck({commanders, cards, size}, registry)` → `{legal, violations, identity}`: singleton (basics exempt), colour identity, deck size, legendary commander(s), Partner-for-two-commanders. Only checks *implemented* cards.
- **`import-deck.ts`** — a decklist feasibility audit, unrelated to any room: `parseDecklistText(text)` parses a pasted Moxfield-style export; `evaluateDecklist(entries, registry)` cross-references each name against the local `CardRegistry` (implemented cards reported from their `CardDefinition`) and falls back to Scryfall for anything else (throttled, 429-aware retry). Wired up as `POST /import-deck` in `index.ts`. Live-fetching a Moxfield URL server-side was tried and abandoned (403s) — pasted export text only.

`server/scripts/smoke.mjs` (`npm run smoke -w server`) is the server's own eyeball check.

## Client architecture (`client/src/`)

A **networked** client: each device is one seat, connected over WebSocket to a `server` room. It
never owns a `Game` or runs a controller loop itself. 2-player rooms render a classic vertical
layout; 3-4 player rooms render a 2x2 quadrant grid, with you always bottom-left.

- **`net/useNetworkGame.ts`** — owns the WebSocket connection and the current seat's `PlayerView`/`actions`/`seats`. Reconnects with exponential backoff; a previously-claimed seat (`clientToken` in `sessionStorage`, per-tab) is reclaimed automatically. `opponents: readonly PlayerId[]` is every other seat in turn order starting right after your own, wrapping around. `createRoom(seed?, players?)`, `claimSeat(seat, displayName?)`, `dispatch(action)`, `passTurn()`/`autoPass()`/`toggleManaSkip()`, `nameOf(id)`.
- **`net/protocol.ts`** — mirrors `server/src/protocol.ts` by hand. Also `ImportedCardReport`, mirroring `server/src/import-deck.ts`'s response shape.
- **`App.tsx`** — `App` picks a screen off `NetworkGame.status`: `LobbyScreen` → `SeatPickerScreen` → `GameScreen`. `GameScreen` renders the topbar/history popup, seat banner, highroll banner, `<Table>`, plus the floating `<Stack>` overlay as a sibling. `Table` (keyed on `game.revision`) classifies `actions` into a `mode` (mulligan → commander-replacement → pay-life-for-untapped → choose-copy → choose-text → choose-modes → sacrifice → scry → assign-combat-damage → put-on-bottom → discard → order-blockers → attackers → blockers → choose-from-zone → choose-x → choose-sacrifice → targeting → priority) and builds the matching `Action` from click handlers. Each decision kind gets its own small UI (e.g. `commander-replacement` shows a move-to-command-zone prompt; `choose-modes` shows Yes/No, one-button-per-mode, or toggle+Confirm depending on shape; `choose-x`/`choose-sacrifice` run before targeting and thread through it). `renderPlayerPanel`/`renderHandAndControls` are shared between the 2-player and quadrant-grid layouts. **`setState` updaters must stay pure** — dispatch happens after `setTargeting`, not inside its updater. `ImportDeckScreen` POSTs pasted decklist text directly to `/import-deck`, bypassing the WS protocol entirely.
- **`ui/`** — `CardTile` (full card face: title/cost, Scryfall art via `ui/art.ts`, type line, text box, P/T or loyalty badge; props for `highlight`/`selected`/`activatable`/`badge`/`order`/`stackCount`/`compact`). `ui/Symbols.tsx`+`symbols.ts`+`mana.ts` render `{…}` mana tokens as pips (art sliced from a spritesheet, CSS fallback for exotic symbols). `ZoneViewer` (takes `ids` + a `resolve(id)` lookup so an unresolvable id renders face-down; optional `castable` prop for graveyard flashback/play-from-graveyard buttons). `PhaseTrack`, `TurnBanner`, `PlayerPanel`, `Stack`, `EventLog`.
- **`lab/`** — the **card lab** (`npm run lab -w client` → port 5174, no room server needed): a searchable gallery of `BUILTIN_CARDS` + a detail pane (`Tile`, `Structure` = feature chips + pretty-printed def, `Sandbox` = a local solo game via `engine`'s `createSandbox`). `vite.lab.config.ts` aliases `engine` to source so card-file edits hot-reload (a *new* file still needs `gen:cards`).
- **`ui/art.ts`** — `resolveArtUrl(art, name, version?)`: a `CardDefinition.art` link or a by-name Scryfall fallback.
- **`game/board.ts`** — `computeBoardEntries(view, pid)`: pure layout logic turning one player's battlefield into `BoardEntry[]` (bucketed by type, Auras/Equipment nested as `attachments`, matching untapped/tapped land stacks collapsed).
- **`format.ts`** — `describeEvent`/`describeTarget` (event log text), `playerLabel` (prefers a chosen display name, falls back to a capitalized seat id), `seatClassOf` (stable per-seat colour by turn-order position, not table position).
- A rejected `dispatch` surfaces as `NetworkGame.error` → a dismissable red banner.
- Styling is one `App.css` — legible dark table, no UI library. Card art is the only network dependency. Out of scope: animation, undo.

## Commands

Run from the repo root unless noted. Workspace scripts: `npm run <script> -w engine` / `-w server` / `-w client`.

**Whole repo** (root scripts fan out with `--workspaces --if-present`):
- `npm run build` — builds `engine` (tsc), then `server` (tsc), then `client` (`tsc -b && vite build`)
- `npm test` — runs `engine` and `server` vitest, each once (`client` has no tests)
- `npm run lint` — oxlint on `client`
- `npm run typecheck` — `tsc --noEmit` on `engine`, `tsc --noEmit` on `server`, `tsc -b` on `client`

**Engine** (`engine/`):
- `npm run card:lookup -w engine -- "Card Name"` — fetches the card's authoritative mana cost/type line/Oracle text/rulings from the Scryfall API (`engine/scripts/scryfall-lookup.mjs`). Run this before authoring a new card — see `cards/AUTHORING.md` §1.
- `npm run test -w engine` — vitest, single pass (CI mode); `-- path/to/file.test.ts` for one file, `-- -t "name"` for a name match
- `npm run test:watch -w engine` — vitest watch mode
- `npm run build -w engine` / `npm run typecheck -w engine`
- `npm run play -w engine` — builds, then runs `engine/scripts/play.mjs`: a full two-player game with default controllers, prints the event log (`-- --seed 7`, `-- --turns 3`). The engine has no UI, so this and the tests are how you watch it run.
- `npm run play:<demo> -w engine` — small narrated demo scripts for specific mechanics: `cast`, `combat`, `abilities`, `triggers`, `static`, `keywords`, `tokens`, `attachments`. See `engine/scripts/*-demo.mjs`.
- `npm run play:random -w engine` — `engine/scripts/random-demo.mjs`: N random-vs-random games (`-- --games 300`, `-- --log`, `-- --players 3|4`). This is the engine fuzzer — if `legalActions` ever offers something `dispatch` refuses, or an unbounded loop/object-count blowup happens, this crashes or hangs. Decks A/B/C/D exercise most of the card pool; kept lean (~50-60 cards) so RandomController actually draws its threats.
- Each major feature has its own dedicated engine test file rather than a standalone demo script (commander, mulligans, legend rule, multiplayer, bounce, X-spells, sacrifice, hand disruption, fight/keywords, counterspell, flash/prowess, proliferate, combat-damage triggers, control-change, base-P/T CDA, clone, animate, text/color, replacements, modal, filters/scopes, tutors, static restrictions, ability costs, ward, cost modification, protection, and one file per "needed-cards" pass — dual-lands, graveyard-recursion, landfall-payloads, count-scaled, trigger-value, token-for-target, token-copy, sacrifice-cost, intervening-if, additional-costs, token-stacking, mdfc, transform, phase10-misc). Read the relevant one for a runnable example of how a mechanic works.

A git-ignored `scratch.mjs` at the repo root is a scratch pad for ad-hoc exploration (`node scratch.mjs` after building `engine`/`server`) — build a `Game` (often spawning objects directly onto the battlefield), wrap it in a `Room`, serve it over a raw `ws` `WebSocketServer` on port 4000 for a browser (or `claude-in-chrome`) to connect to at the client dev server's URL with `?room=<CODE>`.

**Server** (`server/`):
- `npm run test -w server` / `test:watch` / `build` / `typecheck`
- `npm run start -w server` — runs the built `dist/index.js`: a real room server on `ws://localhost:4000` (or `$PORT`)
- `npm run dev -w server` — `tsc --watch` + `node --watch dist/index.js` together
- `npm run smoke -w server` — an in-process two-client round-trip sanity check

**Client** (`client/`):
- `npm run dev -w client` — Vite dev server with HMR (build `engine`/`server` first); needs a room server reachable at `ws://<host>:4000` (override with `VITE_SERVER_URL`)
- `npm run lab -w client` — the card lab, no room server needed (build `engine` once first for types)
- `npm run build -w client` / `lint -w client` / `preview -w client`
- No client tests yet. To watch it run: start a room server, then `npm run dev -w client` and open two tabs/devices to the same room code.

## Git workflow

- **Standing authorization to commit and push**: once a feature is working (build/lint/typecheck/tests clean, and — for anything UI-visible — checked live in the browser), commit it and push to `origin/main` without asking first each time. Split unrelated work into separate, logically-scoped commits the way the existing history does (see `git log`), rather than one giant commit. This still doesn't cover force-push, history rewrites, or pushing something you haven't actually verified — those still warrant asking.

## Toolchain notes

- **Module systems differ**: `engine`/`server` are ESM + NodeNext, so their own relative imports need explicit `.js` extensions (e.g. `import { x } from "./foo.js"` even though the file is `foo.ts`). `client` is ESM + bundler mode.
- **Engine/server TS config is `erasableSyntaxOnly`** (same as the client): **no `enum`, no `namespace`, no constructor parameter properties**. Use string-literal unions + `as const satisfies` tables instead. Also `verbatimModuleSyntax` → split `import type { … }` from value imports. `strict` + `noUnusedLocals`/`noUnusedParameters`.
- **Client TS config** (`client/tsconfig.app.json`) is strict bundler-mode: `verbatimModuleSyntax`, `erasableSyntaxOnly`, `noUnusedLocals`/`noUnusedParameters`, `allowImportingTsExtensions` (relative imports include the `.tsx`/`.ts` extension). `noEmit` — Vite does the transform.
- **Engine/server tsconfig excludes `src/**/*.test.ts`** from the build; vitest type-checks tests itself.
- **Shared dev deps are hoisted to the root** `package.json` (`typescript`, `@types/node`). Don't re-add them to a workspace unless a version needs to diverge.
- **Lint** is oxlint, not ESLint. Config in `client/.oxlintrc.json` (`react`, `typescript`, `oxc` plugins; `react/rules-of-hooks` errors).
- Assets in `client/public/` are referenced by absolute path (e.g. `/favicon.svg`); assets imported from `src/` go through Vite.
- **Windows CRLF/LF drift**: editing an existing pure-LF source file on Windows can leave it with *mixed* line endings (untouched lines stay LF, lines the tool rewrites come out CRLF) — distinct from a file that's already consistently CRLF (harmless). Before committing, if `git diff --stat` on an edited file looks disproportionate to the actual edits, check directly (`git cat-file -p HEAD:<path> | grep -c $'\r'` vs total line count) rather than trusting the diff size. Fix with `sed -i 's/\r$//' <path>`, rebuild/retest, then fold the fix into the same commit via `git commit --amend` if nothing's been pushed yet.
