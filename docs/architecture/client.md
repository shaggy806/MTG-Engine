# Client architecture reference (`client/src/`)

Reference detail, **not loaded automatically**: read the entry for a file before changing it. The short, always-relevant version is `client/CLAUDE.md`; this is the per-file detail it points into. Keep it current when a file's shape changes, but it is a map of the code as it is, not a changelog.

## The workspace

- `client/` — a Vite + React 19 + TypeScript app: a **networked** client — each device is one seat, connected over WebSocket to a `server` room, never running a local `Game` or a controller loop itself. Imports the engine (`"engine": "*"`, the workspace symlink) as **`engine/client`** — `engine/src/client.ts`, a second package entry with every type but only the values a page uses, none of which reaches a card definition (`test/client-entry.test.ts` walks its imports to keep it so). The main `engine` barrel exports `BUILTIN_CARDS`, which imports every card file, and Vite's dev server doesn't tree-shake, so a page importing the barrel fetched all ~5,500 card modules on every load (16 s warm). No page imports `engine` itself. Consumes the engine's public seam — the `Action`/`LegalAction`/`PlayerView` types, plus pure helpers such as the combat validators — indirectly, via the wire protocol `server` speaks. Needs `engine/dist/` and `protocol/dist/` built (`npm run build` does engine, protocol, server, then client).

## Architecture

A **networked** client: each device is one seat, connected over WebSocket to a `server` room. It
never owns a `Game` or runs a controller loop itself. 2-player rooms render a classic vertical
layout; 3-4 player rooms render a 2x2 quadrant grid, with you always bottom-left.

**Three pages, branched by path in `main.tsx`** before `<App/>` is chosen, so `useNetworkGame`'s
eager WebSocket never opens for the two network-free ones: `/library` → `LibraryPage`,
`/deck-builder` → `DeckBuilderPage`, everything else → `App` (the game itself). The two
network-free pages are `React.lazy` chunks, each fetched **together with the whole card pool**
and rendered once both are in; the game's own download holds no card definitions at all (see
`cards/cardData.ts` below).

- **`cards/cardData.ts`** — the client's only way to card definitions, which the engine ships as
  32 name-hashed shards, each its own file in the build (engine `cards/card-shards.ts`). A
  **lookup by name** — `peekCard` (sync: the definition, `null` for no such card, `undefined`
  while its shard isn't loaded), `loadCard`, `requestCards` and the `useCardData` hook (re-renders
  as each shard arrives) — fetches only the shard that name hashes to. That serves the game page's
  two extras: an event-log name's tooltip (fetched as the pointer reaches it) and a double-faced
  card's other face in `ZoneViewer`. Everything a game needs to be *played* comes in the server's
  views instead. The **whole pool** — `loadCardPool`, then `cardPool()` (`cards`, `tokens`,
  `byName`, and a `CardRegistry` for the engine's deck rules) — is what the library and the deck
  builder read, synchronously, since `main.tsx` has loaded it before they render. A commander's art
  in the lobby needs no definition at all: the engine's generated `PINNED_ART` holds the few
  printings the pool pins, and everything else resolves on Scryfall by name. A shard that fails
  to load (the network, or a deploy replacing the build while a tab is open) reads as not loaded
  and is asked for again next time; the lazy pages show `cards/PoolLoading.tsx`'s loading state
  and, on failure, a reload offer. `engine/client` doesn't export `BUILTIN_CARDS`,
  `POOL_CARDS`, `TOKEN_CARDS` or `createDefaultRegistry`, and must not start to: any of them puts
  the whole pool back into whichever chunk imported it.

- **`net/useNetworkGame.ts`** — owns the WebSocket connection and the current seat's latest `frame` (`{seq, view, actions}` — one server push, whole), with `view`/`actions` derived from it for bookkeeping that has to be current. Reconnects with exponential backoff; a previously-claimed seat (`clientToken` in `sessionStorage`, per-tab) is reclaimed automatically. `ConnectionStatus` is `connecting` → `no-room`/`room-not-found` → `choosing-seat` → `waiting-for-players` (my seat is claimed but the room is still a `PendingRoom` — other seats are open) → `playing`/`disconnected`. `opponents: readonly PlayerId[]` is every other seat in turn order starting right after your own, wrapping around. `createRoom()` (mints and stores this tab's host token), `isHost`/`botSpeed`/`setBotSpeed(speed)`, `claimSeat(seat, displayName?, deck?)`, `addBot(seat)`, `addSeat()`/`removeSeat(seat)`, `dispatch(action)`, `passTurn()`/`autoPass()`/`toggleManaSkip()`, `ackFrame(seq)`, `nameOf(id)`. `everConnected` distinguishes a first visit to a server that isn't up from a connection actually lost mid-game — both land on `disconnected` (a failed initial socket fires `onerror` then `onclose` without ever reaching `no-room`), and only the wording differs.
- **`net/`** — no `protocol.ts` of its own: the wire types come from the `protocol` workspace (`import type { ServerMessage } from "protocol"`), exactly as on the server.
- **`App.tsx`** — `App` picks a screen off `NetworkGame.status`: `LandingScreen` → `SeatPickerScreen` → `GameScreen`. `GameScreen` renders the topbar/history popup, seat banner, highroll banner, `<Table>`, plus the floating `<Stack>` overlay and `<AnimationLayer>` as siblings. **Everything it draws comes from `usePlayback`'s `shown` view, never `game.view`** — the two differ for as long as an animation is running, and mixing them is what put a card's arrival animation over a board that already had the card on it. `Table` (keyed on `shown.revision`, i.e. one remount per frame actually shown) classifies `actions` into a `mode` (mulligan → commander-replacement → pay-life-for-untapped → choose-copy → choose-enchant → legend-rule → choose-text → choose-modes → sacrifice → scry → assign-combat-damage → put-on-bottom → discard → attackers → blockers → choose-from-zone → choose-x → choose-sacrifice → targeting → cast-now → priority — `cast-now` last, so once one of its cast buttons is clicked the ordinary X / modes / targets steps take over, and `useNetworkGame`'s `dispatch` sends the finished `via: "effect"` cast as the decision's answer) and builds the matching `Action` from click handlers. Each decision kind gets its own small UI (e.g. `commander-replacement` shows a move-to-command-zone prompt; `choose-modes` shows Yes/No, one-button-per-mode, or toggle+Confirm depending on shape; `choose-x`/`choose-sacrifice` run before targeting and thread through it). `renderPlayerPanel`/`renderHandAndControls` are shared between the 2-player and quadrant-grid layouts. What a spell or ability on the stack targets is marked on the board (`Table`'s `aim`: the top of the stack's targets, or the hovered entry's via `Stack`'s `onFocusEntry`): a red frame and a reticle (`ui/TargetedMark.tsx`) on a permanent, a red frame and a "Targeted" chip on a player's panel, a red glow on a targeted spell's stack card — its own channel, since the border ring and the attack outline are both in use while a player responds. **`setState` updaters must stay pure** — dispatch happens after `setTargeting`, not inside its updater. State that must *not* reset per frame lives in `GameScreen` and comes in as props — the peekable hand tray's raised flag, which as `Table`-local state slammed the hand shut every time you played a card. For the same reason, anything measured off the layout that changes what's drawn is measured in a `useLayoutEffect` or a callback ref (as the boards' tile width is), never a plain `useEffect`: a freshly mounted `Table` would paint one frame at the default first. The hand's card spacing did exactly that, and the hand jittered through the mulligan each time a bot decided.
- **`lobby/`** — the two screens before a game. **`LandingScreen`** (`landing.css`) is the front door: a hero, then "Start a game" and "Join a game" as two separated panels, then the library/deck-builder pages as footer cards. It is a real page, not `.overlay`/`.overlay-box` — reusing the same box the "Connecting…" dialog draws is why the app's first impression used to be a 368x277 modal on an empty scrim. It asks **no** player count: three "N players" buttons above the CTA left nothing tying the counts to the button under them (all four read as one menu), and the *selected count* was the only accent-coloured thing on the page, so a setting outranked the primary action. The count moved to `SeatBoard` — see below. The join field carries no `maxLength`: the browser applies that to pasted text, which would chop a pasted room *link* to five characters before `parseRoomCode` could read the code out of it; the cap lives in `normalizeCode` instead, and a complete five-character code submits itself. Behind it all, `client/public/menu-backdrop.webp` (a seamlessly-tiling 10x10 grid of the top 100 commanders) drifts diagonally: an outer element holds the angle and clips while an inner one, exactly one tile wider, slides exactly one tile — which lands on an identical repeat, so only a transform animates and no edge is ever dragged into view. Two things there are easy to get wrong and are commented in `landing.css`: the oversize has to add *half the opposite axis* rather than a flat percentage (a fixed 160% covers 16:9 and fails on a wide, short window), and the blur is baked into the image rather than applied as a CSS `filter` — blur strips exactly the high-frequency detail that costs bytes, which took the same 2048px export from 1278KB to 263KB. The shipped file is 1536x2128 at 152KB, from a 241MB 7680x10640 source: `magick src.png -background "#12171b" -alpha remove -alpha off -filter Lanczos -resize 1536x -gaussian-blur 0x3 -quality 72 menu-backdrop.webp`. **`SeatBoard`** (`lobby.css`) is the seat-picker/waiting room. Its table-shaping controls (seats, bots and their decks, bot speed, Start Game) render only for the host; everyone else sees a Host badge on the host's seat, the bot speed as text, and "Waiting for <host> to start". It owns table size via an "Add seat" tile on the end of the row plus a × on any seat nobody is sitting in (2-4, enforced server-side by `PendingRoom`). Its grid gap and the dialog's own side padding share one `--seat-gap` token declared on `.seat-board-box`, because the grid runs the full width of that box and two different numbers there read as an uneven row. A seat's deck starts as the deck builder's active one (`getActiveDeck()`) and can be swapped per seat in `DeckPickerModal`; `claimSeat`/`addBot`/`setBotDeck` send it as a `WireDeck`.
- **`deck-builder/`** — `DeckBuilderPage` (`/deck-builder`, no room server needed to browse/build): search the pool (`cardPool().cards` filtered by `isDeckableCard` — no tokens, no back faces; the result list pages at `POOL_PAGE_SIZE` 100, larger than the library's because a row here is text rather than an image), build a 100-card deck with a commander or a Partner pair (`SavedDeck.commanders` — a deck saved with the older single `commander` is migrated on read; starring a card pairs it with a commander it can partner with, and otherwise replaces them), and see live `validateCommanderDeck` legality — run in-browser from `engine` over `cardPool().registry`, no round-trip. **Right-clicking a card row** opens `CardContextMenu` (portalled to `<body>` and placed from JS, like the hover preview, since the lists are scroll boxes); its one unique item is "Change printing…", which opens `PrintingPicker` over Scryfall's `unique=prints` search (`printings.ts`, a direct browser call — one search for one card, unlike the import's hundred-name batch that needs the server). The choice is stored on `SavedDeck.printings` (card name → Scryfall card id) and travels `WireDeck.printings` → `DeckList.printings` → `viewFor`'s `art`. The server only accepts a bare card id there (`assertPrintingsAreSafe`): the value ends up as an `<img src>` in *every* seat's browser, and `resolveArtUrl` would otherwise take any absolute URL verbatim. Also hosts the **decklist import** panel, which POSTs pasted text to `/import-deck`, streams that endpoint's NDJSON progress lines into a live per-card progress bar, substitutes each unimplemented card's first suggested stand-in, and then opens `ReplacementReview` — a popup that walks the substitutions one at a time as real card faces (the original from Scryfall by name on the left, the up-to-three stand-ins on the right with a match-strength badge and the oracle tags each shares), where clicking a face (or 1-3, with ←/→ between cards) swaps it into the saved deck on the spot; a card the deck already holds is blocked. The report banner above the editor summarises the swaps and reopens the popup, and carries each kept card's `printingId` into the new deck's `printings` — so an imported list keeps the art it was exported with, without anyone opening the picker. `decks.ts` is per-browser persistence in `localStorage` (not `sessionStorage` — a deck should outlive the tab): a named `SavedDeck` list plus an `ActiveRef` pointing at either a saved deck or one of `engine`'s `SAMPLE_DECKS` directly, so a starter deck is playable without duplicating it first. Server-side deck save/share doesn't exist yet.
- **`library/`** — `LibraryPage` (`/library`): the public, read-only card gallery, shaped like a Scryfall search result — a sticky search/filter bar (text, type, colour, sort and its direction — unranked cards stay last either way —, a "Tokens" toggle) over a **paginated** responsive grid of whole printed card faces (`PAGE_SIZE` 60, rounded to a whole number of rows of the grid's current column count — `pageSizeFor`, measured by `useGridColumns` — so only the last page ends in a short row; `loading="lazy"` keeps images off the wire but does nothing about node count, which is what costs layout time as the pool grows into the thousands). Its rows are built once from `cardPool()`, the first time the page renders. One sort is **`Popularity`**, off `engine`'s generated `EDHREC_RANK` (which ships in the library's own chunk), with unranked cards (basics) last (`CardImage`, not `CardTile` — nothing here is a game object, so there's no live state to overlay), and a card's own page as an overlay rather than a side pane, so the grid keeps its scroll and filters. One entry per *card*, not per registered definition: a DFC's back face appears as its front's flip side (`isCardFront`), and tokens are excluded unless asked for. `?card=Name` deep links.
- **`ui/`** — `CardTile` (a card face *reassembled* out of DOM — title/cost, Scryfall art crop via `ui/art.ts`, type line, text box, P/T or loyalty badge; props for `highlight`/`selected`/`activatable`/`badge`/`order`/`stackCount`/`compact` — because it has to overlay live game state on it). `CardImage` is the other half of that pair: the whole printed face as one image, for anywhere there's no game state to show (the library gallery). It owns `ui/card-image.css` — one of the two stylesheets a component imports rather than a page, with `Symbols`' `ui/symbols.css` — and skips the art lookup entirely for a token with no pinned printing, since a token's name isn't one Scryfall has ever known. `ui/Symbols.tsx`+`symbols.ts`+`mana.ts` render `{…}` mana tokens as pips (art sliced from a spritesheet, CSS fallback for exotic symbols). A planeswalker loyalty cost opening a line (`[+1]:`, `[-4]:`, `[0]:`, or the bare `+1:` Oracle form) becomes the printed loyalty badge instead: the Mana font's up/down/zero shape with the number laid over it, nudged per shape into the shape's body. That covers every card text and the ability menu at once. A permanent's loyalty is `LoyaltyCounter`, the starting-loyalty shield, in place of a gold box. `ZoneViewer` (takes `ids` + a `resolve(id)` lookup so an unresolvable id renders face-down; optional `castable` prop for graveyard flashback/play-from-graveyard buttons; in `selection` mode — a forced choose-from-zone/scry/surveil decision — a "View board" button hides it via `collapsed`/`onCollapse`, still mounted so picks survive, and `Table`'s `decisionCollapsed` puts a "Show choices" button in the decision strip as the way back; `CreatureTypePicker` shares the same state). `MiniTile` (a battlefield permanent as art + a stat badge) **portals its hover popover to `document.body` and places it from JS** — below the tile, flipped above when near the bottom of the screen, clamped inside the viewport; it can't be a CSS-revealed absolutely-positioned child, since `.quadrant-body` is a scroll box (clips it) *and* a size container (so `position: fixed` wouldn't escape either). Its width is **per board**: `Table`'s `recomputeBoardMiniW` binary-searches the widest `--mini-w-fit` at which that board's rows still fit its quadrant's height, and the `.board` rule caps it at `--card-w-max`, so a sparse board's tiles grow into the room they have and a crowded one's shrink, to a 40px floor past which the board scrolls. It measures the rows' extent, never the board's own box — the board is stretched to the command/library rail's height, which is what used to pin every tile at the floor. A tile's keywords are drawn as the Mana font's Arena ability icons (`ui/abilityIcons.ts`, a `Record` over the engine's `Keyword` union so a new keyword without an icon fails the build). Only the font's woff2 is bundled, registered through `FontFace`, never the package's stylesheet, which drags in every font format. `mana-font` is pinned to an exact version because the glyphs are private-use code points copied from its CSS. `AbilityMenu` (a permanent's activated abilities, as a small menu beside the permanent — portalled and JS-placed for the same reasons `MiniTile`'s popover is, finding its anchor in the live DOM by the tile's `data-obj-id`, flipping to the tile's other side at a screen edge; it used to be a bar docked in the hand strip, a whole screen away from the tile it belonged to). `PhaseTrack`, `TurnBanner`, `PlayerPanel`, `Stack`, `EventLog`. A permanent's summoning sickness and its designations — goaded (in each goader's seat colour, naming them) and suspected — are `ui/CardFlags.tsx`'s chips in its bottom-left corner, stacked up the edge on a battlefield tile. `PlayerPanel`'s zone row gains an "emblems N" link once the player has one, opening the zone viewer on `defToVisible.ts`'s `emblemToVisible` cards ("Emblem — <source>", with the source card's art). `PlayerPanel`'s header carries the player's counters (poison, energy, experience) right after the name, and a `CommanderDamageChip` per commander that has dealt that player combat damage — the commander's art in a ring of its owner's seat colour plus the total, amber from 15 and red from 18 of 21 — in the header row rather than a row of its own, since a quadrant has no height to spare. `CommanderTile` is the command zone's compact commander: just its art and mana cost (tax included), with name and P/T left to the hover card. Clamped into a rail a few pips wide the name was rarely readable, and the two together overflowed the rail on a short screen and left no room for a second commander. Two Partners get a tile each, `paired` (a shorter art box and tighter spacing), stacked with a gap in `.command-stack` so they read as two cards. The rail is one card wide and height-capped: measured at a 583px-tall viewport, a Partner pair and the library still fit its 165px. In a quadrant the cost stays on one line with its pips shrinking to fit: wrapping put one pip per line and overflowed every rail at 768px. `AnimationLayer` draws the purely cosmetic overlays (a card zooming up when cast or played, an attacker lunging at what it damages, turn/phase banners, a revealed card held up briefly — deliberately not a dismissible modal, since the History log already keeps the permanent record and a tutor-heavy deck would otherwise make an opponent dismiss one every turn) off the cues `usePlayback` publishes — nothing here ever touches game state, and a missed or double-played animation is harmless.
- **`ui/art.ts`** — `resolveArtUrl(art, name, version?, opts?)`: a `CardDefinition.art` link (a bare card id, a Scryfall page/API link, or a direct `cards.scryfall.io` file, whose first path segment is the size and so gets re-pointed at the one asked for) or a by-name Scryfall fallback. `opts.backFace` appends `face=back`, which is the only way to address a DFC's second image when the reference is a card id — pass `VisibleObject.faceIsBack` for it. Names without a pinned printing resolve through a batched `/cards/collection` lookup (`queueArtLookup`), and that name → image-URL cache is **persisted to `localStorage`** (`mtg-engine:art-cache:v1`, 14-day expiry, capped at 4,000 entries) — so a repeat visit to the library renders the faces it has shown before from the browser's HTTP cache without re-asking Scryfall for every URL first. Blocked or full storage just means a cold start. **Every emitted URL is host-checked against `ALLOWED_ART_HOSTS`**, and anything else falls back to the by-name lookup: `art` is also where another player's chosen printing lands after crossing the wire, and this function is what turns a value into an `<img src>`, so an arbitrary host here would be a request from every viewer's browser to whoever picked it. `cssUrl(url)` wraps one for a `background-image` — **always use it there**: an unquoted `url()` token may not contain a quote character and `encodeURIComponent` leaves an apostrophe alone, so every card whose name has one ("Atraxa, Praetors' Voice") silently lost its art.
- **`game/board.ts`** — `computeBoardEntries(view, pid)`: pure layout logic turning one player's battlefield into `BoardEntry[]` (bucketed by type, Auras/Equipment nested as `attachments`, matching untapped/tapped land stacks collapsed).
- **`game/damageAssignment.ts`** — the `assign-combat-damage` bar's model, pure. `groupBlockers` folds the offer's blockers into rows of interchangeable ones (the same in everything the view shows bar summoning sickness, the same lethal, nothing attached), because a token stack blocks as one creature per token and one input each made a twenty-Goblin block taller than the quadrant under it. The rows scroll past a few, and the board takes clicks for the same choice (`clickMembers`: one more to lethal, else spare), each blocker badged with its damage. A click or a row's `+` that needs more than is free takes it from other blockers wherever that kills least: damage past lethal, then damage too little to kill, then the cheapest kills. The answer is still one amount per blocker in offer order, checked by the engine's `damageAssignmentViolations`. Indestructible blockers take lethal (trample needs it) but aren't drawn as dying.
- **`game/usePlayback.ts` + `game/animationBus.ts` + `game/animationSchedule.ts`** — the animation pipeline, Hearthstone-style: **one thing at a time, and nothing may act until it finishes**. `usePlayback(frame, bus, onShown)` queues the server's frames and plays them one at a time — each frame's animations run against the board *before* it (the previous frame's, still on screen), and only when they finish does the new board replace it. It reports `{view, actions, revision, busy}`; `busy` empties `Table`'s action list, and `onShown` (wired to `ackFrame`) is what lets the server hold its bots to the same rule. `scheduleEvents` gives each animate-worthy event its slot (`CARD_STEP_MS` 1800 / `HIT_STEP_MS` 720 / `DEATH_STEP_MS` 420 / `DRAW_STEP_MS` 520 / `TURN_STEP_MS` 1300 / `PHASE_STEP_MS` 700 — the same numbers `AnimationLayer`'s overlay timeouts and App.css's `animation-duration`s are written to, so nothing outlives its slot), with `MAX_FRAME_MS` (6s) as a backstop that *drops* animations rather than clustering them past the ceiling. **Only the animations in `PACED` (a card play, a combat hit, a permanent leaving) hold the game up**; a turn or phase banner is a caption that plays over whatever the board has moved on to, costing nothing — otherwise a land the bot played hangs in the air for the length of an "End Phase" banner before reaching the table. Banners a frame merely passed *through* are dropped too (only the phase it lands in is announced), and `MAX_QUEUED_BANNERS` (3) keeps the banner queue from narrating a turn that finished several turns ago. `AnimationBus` carries cues sideways to `AnimationLayer` (a sibling, since `Table` remounts per frame), and **each cue carries the view it belongs to** — that's what makes a played land draw as it looked when played, rather than as it looks after the bot tapped it. A played card flies out of its owner's `.quadrant-cell` and shrinks back toward it (`flyOrigin` measures the cell off the live DOM and hands the offset to the CSS as `--fly-x`/`--fly-y`), so which side of the table a play came from is readable at a glance. A permanent leaving the board fades out first (`runDeath`, on `permanent-left-battlefield`, whatever the destination) rather than blinking out of existence; a run of them in one frame goes together on one beat. An attacking creature is tapped, so its tile is drawn tilted — the lunge travels on the outer `data-obj-id` box and the tilted face inside just goes along (straightening it up on impact read as the card spinning), clamped to stay inside its quadrant's scroll box, since a tile translated past a scroll box's edge counts toward its scrollable overflow and flashes a scrollbar. A `card-drawn` sends a small cardback out of that player's `data-library-of` pile and into their hand — the bottom edge of their cell for you, the top edge for a seat across the table (`drawFlight`) — staggered when several land at once and capped per frame, and unpaced like the banners. `MAX_QUEUED_FRAMES` (4) is the catch-up valve for a backgrounded tab whose timers have been throttled.
- **`format.ts`** — `describeEvent`/`describeTarget` (event log text), `playerLabel` (prefers a chosen display name, falls back to a capitalized seat id), `seatClassOf` (stable per-seat colour by turn-order position, not table position), `isDetailOnlyEvent` (the bookkeeping the history hides by default — priority going round, step boundaries, mana entering a pool and the lands tapping to fill it; it's roughly three quarters of the log by volume, so `EventLog` opens concise and offers "Detailed" as a toggle). `EventLog` names each line's objects by what they were publicly known as when that event happened (`publicNameAt` over the view's `publicStints`, falling back to the current view), so a line keeps its card's name after the card is bounced to a hand; and a name there shows the whole card on hover (`LogCardName`, a portalled `CardTile` through `useHoverPopover`, layered over the History popup with `.over-history`).
- A rejected `dispatch` surfaces as `NetworkGame.error` → a dismissable red banner.
- Styling is `App.css` for the game table (plus a small `.css` beside each standalone page: `lobby/` — two files, `landing.css` and `lobby.css` — `deck-builder/`, `library/`) — legible dark table, no UI library. `index.css` holds the palette tokens and the element-level baseline for `button` and for text `input`s; that input rule is written as `input:where(…)` so it weighs the same as a bare element selector and every per-page class rule still wins. Card art is the only network dependency. Out of scope: undo.

**Standing UI rules** (settled during the board redesign — see `client/BOARD_REDESIGN_PLAN.md`):

- **No fixed px.** Sizing is `clamp()`/`vw`/`vh`, derived from the shared `--card-w` token for anything card-sized — never a new hardcoded number.
- **`--card-w` is viewport-*width*-derived; cap it against height where height is the real constraint.** A card-shaped box inside a container whose height is a viewport fraction (the quadrants are roughly half of it) needs a height cap too, or it fits on a tall monitor and overflows a short one — the two scale independently, and `--card-w` sits at its 150px ceiling all the way down to a 1667px-wide viewport. `--card-w-max` is the ceiling and `--card-w` is what everything reads, so a height-constrained subtree narrows `--card-w` for itself against that ceiling (the command/library rail does exactly this: `.quadrant-body` is a `container-type: size` container and the rail caps at `32cqh`). That cap is set against the **commander slot alone**, because the library pile below it squashes to whatever is left rather than demanding a full card's height — stacking two full slots plus their labels needs about twice a card's height, which at 768px tall didn't fit at all (a 286px rail in a 269px quadrant, the library count clipped off every cell, and that overflow was what made the boards scroll). The rail also stretches to the quadrant's full height, so its seat-coloured divider runs down the whole board. Note that making `.quadrant-body` a size container also makes it the containing block for `position: fixed` descendants (`contain: layout`), which is why the board's hover popover has to leave the subtree entirely rather than just going fixed.
- **What a decision picks from the board is picked on the board**, never from a row of name buttons (two Forests, or two copies of one creature, are two identical buttons): the eligible permanents are highlighted and clicked, players by their panel (`PlayerPanel`'s `targetable`/`selected`). Buttons are for what isn't on the board — "Copy nothing", "All mine", Confirm. And **every decision but the mulligan asks in the bottom-right `.decision-banner`**; one that picks from the hand (discard, put-on-bottom) holds the hand tray open under it rather than docking beside the hand, which pulled the strip out of its tray and squashed the board.
- **Mana symbols always go through `<Symbols text={…} />`**, which renders `{…}` tokens as sliced-artwork pips with a CSS fallback. Never hand-roll a coloured circle.
- **Columns that must be equal need `minmax(0, 1fr)`, not `1fr`.** A bare `1fr` is `minmax(auto, 1fr)`, so a track whose content has a wide minimum (a row of input-plus-button, a long unbreakable word, an image) takes more than its share and its neighbour takes less. On the landing page that silently gave the join panel 414px against the start panel's 387 while the footer nav below, having no such pressure, split evenly and lined up with neither. The same footgun is why the seat grid and the board rows are written with `minmax(0, 1fr)` too.
- **A child that names its own width inside a padded box will escape that padding.** `.seat-board` at `min(1180px, 90vw)` inside a `.seat-board-box` at `min(1180px, 94vw)` overran the box's content area on a wide screen and pushed the outer seat panels out through its side padding. Let the box own the width and the child fill it (`width: 100%`).
- **The client's only automated tests are a Playwright smoke suite** (`client/e2e/`, `npm run test:e2e -w client`): the landing page, a 2- and a 4-player dev room at 1366x768, and walking into combat. It catches a page that no longer loads or a flow that no longer reaches its decision, not a layout that got worse, so verify any UI change live in the browser, in *both* a 2-player and a 3-4 player room, since the layouts diverge — **and at a short viewport (~768px tall), not just whatever monitor you're on.** Several severe layout bugs (every battlefield tile crushed to its 40px floor, the command/library rail overflowing its quadrant, the hand fan hanging off the bottom of the screen) were invisible at 1440p and obvious at 768p.

## Client commands, in full

- `npm run dev -w client` — Vite dev server with HMR (build `engine`/`server` first); needs a room server reachable at `ws://<host>:4000` (override with `VITE_SERVER_URL`)
- `npm run build -w client` / `lint -w client` / `preview -w client`
- `npm run test:e2e -w client` — the Playwright smoke suite (`client/e2e/`, config `client/playwright.config.ts`, CI `.github/workflows/e2e.yml`). It starts `dev-rooms` and the Vite dev server itself, or reuses them if they're already up, and resets each dev room it uses through the command port. Build `engine`, `protocol` and `server` first. It runs one test at a time on purpose: a dev-rooms `reset` drops every open connection, not just that room's. `@playwright/test` is pinned to the version whose Chromium the cloud sessions' image ships; elsewhere run `npx playwright install chromium` once.
- To watch it run by hand: start a room server, then `npm run dev -w client` and open two tabs/devices to the same room code.
