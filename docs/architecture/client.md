# Client architecture reference (`client/src/`)

Reference detail, **not loaded automatically**: read the entry for a file before changing it. The short, always-relevant version is `client/CLAUDE.md`; this is the per-file detail it points into. Keep it current when a file's shape changes, but it is a map of the code as it is, not a changelog.

## The workspace

- `client/` — a Vite + React 19 + TypeScript app: a **networked** client — each device is one seat, connected over WebSocket to a `server` room, never running a local `Game` or a controller loop itself. Imports the engine (`"engine": "*"`, the workspace symlink) as **`engine/client`** — `engine/src/client.ts`, a second package entry with every type but only the values a page uses, none of which reaches a card definition (`test/client-entry.test.ts` walks its imports to keep it so). The main `engine` barrel exports `BUILTIN_CARDS`, which imports every card file, and Vite's dev server doesn't tree-shake, so a page importing the barrel fetched all ~5,500 card modules on every load (16 s warm). No page imports `engine` itself. Consumes the engine's public seam — the `Action`/`LegalAction`/`PlayerView` types, plus pure helpers such as the combat validators — indirectly, via the wire protocol `server` speaks. Needs `engine/dist/` and `protocol/dist/` built (`npm run build` does engine, protocol, server, then client).

## Architecture

A **networked** client: each device is one seat, connected over WebSocket to a `server` room. It
never owns a `Game` or runs a controller loop itself. 2-player rooms render a classic vertical
layout; 3-4 player rooms render a 2x2 quadrant grid, with you always bottom-left.

**Three pages, branched by path in `main.tsx`** before `<App/>` is chosen, so `useNetworkGame`'s
eager WebSocket never opens for the two network-free ones: `/library` → `LibraryPage`,
`/deck-builder` → `DeckBuilderPage`, everything else → `App` (the game itself). The two
network-free pages are `React.lazy` chunks, each fetched **together with the whole card pool**
and rendered once both are in; the game's own download holds no card definitions at all (see
`cards/cardData.ts` below).

- **`cards/cardData.ts`** — the client's only way to card definitions, which the engine ships as
  32 name-hashed shards, each its own file in the build (engine `cards/card-shards.ts`). A
  **lookup by name** — `peekCard` (sync: the definition, `null` for no such card, `undefined`
  while its shard isn't loaded), `loadCard`, `requestCards` and the `useCardData` hook (re-renders
  as each shard arrives) — fetches only the shard that name hashes to. That serves the game page's
  two extras: an event-log name's tooltip (fetched as the pointer reaches it) and a double-faced
  card's other face in `ZoneViewer`. Everything a game needs to be *played* comes in the server's
  views instead. The **whole pool** — `loadCardPool`, then `cardPool()` (`cards`, `tokens`,
  `byName`, and a `CardRegistry` for the engine's deck rules) — is what the library and the deck
  builder read, synchronously, since `main.tsx` has loaded it before they render. A commander's art
  in the lobby needs no definition at all: the engine's generated `PINNED_ART` holds the few
  printings the pool pins, and everything else resolves on Scryfall by name. A shard that fails
  to load (the network, or a deploy replacing the build while a tab is open) reads as not loaded
  and is asked for again next time. While the pool loads, the lazy pages show
  `cards/PoolLoading.tsx`: a progress bar (`role="progressbar"`, shards loaded of
  `CARD_SHARD_COUNT`) fed by `usePoolProgress` — `poolProgress()`'s `{loaded, total}`, a snapshot
  replaced as each shard arrives, counting shards a lookup by name fetched first and never a failed
  one. A failed shard rejects `loadCardPool`, and `PoolLoadBoundary` swaps the bar for a reload
  offer; a shard that never answers leaves the bar still, so after 15 s without a new shard it
  says "This is taking longer than usual" with a Reload button, hung below the bar so the bar
  doesn't move, inside a `role="status"` region that's there (empty) from the start so a screen
  reader announces it. The bar's fill and the screen's fade-in follow `motionPrefs`
  (`--anim-scale`; neither moves under `[data-reduce-motion]`, set by the viewer's own setting or
  the browser's); `cards/cardData.test.ts` covers the accounting and
  `e2e/pool-progress.spec.ts` the page, holding the shard responses to read the bar part-way
  (`E2E_SHOTS_DIR` saves screenshots). `engine/client` doesn't export `BUILTIN_CARDS`,
  `POOL_CARDS`, `TOKEN_CARDS` or `createDefaultRegistry`, and must not start to: any of them puts
  the whole pool back into whichever chunk imported it.

- **`net/useNetworkGame.ts`** — owns the WebSocket connection and the current seat's latest `frame` (`{seq, view, actions}` — one server push, whole), with `view`/`actions` derived from it for bookkeeping that has to be current. Reconnects with exponential backoff; a previously-claimed seat (`clientToken` in `sessionStorage`, per-tab) is reclaimed automatically. `ConnectionStatus` is `connecting` → `no-room`/`room-not-found` → `choosing-seat` → `waiting-for-players` (my seat is claimed but the room is still a `PendingRoom` — other seats are open) → `playing`/`disconnected`. `opponents: readonly PlayerId[]` is every other seat in turn order starting right after your own, wrapping around. `createRoom()` (mints and stores this tab's host token), `isHost`/`botSpeed`/`setBotSpeed(speed)`, `claimSeat(seat, displayName?, deck?)`, `addBot(seat)`, `addSeat()`/`removeSeat(seat)`, `dispatch(action)`, `passTurn()`/`autoPass()`/`toggleManaSkip()`, `ackFrame(seq)`, `nameOf(id)`. `everConnected` distinguishes a first visit to a server that isn't up from a connection actually lost mid-game — both land on `disconnected` (a failed initial socket fires `onerror` then `onclose` without ever reaching `no-room`), and only the wording differs.
- **`net/`** — no `protocol.ts` of its own: the wire types come from the `protocol` workspace (`import type { ServerMessage } from "protocol"`), exactly as on the server.
- **`App.tsx`** — `App` picks a screen off `NetworkGame.status`: `LandingScreen` → `SeatPickerScreen` → `GameScreen`. `GameScreen` renders the topbar/history popup, seat banner, highroll banner, `<Table>`, plus the floating `<Stack>` overlay and `<AnimationLayer>` as siblings. **Everything it draws comes from `usePlayback`'s `shown` view, never `game.view`** — the two differ for as long as an animation is running, and mixing them is what put a card's arrival animation over a board that already had the card on it. `Table` (keyed on `shown.revision`, i.e. one remount per frame actually shown) classifies `actions` into a `mode` (mulligan → commander-replacement → pay-life-for-untapped → reveal-for-untapped → choose-copy → choose-enchant → legend-rule → choose-text → choose-modes → sacrifice → scry → assign-combat-damage → put-on-bottom → discard → attackers → blockers → choose-from-zone → choose-x → choose-sacrifice → targeting → cast-now → priority — `cast-now` last, so once one of its cast buttons is clicked the ordinary X / modes / targets steps take over, and `useNetworkGame`'s `dispatch` sends the finished `via: "effect"` cast as the decision's answer; a land on offer (hideaway's "you may play the exiled card" — the offer's `lands`) is a Play button that answers with a `play-land` directly; with several cards on offer, or `looked` cards to look at first, the card is picked in a `ZoneViewer` popup — "Don't cast" as its none — and a card with more than one way to cast it, kicked or not (a multikicker once per number of kicks, its `kickCount` echoed back), a face, or one X each when its target reads X (`xCost.minX` = `maxX`, which skips the X prompt), gets a button per way with a Back; an X spell's targeting runs on `specsAtX(targetSpecs, X)`, so an "X target …" group's Done waits for X members — `mayFinishGroup`) and builds the matching `Action` from click handlers. Each decision kind gets its own small UI (e.g. `commander-replacement` shows a move-to-command-zone prompt; `choose-modes` shows Yes/No, one-button-per-mode, or toggle+Confirm depending on shape, plus "Yes to all N" / "No to all N" when identical triggers wait under a trigger's "you may" (`sameForAll`, answered with `forAll`); `choose-x`/`choose-sacrifice` run before targeting and thread through it; an escape cast's exiled cards and then a delve cast's are picked before those, each in a `ZoneViewer` (`pendingEscape`, `pendingDelve` — delve between its offer's `minCards` and `maxCards`), carried on as `CastPicks`). `renderPlayerPanel`/`renderHandAndControls` are shared between the 2-player and quadrant-grid layouts. What a spell or ability on the stack targets is marked on the board (`Table`'s `aim`: the top of the stack's targets, or the hovered entry's via `Stack`'s `onFocusEntry`): a red frame and a reticle (`ui/TargetedMark.tsx`) on a permanent, a red frame and a "Targeted" chip on a player's panel, a red glow on a targeted spell's stack card — its own channel, since the border ring and the attack outline are both in use while a player responds. **`setState` updaters must stay pure** — dispatch happens after `setTargeting`, not inside its updater. State that must *not* reset per frame lives in `GameScreen` and comes in as props — the peekable hand tray's raised flag, which as `Table`-local state slammed the hand shut every time you played a card. For the same reason, anything measured off the layout that changes what's drawn is measured in a `useLayoutEffect` or a callback ref (as the boards' tile width is), never a plain `useEffect`: a freshly mounted `Table` would paint one frame at the default first. The hand's card spacing did exactly that, and the hand jittered through the mulligan each time a bot decided. The division step (`pendingDivision`) serves an ability as well as a cast: an `activate-ability` offer's or a `choose-targets` decision's `divide` is carried on the `Targeting`, and the answer goes out as that action's `division`. A `Targeting` also carries `facts` (`viewTargetFacts(view)` — who controls a target, its power, off the view), which `slotOptions` narrows "controlled by different players" and "total power N or less" by; the off-board group popup's Confirm waits on `groupPowerExceeded`. The escape-exile picker serves a graveyard permission's "exile N other cards" too (Kotis), worded by the cast's `via`. A modal cast's mode chooser (`choose-cast-modes`) draws each mode's text through `Symbols`, and for a spree spell (rule 702.172a) keeps to the offer's `castModal.modeSets`: a mode is open while some payable set holds it beside the picks, and Confirm waits for picks that are one of those sets. A gift spell's promised variant is its `kickerKeyword: "gift"` button; the opponent is asked afterwards, one at a time, as an optional `choose-modes` with `about`. `zoneChoiceTitle` says whose hand the cards go to when a `choose-from-zone` offer's `forPlayer` is someone else. `zoneChoiceTitle` has a line for an `"exile"` destination (Necropolis Fiend's cost).
- **`lobby/`** — the two screens before a game. **`LandingScreen`** (`landing.css`) is the front door: a hero, then "Start a game" and "Join a game" as two separated panels, then the library/deck-builder pages as footer cards. It is a real page, not `.overlay`/`.overlay-box` — reusing the same box the "Connecting…" dialog draws is why the app's first impression used to be a 368x277 modal on an empty scrim. It asks **no** player count: three "N players" buttons above the CTA left nothing tying the counts to the button under them (all four read as one menu), and the *selected count* was the only accent-coloured thing on the page, so a setting outranked the primary action. The count moved to `SeatBoard` — see below. The join field carries no `maxLength`: the browser applies that to pasted text, which would chop a pasted room *link* to five characters before `parseRoomCode` could read the code out of it; the cap lives in `normalizeCode` instead, and a complete five-character code submits itself. Behind it all, `client/public/menu-backdrop.webp` (a seamlessly-tiling 10x10 grid of the top 100 commanders) drifts diagonally: an outer element holds the angle and clips while an inner one, exactly one tile wider, slides exactly one tile — which lands on an identical repeat, so only a transform animates and no edge is ever dragged into view. Two things there are easy to get wrong and are commented in `landing.css`: the oversize has to add *half the opposite axis* rather than a flat percentage (a fixed 160% covers 16:9 and fails on a wide, short window), and the blur is baked into the image rather than applied as a CSS `filter` — blur strips exactly the high-frequency detail that costs bytes, which took the same 2048px export from 1278KB to 263KB. The shipped file is 1536x2128 at 152KB, from a 241MB 7680x10640 source: `magick src.png -background "#12171b" -alpha remove -alpha off -filter Lanczos -resize 1536x -gaussian-blur 0x3 -quality 72 menu-backdrop.webp`. **`SeatBoard`** (`lobby.css`) is the seat-picker/waiting room. Its table-shaping controls (seats, bots and their decks, bot speed, Start Game) render only for the host; everyone else sees a Host badge on the host's seat, the bot speed as text, and "Waiting for <host> to start". It owns table size via "Add seat" and "Remove seat" tiles in a column on the end of the row (Remove drops the last seat nobody is sitting in, so the table shrinks from the end it grows at), plus a × on any such seat (2-4, enforced server-side by `PendingRoom`). A seat is the same width at every table size — the width it has when four share the row, with room for the controls column set aside — and a smaller table is a narrower, centred row of them: letting two seats take half the row each made the two-player lobby a different screen (450px deck art, Start Game below the fold at 768px). An empty seat's deck slot is laid out like a filled one (an art-shaped box, then the name and commander lines), so the row doesn't go ragged as decks are picked. Its grid gap and the dialog's own side padding share one `--seat-gap` token declared on `.seat-board-box`, because the grid runs the full width of that box and two different numbers there read as an uneven row. A seat's deck starts as the deck builder's active one (`getActiveDeck()`) and can be swapped per seat in `DeckPickerModal`; `claimSeat`/`addBot`/`setBotDeck` send it as a `WireDeck`. **A device takes a seat as it arrives** in a waiting room (`SeatBoard`'s effect → `takeSeat` → the server's `take-seat`, un-readied, named "Player N"; `room-joined` carries the `seat` it got and whether the room is `pending`), so two people who haven't readied no longer both draw themselves in the first open seat. A full table under four grows a seat for the arrival. The name field stays open until Ready, which sends a typed name with it. A rejoin to a waiting room goes through `take-seat` too (it reuses the stored token), since an un-readied seat is freed when its device drops.
- **`deck-builder/`** — `DeckBuilderPage` (`/deck-builder`, no room server needed to browse/build): search the pool (`cardPool().cards` filtered by `isDeckableCard` — no tokens, no back faces; the result list pages at `POOL_PAGE_SIZE` 100, larger than the library's because a row here is text rather than an image), build a 100-card deck with a commander or a Partner pair (`SavedDeck.commanders` — a deck saved with the older single `commander` is migrated on read; starring a card pairs it with a commander it can partner with, and otherwise replaces them), and see live `validateCommanderDeck` legality — run in-browser from `engine` over `cardPool().registry`, no round-trip. **Right-clicking a card row** opens `CardContextMenu` (portalled to `<body>` and placed from JS, like the hover preview, since the lists are scroll boxes); its one unique item is "Change printing…", which opens `PrintingPicker` over Scryfall's `unique=prints` search (`printings.ts`, a direct browser call — one search for one card, unlike the import's hundred-name batch that needs the server). The choice is stored on `SavedDeck.printings` (card name → Scryfall card id) and travels `WireDeck.printings` → `DeckList.printings` → `viewFor`'s `art`. The server only accepts a bare card id there (`assertPrintingsAreSafe`): the value ends up as an `<img src>` in *every* seat's browser, and `resolveArtUrl` would otherwise take any absolute URL verbatim. Also hosts the **decklist import** panel, which POSTs pasted text to `/import-deck`, streams that endpoint's NDJSON progress lines into a live per-card progress bar, substitutes each unimplemented card's first suggested stand-in, and then opens `ReplacementReview` — a popup that walks the substitutions one at a time as real card faces (the original from Scryfall by name on the left, the up-to-three stand-ins on the right with a match-strength badge and the oracle tags each shares), where clicking a face (or 1-3, with ←/→ between cards) swaps it into the saved deck on the spot; a card the deck already holds is blocked. The report banner above the editor summarises the swaps and reopens the popup, and carries each kept card's `printingId` into the new deck's `printings` — so an imported list keeps the art it was exported with, without anyone opening the picker. `decks.ts` is per-browser persistence in `localStorage` (not `sessionStorage` — a deck should outlive the tab): a named `SavedDeck` list plus an `ActiveRef` pointing at either a saved deck or one of `engine`'s `SAMPLE_DECKS` directly, so a starter deck is playable without duplicating it first. Server-side deck save/share doesn't exist yet.
- **`library/`** — `LibraryPage` (`/library`): the public, read-only card gallery, shaped like a Scryfall search result — a sticky search/filter bar (text — name, flavor names, type line and rules text, type, colour, sort and its direction — unranked cards stay last either way —, a "Tokens" toggle) over a **paginated** responsive grid of whole printed card faces (`PAGE_SIZE` 60, rounded to a whole number of rows of the grid's current column count — `pageSizeFor`, measured by `useGridColumns` — so only the last page ends in a short row; `loading="lazy"` keeps images off the wire but does nothing about node count, which is what costs layout time as the pool grows into the thousands). Its rows are built once from `cardPool()`, the first time the page renders. One sort is **`Popularity`**, off `engine`'s generated `EDHREC_RANK` (which ships in the library's own chunk), with unranked cards (basics) last (`CardImage`, not `CardTile` — nothing here is a game object, so there's no live state to overlay), and a card's own page as an overlay rather than a side pane, so the grid keeps its scroll and filters. One entry per *card*, not per registered definition: a DFC's back face appears as its front's flip side (`isCardFront`), and tokens are excluded unless asked for. `?card=Name` deep links. An omen card (`omen`) is shown like an adventure: one printed image, its Omen beneath an "Omen" divider, never flippable.
- **`ui/`** — `CardTile` (a card face *reassembled* out of DOM — title/cost, Scryfall art crop via `ui/art.ts`, type line, text box, P/T or loyalty badge; props for `highlight`/`selected`/`activatable`/`badge`/`order`/`stackCount`/`compact` — because it has to overlay live game state on it). `CardImage` is the other half of that pair: the whole printed face as one image, for anywhere there's no game state to show (the library gallery). It owns `ui/card-image.css` — one of the two stylesheets a component imports rather than a page, with `Symbols`' `ui/symbols.css` — and skips the art lookup entirely for a token with no pinned printing, since a token's name isn't one Scryfall has ever known. `ui/Symbols.tsx`+`symbols.ts`+`mana.ts` render `{…}` mana tokens as pips (art sliced from a spritesheet, CSS fallback for exotic symbols) — every cost on screen goes through them, a button's too (Cycle, Suspend, a cast's kicker or cost option, a zone viewer's ways to cast, a "you may pay" prompt). `CostSymbols` draws a cost as it is now (`effectiveManaCost`) against the printed one, its generic number tinted a muted green when it has come down, red when it has gone up. A planeswalker loyalty cost opening a line (`[+1]:`, `[-4]:`, `[0]:`, or the bare `+1:` Oracle form) becomes the printed loyalty badge instead: the Mana font's up/down/zero shape with the number laid over it, nudged per shape into the shape's body. That covers every card text and the ability menu at once. A permanent's loyalty is `LoyaltyCounter`, the starting-loyalty shield, in place of a gold box. `ZoneViewer` (takes `ids` + a `resolve(id)` lookup so an unresolvable id renders face-down; optional `castable` prop for graveyard flashback/play-from-graveyard buttons; in `selection` mode — a forced choose-from-zone/scry/surveil decision, whose optional `fits` (an offer's `together`, via `fitsTogether`) holds Confirm until the picks obey a set rule — a "View board" button hides it via `collapsed`/`onCollapse`, still mounted so picks survive, and `Table`'s `decisionCollapsed` puts a "Show choices" button in the decision strip as the way back; `CreatureTypePicker` shares the same state). `MiniTile` (a battlefield permanent as art + a stat badge; `held` is what it holds in exile — the engine's `VisibleObject.holding` resolved against the shown view, `null` for a face-down card — drawn beside the hover card under "Exiled with it", smaller as there are more, with an `Ex N` chip from `CardFlags` on the tile) **portals its hover popover to `document.body` and places it from JS** — below the tile, flipped above when near the bottom of the screen, clamped inside the viewport; it can't be a CSS-revealed absolutely-positioned child, since `.quadrant-body` is a scroll box (clips it) *and* a size container (so `position: fixed` wouldn't escape either). Its width is **per board**: `Table`'s `recomputeBoardMiniW` binary-searches the widest `--mini-w-fit` at which that board's rows still fit its quadrant's height, and the `.board` rule caps it at `--card-w-max`, so a sparse board's tiles grow into the room they have and a crowded one's shrink, to a 40px floor past which the board scrolls. It measures the rows' extent, never the board's own box — the board is stretched to the command/library rail's height, which is what used to pin every tile at the floor. `.quadrant-body` reserves its scrollbar's room (`scrollbar-gutter: stable`): without it the search could loop forever, a width that fits with no scrollbar wrapping a tile onto a new row once the scrollbar a probe left behind narrows the box, so the tiles jumped between rows every frame. A tile's keywords are drawn as the Mana font's Arena ability icons (`ui/abilityIcons.ts`, a `Record` over the engine's `Keyword` union so a new keyword without an icon fails the build). Only the font's woff2 is bundled, registered through `FontFace`, never the package's stylesheet, which drags in every font format. `mana-font` is pinned to an exact version because the glyphs are private-use code points copied from its CSS. `AbilityMenu` (a permanent's activated abilities, as a small menu beside the permanent — portalled and JS-placed for the same reasons `MiniTile`'s popover is, finding its anchor in the live DOM by the tile's `data-obj-id`, flipping to the tile's other side at a screen edge; it used to be a bar docked in the hand strip, a whole screen away from the tile it belonged to). `PhaseTrack` (keeps the current step scrolled into view when the strip is too narrow for all twelve; each pip is a button that flags its step as a **stop** — `game/passSettings.ts`, `toggleStop` — kept apart for your own turns and others', the row showing whichever this turn is, amber when flagged; UT and CU can't be), `TurnBanner`, `PlayerPanel`, `Stack` (an ability entry is drawn as its source permanent is now while that's still on the battlefield — an ability object carries only the card name, so drawn by itself it read as printed: a prototyped Combat Thresher's trigger showed {7} 3/3; each entry is labelled with its controller in their seat colour, and a player target by display name; its label and target lines scale with the card; `Stack` renders inside `Table` and so remounts every frame, which is why it takes `previousStack` — from `usePlayback`'s `previousView` — and gives only an entry that wasn't there before the `is-new` arrival animation; each entry carries `data-stack-id` for `AnimationLayer`'s exits, which find an entry only by the id its event names (`ability-resolved`'s `object` too) — never an older entry of the same source; the "prompted by" entry, like an ability's, is drawn as a card (`asCardFace`: untapped, no damage, counters or combat); the pile sits in from the right edge by a rail's width, clear of the command/library rail and the life totals), `EventLog` (its entries take an `onSelect`: `GameScreen` closes the log and `ui/highlight.ts`'s `highlightEvent` pulses whatever the entry named that's still drawn — permanents, stack entries, your hand, players' panels — read structurally from the event's `object`/`source`/`objects`/`arrivals`/`target`/`player` fields). The top strip also carries the host's bot controls when the table has bots: ⏸/▶ to pause or resume them and, while paused, ⏭ to let one move go (`useNetworkGame`'s `setBotsPaused`/`stepBots`); everyone else sees a "Bots paused" badge. `PlayerPanel` shows "thinking…" (a bot) or "deciding…" (a person) beside the name of the seat the game is waiting on, other than your own, and marks its hand link `data-hand-of`, which flashes "−N discarded" when that player discards (no one else's hand is drawn). The active player's `.quadrant-cell` is framed in their seat colour for the whole turn. A permanent's counters are `ui/CounterChips.tsx`'s pills up the right edge of a battlefield tile, above the P/T badge: the Mana font's `ms-counter-*` glyph for the kind (a keyword counter borrows its keyword's icon, a kind with no glyph shows its initial) and the count; loyalty stays on the shield. A permanent's summoning sickness and its designations — goaded (in each goader's seat colour, naming them) and suspected — and what it chose as it entered (`chosen`: "Temur", a colour letter shown as its name) are `ui/CardFlags.tsx`'s chips in its bottom-left corner, stacked up the edge on a battlefield tile. `PlayerPanel`'s zone row gains an "emblems N" link once the player has one, opening the zone viewer on `defToVisible.ts`'s `emblemToVisible` cards ("Emblem — <source>", with the source card's art). `PlayerPanel`'s header carries the player's counters (poison, energy, experience) right after the name, and a `CommanderDamageChip` per commander that has dealt that player combat damage — the commander's art in a ring of its owner's seat colour plus the total, amber from 15 and red from 18 of 21 — in the header row rather than a row of its own, since a quadrant has no height to spare. `CommanderTile` is the command zone's compact commander: just its art and mana cost (as it is now — a cost reduction shows here as in the hand — with the tax as its own "+N"), with name and P/T left to the hover card. Clamped into a rail a few pips wide the name was rarely readable, and the two together overflowed the rail on a short screen and left no room for a second commander. Two Partners get a tile each, `paired` (a shorter art box and tighter spacing), stacked with a gap in `.command-stack` so they read as two cards. The rail is one card wide and height-capped: measured at a 583px-tall viewport, a Partner pair and the library still fit its 165px. In a quadrant the cost stays on one line with its pips shrinking to fit: wrapping put one pip per line and overflowed every rail at 768px. `AnimationLayer` draws the purely cosmetic overlays (a card zooming up when cast or played, an attacker lunging at what it damages, turn/phase banners, a revealed card held up briefly — deliberately not a dismissible modal, since the History log already keeps the permanent record and a tutor-heavy deck would otherwise make an opponent dismiss one every turn) off the cues `usePlayback` publishes — nothing here ever touches game state, and a missed or double-played animation is harmless.
- **`ui/art.ts`** — `resolveArtUrl(art, name, version?, opts?)`: a `CardDefinition.art` link (a bare card id, a Scryfall page/API link, or a direct `cards.scryfall.io` file, whose first path segment is the size and so gets re-pointed at the one asked for) or a by-name Scryfall fallback. `opts.backFace` appends `face=back`, which is the only way to address a DFC's second image when the reference is a card id — pass `VisibleObject.faceIsBack` for it. Names without a pinned printing resolve through a batched `/cards/collection` lookup (`queueArtLookup`), and that name → image-URL cache is **persisted to `localStorage`** (`mtg-engine:art-cache:v1`, 14-day expiry, capped at 4,000 entries) — so a repeat visit to the library renders the faces it has shown before from the browser's HTTP cache without re-asking Scryfall for every URL first. Blocked or full storage just means a cold start. **Every emitted URL is host-checked against `ALLOWED_ART_HOSTS`**, and anything else falls back to the by-name lookup: `art` is also where another player's chosen printing lands after crossing the wire, and this function is what turns a value into an `<img src>`, so an arbitrary host here would be a request from every viewer's browser to whoever picked it. `cssUrl(url)` wraps one for a `background-image` — **always use it there**: an unquoted `url()` token may not contain a quote character and `encodeURIComponent` leaves an apostrophe alone, so every card whose name has one ("Atraxa, Praetors' Voice") silently lost its art. `prefetchArt(manifest)`, from the first frame's `artManifest`, loads every card's art crop quietly: 1.5 s after that frame, names through the batched lookup, a pinned printing's API redirect paced under Scryfall's rate limit, four images at a time at low priority, nothing under the browser's data saver.
- **`game/board.ts`** — `computeBoardEntries(view, pid)`: pure layout logic turning one player's battlefield into `BoardEntry[]` (bucketed by type, Auras/Equipment nested as `attachments`, matching untapped/tapped land stacks collapsed).
- **`game/boardOrder.ts`** — the order you've dragged your own permanents into, a client-only layout preference (where a permanent sits has no rules meaning): a list of object ids. `applyBoardOrder` sorts `computeBoardEntries`' tiles by it — a tile ranks by the earliest of its ids, so a token joining a stack keeps the stack's place, and tiles with no id in the list (anything that arrived since the last drag) follow in the board's own order. `moveInRow` gives the list after one drop. Only your own board is reordered; opponents' boards are as laid out.
- **`game/useBoardDrag.ts`** — the drag itself, used by `GameScreen` (not `Table`, which remounts every frame: a bot's move mid-drag would drop the tile) and handed to `Table` as `boardDrag`. Pointer events on `window`, not HTML5 drag-and-drop; a press becomes a drag after 6px, so a click on a tile still acts, and the click a real drag ends with is swallowed. It reads the board from the DOM each time — own rows carry `data-drag-row` (`lands` / `permanents`), tiles `data-obj-ids` — so whichever `Table` is mounted, the drop lands on what's drawn. The dragged tile follows the pointer (`.board-entry.dragging`, a `translate`), the tile nearest the pointer in its row shows a bar on the side it would drop (`.drop-before` / `.drop-after`), Escape cancels, and `body.board-dragging` hides hover cards. Rows never mix. The order is kept per room in `sessionStorage`, so a reload keeps it. The tile art's native image drag is off (`-webkit-user-drag` plus `onDragStart`): it fired `dragstart` and cancelled the pointer stream.
- **`game/passSettings.ts`** — the viewer's priority-passing preferences (`PassSettings`, from `protocol`): *pass to main*, *pass through combat*, *skip mana stops* (on by default; it was a toggle button beside Auto-pass until it moved into Settings → Priority) and the stops flagged on the phase track, per device in `localStorage` (`mtg.pass`) behind `usePassSettings`. The server does the passing, so `GameScreen` sends them (`sendPassSettings` → `set-pass-settings`) whenever they change and whenever the game screen is `playing`. Edited in the **Settings** panel (`ui/MotionControl.tsx` — the top strip's one settings button, a Priority section above the Animations one, listing both kinds of turn's stops with *Clear stops*) and on the `PhaseTrack` pips.
- **`ui/TriggerOrder.tsx`** — the `order-triggers` decision's controls in the decision banner: your simultaneous triggers listed in the order they'll resolve (top first), each with ↑/↓, and *Confirm order*. Asked only with Settings → Priority → *Order my own triggers* on (`PassSettings.orderTriggers`, which the server hands the engine).
- **`ui/SeatMenu.tsx`** — the top strip's "Seat" button: a panel (the animations panel's box) with *Let a bot play for me* / *Take back control* (`bot-takeover`; the button turns amber while a bot has the seat, and `GameScreen` empties the action list then), *Concede…* with an in-panel confirm (`concede`; hidden before the game begins and once you've left it), and *Leave the room*.
- **`game/blockGroups.ts`** — the block bar's model where one tile is several creatures, pure. A click on a folded tile takes a fitting member rather than the first: one of your blockers not yet blocking (`freeBlocker`), or the attacker with the fewest blockers so far (`leastBlocked`) — a stack of attacking tokens is woken into one attacker per token and folds right back into one tile, and before this every blocker landed on the same token. `blockPairs` gives the bar a count row per (your folded tile → the attacker tile it blocks), drawn with `ui/CountStepper.tsx` (− / a number field / + / "of N"), and `setPairCount` adds or frees blockers to hit a count, keeping blocks spread. A click on a tile whose members are all spoken for takes the whole tile back out. The answer is still one attacker per blocker id, checked by the engine's `blockingViolations`. A tile of several attacking tokens carries a shield and how many of them are blocked beside its `×N` pill (`MiniTile`'s `blockedCount`): picked in the bar while choosing, and afterwards the view's `blocked`, which every seat sees and which stays true once the blockers are gone (rule 509.1h). `board.ts`'s `tileKey` leaves `blocked` out, so the stack stays one tile rather than splitting in two. An engine-compacted stack takes part through **`game/stackMembers.ts`**: while a declaration is built, the offer is expanded so each stack is one member id per token (`<id>#<k>`, capped at the engine's 100 — `expandAttackOffer`/`expandBlockOffer`), everything above works on members, the engine's own `blockingViolations`/`attackingViolations` run on the expanded offer, and Confirm folds them back into counted entries (`collapseAttacks`/`collapseBlocks` — a stack that all goes one way is sent without a count, as a whole stack, which a must-attack stack needs). `game.nameOf` resolves a member id to its stack. The **`enter-attacking`** decision (what creatures put onto the battlefield attacking attack — rule 508.4) is answered with the same attack bar: `Table` reshapes its offer into a `declare-attackers` one where every creature must be sent somewhere (`mustAttack`), the banner reads "<card>: choose what each attacks — n of m" with Confirm, and `confirmAttackers` sends the `enter-attacking` action instead. A creature still waiting for its answer is attacking a placeholder in the view, so its tile shows no target until one is picked. A `choose-modes` offer with `about` (myriad's "you may", once per opponent) names that player after the prompt. **`game/attackGroups.ts`** is the attack bar's twin of this: a click on a tile takes a member not yet attacking (`freeAttacker`), and a count row per (your tile → a defender) (`attackPairs`, `setAttackPairCount`).
- **`game/damageAssignment.ts`** — the `assign-combat-damage` bar's model, pure. `groupBlockers` folds the offer's blockers into rows of interchangeable ones (the same in everything the view shows bar summoning sickness, the same lethal, nothing attached), because a token stack blocks as one creature per token and one input each made a twenty-Goblin block taller than the quadrant under it. The rows scroll past a few, and the board takes clicks for the same choice (`clickMembers`: one more to lethal, else spare), each blocker badged with its damage. A click or a row's `+` that needs more than is free takes it from other blockers wherever that kills least: damage past lethal, then damage too little to kill, then the cheapest kills. The answer is still one amount per blocker in offer order, checked by the engine's `damageAssignmentViolations`. Indestructible blockers take lethal (trample needs it) but aren't drawn as dying.
- **`game/usePlayback.ts` + `game/animationBus.ts` + `game/animationSchedule.ts`** — the animation pipeline, Hearthstone-style: **one thing at a time, and nothing may act until it finishes**. `usePlayback(frame, bus, onShown)` queues the server's frames and plays them one at a time — each frame's animations run against the board *before* it (the previous frame's, still on screen), and only when they finish does the new board replace it. It reports `{view, actions, revision, busy}`; `busy` empties `Table`'s action list, and `onShown` (wired to `ackFrame`) is what lets the server hold its bots to the same rule. `scheduleEvents` gives each animate-worthy event its slot (`CARD_STEP_MS` 1800 / `HIT_STEP_MS` 720 / `DEATH_STEP_MS` 420 / `DRAW_STEP_MS` 520 / `TURN_STEP_MS` 1300 / `PHASE_STEP_MS` 700 / `TAP_STEP_MS` 260 — the same numbers `AnimationLayer`'s overlay timeouts and App.css's `animation-duration`s are written to, so nothing outlives its slot), with `MAX_FRAME_MS` (6s) as a backstop: the first paced slot that won't fit ends the frame, and it and everything after it are shown without animating rather than clustered past the ceiling. **A frame has two halves.** `before` plays over the old board (everything above); `after` plays over the new one once it's shown — a tile tilting to tapped or back upright (`permanent-tapped`/`permanent-untapped`, each kind one shared beat) — and the frame isn't acked, nor `busy` cleared, until it finishes. `usePlayback` publishes the `after` cues from a layout effect, once the new board is in the DOM and before it's painted, and `AnimationLayer` starts them in that same task with the wait handed to `.animate({ delay, fill: 'backwards' })`, so the new pose never paints first; a timer there would flash it. **The viewer's settings** (`game/motionPrefs.ts`, set from `ui/MotionControl.tsx`, the "Settings" button in the top strip, per device in `localStorage`): `animScale` (0.5–2) multiplies every slot, every overlay timeout and — as `--anim-scale` on `:root` — every overlay's CSS duration; reduced motion (the setting *or* `prefers-reduced-motion`) sets `:root[data-reduce-motion]`, which every reduced-motion rule in App.css keys on instead of the media query, drops the pure-movement slots (draws, taps), and turns the rest into fades and flashes (a hit flashes the target without the lunge, a played card fades in place). Both halves together are capped at `FRAME_CEILING_MS` (11s) however slow the viewer, under the server's 12s `FRAME_ACK_TIMEOUT_MS`. A hidden tab (`document.visibilityState`) animates nothing and acks each frame at once, so a backgrounded player never holds the bots up. **Only the animations in `PACED` (a card play, a combat hit, a permanent leaving, a tap) hold the game up**; a turn or phase banner is a caption that plays over whatever the board has moved on to, costing nothing — otherwise a land the bot played hangs in the air for the length of an "End Phase" banner before reaching the table. Banners a frame merely passed *through* are dropped too (only the phase it lands in is announced), and `MAX_QUEUED_BANNERS` (3) keeps the banner queue from narrating a turn that finished several turns ago. `AnimationBus` carries cues sideways to `AnimationLayer` (a sibling, since `Table` remounts per frame), and **each cue carries the view it belongs to** — that's what makes a played land draw as it looked when played, rather than as it looks after the bot tapped it. A played card flies out of its owner's `.quadrant-cell` and shrinks back toward it (`flyOrigin` measures the cell off the live DOM and hands the offset to the CSS as `--fly-x`/`--fly-y`), so which side of the table a play came from is readable at a glance. A permanent leaving the board is shown where it stands (`runDeath`, on `permanent-left-battlefield`), by where it went: to a graveyard it drains of colour and sinks, to exile it flares white-blue and dissolves upward, anywhere else it fades; a run of them in one frame goes together on one beat. One returned to hand (`toZone: 'hand'`) flies to its *owner's* hand edge (`runBounce`), the owner read off the old board — every cue carries `prev`, the board the frame started from, for what only it knows. Cards leaving a library from the top (`cards-milled`, `cards-put-into-exile` from a library — each arrival names its `owner`, so a face-down card or one already back in the library still finds its pile) peel off the pile's card (`libraryCardOf`: its cardback, or the revealed top card — never the `data-library-of` box, which stretches to the rail's height) as cardbacks turning over (`runMill`: one after another, `MILL_STAGGER_MS` 150 apart, up to `MAX_PEELED` 8, each a `MILL_STEP_MS` 560 peel; the pile's count, the panel's `data-library-count-of` and the `data-graveyard-count-of` / `data-exile-count-of` it lands in tick in step on the old board, and "−N exiled" / "−N milled" floats off the top of the card): darkening as they drop for a mill, flaring white-blue for an exile. All the cards shown sit on the pile from the start, each put in *under* the one before it so the card peeling is always on top of the ones still waiting (appended in order, a later one covered each peel), and each carries the number the pile's cardback shows while it's the top card, so the count on the pile itself runs down rather than hiding under the peels and jumping. Each peel's keyframe filters are one list of functions: lists that differ animate discretely, and Chromium painted the mill's last filter (`grayscale brightness(0.4)`) from the start, so its waiting cards came out black. **A run of them is one sequence**: the mill slots sharing a beat are merged per library (`libraryPeels` — "each player mills" or Pako's every-library exile peel side by side, one library's cards one after another), the beat lasting the whole run (`peelDurationMs`, laid out by `beatDuration`), and `AnimationLayer` gathers the run's cues by their shared delay into one `runMill`. That's what makes a cascade, a discover or an "exile cards until …" — which the engine announces one card per move — read as one library losing N cards like a mill of N, rather than N cards peeling at once under N "−1"s with the count dropping by one. A discard (`runDiscard`) lifts your own cards out of the fan and greys them away. **Moves** — a change of control, an Aura or Equipment moving to a new host, the monarch's crown — need both boards: the frame's first half takes a hidden snapshot of the old spot the moment it starts (`captureMove`, a zero-cost `capture` slot), and the second half flies it onto the new spot with the real one held hidden until it lands (`runMove`/`runCrown`, `MOVE_STEP_MS` 560 / `CROWN_STEP_MS` 640); without a snapshot (an Aura just cast) it simply arrives. The cast caption names the zone a spell came from when it isn't the hand ("casts from their graveyard"). It goes through `flyGhost`, the one "a card moves from here to there" helper: a copy of the tile in its own `.ghost-flight` box on `<body>`, outside React (the board it came from is about to remount), sized from the tile's layout width rather than its tilted on-screen box, flown with `.animate()` and removed when it lands, while the real tile is hidden. An attacking creature is tapped, so its tile is drawn tilted — the lunge travels on the outer `data-obj-id` box and the tilted face inside just goes along (straightening it up on impact read as the card spinning), clamped to stay inside its quadrant's scroll box, since a tile translated past a scroll box's edge counts toward its scrollable overflow and flashes a scrollbar. Something leaving the stack (`spell-resolved`, `ability-resolved`, `spell-countered`, `spell-fizzled`) gets a paced `before` slot (`STACK_EXIT_MS` 520): `runStackExit` flies a resolving permanent spell's entry to its controller's side, where it's about to appear; everything else ends where it is, since no graveyard or exile is drawn on the table to send it to (the user's call, 2026-09-30): an instant or sorcery flares and lifts away, an ability dissolves, and a countered or fizzled one breaks (a shudder, drained of colour, then it drops and fades) so it can't read as resolved. A trigger going on the stack (`ability-triggered`) lights its source's tile in the `after` half (`TRIGGER_STEP_MS` 480, one shared beat, `runPulse`); a source that's already gone — a dies trigger's — has no tile to light. The `after` half also carries the board's own changes, **grouped by kind** (`AFTER_ORDER`: untap, tap, enter, flip, counter, buff, hurt, pulse — not log order), each run of one kind on one shared beat: a permanent arriving grows into place, and a token also shimmers cyan (`runEnter`, `ENTER_STEP_MS` 420, reading `VisibleObject.isToken`; `runEnters` plays one arrival per tile, so permanents the board folds into one tile — each `.board-entry` lists its members in `data-obj-ids` — grow in once with "×N" floating off, and ones joining a tile already there glow with "+N"); counters glow green (purple-red for −1/−1) and a one-shot pump or granted keyword glows blue, each with its change floating off the tile (`runMark`, `MARK_STEP_MS` 520); a transformed card swings in edge-on (`runFlip`); `life-changed` flashes the player's panel green or red and floats the amount off the life total, and damage to a creature floats "−N" off its tile, with a red flash when it wasn't combat (the strike already showed that) (`runHurt`, `HURT_STEP_MS` 700). Combat damage to a creature is the one event with a slot in each half. The floating words are `floatText`: a `.float-text` element on `<body>`, outside React, gone when it's done. A static buff (a lord, an anthem) changes P/T with no event, so it has no animation. The cast spotlight carries a "Bob casts" / "Bob plays" caption in the caster's seat colour, and by default **rises** from one spot below the middle for everyone (`:root[data-cast-entrance]`, the Animations panel's "Card entrance": rise, the older flight in from the caster's side, or a fade). A `card-drawn` sends a small cardback out of that player's library pile (`libraryCardOf`) and into their hand — the bottom edge of their cell for you, the top edge for a seat across the table (`drawFlight`) — staggered when several land at once and capped per frame, and unpaced like the banners. `MAX_QUEUED_FRAMES` (4) is the catch-up valve for a backgrounded tab whose timers have been throttled. **Replay** (`usePlayback`'s `replay`, the ↺ button in the top strip): the last frame that had events is kept with the board it started from; replaying shows that board, then plays the frame through the same `runFrame` the live queue uses, without acking (the server already has its ack); a frame arriving meanwhile waits its turn. **Sound** (`game/sound.ts`, off unless the Animations panel's "Sound effects" is on): a few short cues synthesised with Web Audio — nothing to license or download — played from the same cues as the animations (`AnimationLayer`'s `soundFor`), each kind at most once per beat. **Arrows** (`ui/ArrowLayer.tsx`, rendered inside `Table`): a full-screen SVG drawn from the board's state rather than from events — the aimed stack entry's targets (the same entry `aim` marks: the top one, or the hovered one), each attacker to what it attacks (a player by their life total), each blocker to what it blocks — measured off the mounted board, again on resize and scroll; one that wasn't on the previous board draws itself in, so the arrows already standing don't redraw every frame.
- **`format.ts`** — `describeEvent`/`describeTarget` (event log text; `describeEvent` takes the room's `seats` and names every player by `playerLabel`, and an attack's defender as a player when it is one, never through the card-name lookup), `playerLabel` (prefers a chosen display name, falls back to a capitalized seat id), `seatClassOf` (stable per-seat colour by turn-order position, not table position), `isDetailOnlyEvent` (the bookkeeping the history hides by default — priority going round, step boundaries, mana entering a pool and the lands tapping to fill it; it's roughly three quarters of the log by volume, so `EventLog` opens concise and offers "Detailed" as a toggle). `EventLog` names each line's objects by what they were publicly known as when that event happened (`publicNameAt` over the view's `publicStints`, falling back to the current view), so a line keeps its card's name after the card is bounced to a hand; and a name there shows the whole card on hover (`LogCardName`, a portalled `CardTile` through `useHoverPopover`, layered over the History popup with `.over-history`). `became-monstrous` and `permanent-exerted` read "X becomes monstrous" / "Alice exerts X". `gift-promised` reads "<player> promises <spell>'s gift to <opponent>". A `restrictions-imposed` with a `duration` (Opportunistic Dragon's "for as long as") doesn't say "this turn"; a `combat-damage-prevention-set` with `partialBy` (Arachnogenesis) says some combat damage is prevented, naming the spell.
- A rejected `dispatch` surfaces as `NetworkGame.error` → a dismissable red banner.
- Styling is `App.css` for the game table (plus a small `.css` beside each standalone page: `lobby/` — two files, `landing.css` and `lobby.css` — `deck-builder/`, `library/`) — legible dark table, no UI library. `index.css` holds the palette tokens and the element-level baseline for `button` and for text `input`s; that input rule is written as `input:where(…)` so it weighs the same as a bare element selector and every per-page class rule still wins. Card art is the only network dependency. Out of scope: undo.

**Standing UI rules** (settled during the board redesign — see `client/BOARD_REDESIGN_PLAN.md`):

- **No fixed px.** Sizing is `clamp()`/`vw`/`vh`, derived from the shared `--card-w` token for anything card-sized — never a new hardcoded number.
- **`--card-w` is viewport-*width*-derived; cap it against height where height is the real constraint.** A card-shaped box inside a container whose height is a viewport fraction (the quadrants are roughly half of it) needs a height cap too, or it fits on a tall monitor and overflows a short one — the two scale independently, and `--card-w` sits at its 150px ceiling all the way down to a 1667px-wide viewport. `--card-w-max` is the ceiling and `--card-w` is what everything reads, so a height-constrained subtree narrows `--card-w` for itself against that ceiling (the command/library rail does exactly this: `.quadrant-body` is a `container-type: size` container and the rail caps at `32cqh`). That cap is set against the **commander slot alone**, because the library pile below it squashes to whatever is left rather than demanding a full card's height — stacking two full slots plus their labels needs about twice a card's height, which at 768px tall didn't fit at all (a 286px rail in a 269px quadrant, the library count clipped off every cell, and that overflow was what made the boards scroll). The rail also stretches to the quadrant's full height, so its seat-coloured divider runs down the whole board. Note that making `.quadrant-body` a size container also makes it the containing block for `position: fixed` descendants (`contain: layout`), which is why the board's hover popover has to leave the subtree entirely rather than just going fixed.
- **What a decision picks from the board is picked on the board**, never from a row of name buttons (two Forests, or two copies of one creature, are two identical buttons): the eligible permanents are highlighted and clicked, players by their panel (`PlayerPanel`'s `targetable`/`selected`). A `choose-from-zone` popup is titled by where the cards go (`zoneChoiceTitle` — `exile` for a graveyard-exile cost), and a choice that puts cards on the top or bottom of a library numbers its picks (`ZoneViewer`'s `selection.ordered`), the order picked being the order they go — an offer's `order` (library ordering: a scry's kept cards, "the rest on the bottom in any order") is titled as an order, the last pick lowest on the bottom; a discard with `orOneOf` takes one land card as an answer. A cast whose offer carries `divide` (Magma Opus) gets a division step once its targets are in (`pendingDivision`, mode `choose-division`): a `CountStepper` per target, at least 1 each, Cast enabled once they total the amount; `finishTargets` is a named function so the step's `resume` can call back into it with the split. Buttons are for what isn't on the board — "Copy nothing", "All mine", Confirm, and "Keep …" when choosing new targets for a copy of a spell (the `choose-targets` action's `current`: the slot's target now, which may no longer be on the board to click; the prompt reads "Choose new targets for the copy of …"). And **every decision but the mulligan asks in the bottom-right `.decision-banner`**; one that picks from the hand (discard, put-on-bottom, a reveal land's reveal) holds the hand tray open under it rather than docking beside the hand, which pulled the strip out of its tray and squashed the board.
- **Mana symbols always go through `<Symbols text={…} />`**, which renders `{…}` tokens as sliced-artwork pips with a CSS fallback. Never hand-roll a coloured circle.
- **Columns that must be equal need `minmax(0, 1fr)`, not `1fr`.** A bare `1fr` is `minmax(auto, 1fr)`, so a track whose content has a wide minimum (a row of input-plus-button, a long unbreakable word, an image) takes more than its share and its neighbour takes less. On the landing page that silently gave the join panel 414px against the start panel's 387 while the footer nav below, having no such pressure, split evenly and lined up with neither. The same footgun is why the seat grid and the board rows are written with `minmax(0, 1fr)` too.
- **A child that names its own width inside a padded box will escape that padding.** `.seat-board` at `min(1180px, 90vw)` inside a `.seat-board-box` at `min(1180px, 94vw)` overran the box's content area on a wide screen and pushed the outer seat panels out through its side padding. Let the box own the width and the child fill it (`width: 100%`).
- **The client's automated tests are a few vitest unit tests for pure logic** (`src/**/*.test.ts`, `npm test -w client`, part of the root `npm test`: the animation scheduler, board order, event wording and the card pool's load progress) **and a Playwright smoke suite** (`client/e2e/`, `npm run test:e2e -w client`): the landing page, a 2- and a 4-player dev room at 1366x768, walking into combat, the library's and deck builder's card-loading bar (`pool-progress.spec.ts`), and exiling from the top of a library (`exile-from-library.spec.ts`: an impulse draw, a cascade and Ulamog's and Pako's exiles played in the EXILE / EXIL4 rooms, with the peels, floating totals and library counts sampled every animation frame, and the order and numbers of Ulamog's eight peels as they wait on bob's pile); `token-stack-counters.spec.ts` casts a token maker under Tribute to the World Tree in `TREES`/`TREE4` and checks the Warriors split off the stack end up one tile with their counters (it reads the engine through the `objects` command, and with `E2E_SHOTS_DIR` set saves screenshots at 1366x768, 1920x1080 and 2560x1440 and a frame sequence). It catches a page that no longer loads or a flow that no longer reaches its decision, not a layout that got worse, so verify any UI change live in the browser, in *both* a 2-player and a 3-4 player room, since the layouts diverge — **and at a short viewport (~768px tall), not just whatever monitor you're on.** Several severe layout bugs (every battlefield tile crushed to its 40px floor, the command/library rail overflowing its quadrant, the hand fan hanging off the bottom of the screen) were invisible at 1440p and obvious at 768p.

## Client commands, in full

- `npm run dev -w client` — Vite dev server with HMR (build `engine`/`server` first); needs a room server reachable at `ws://<host>:4000` (override with `VITE_SERVER_URL`)
- `npm run build -w client` / `lint -w client` / `preview -w client`
- `npm run test:e2e -w client` — the Playwright smoke suite (`client/e2e/`, config `client/playwright.config.ts`, CI `.github/workflows/e2e.yml`). It starts `dev-rooms` and the Vite dev server itself, or reuses them if they're already up, and resets each dev room it uses through the command port. `E2E_WEB_PORT`, `E2E_SERVER_PORT` and `E2E_CONTROL_PORT` move it off 5173/4000/4099 — set any of them and it never reuses a running server (which could be another checkout's), so parallel worktrees each run their own: `E2E_WEB_PORT=5273 E2E_SERVER_PORT=4100 E2E_CONTROL_PORT=4199 npx playwright test`. Build `engine`, `protocol` and `server` first. It runs one test at a time on purpose: a dev-rooms `reset` drops every open connection, not just that room's. `@playwright/test` is pinned to the version whose Chromium the cloud sessions' image ships; elsewhere run `npx playwright install chromium` once.
- To watch it run by hand: start a room server, then `npm run dev -w client` and open two tabs/devices to the same room code.
