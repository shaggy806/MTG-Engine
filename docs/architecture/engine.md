# Engine architecture reference (`engine/src/`)

Reference detail, **not loaded automatically**: read the entry for a file before changing it. The short, always-relevant version is `engine/CLAUDE.md`; this is the per-file detail it points into. Keep it current when a file's shape changes, but it is a map of the code as it is, not a changelog.

## The workspace

- `engine/` — a TypeScript library package, ESM (`"type": "module"`), NodeNext resolution. Emits to `dist/` with declarations; `package.json` `exports`/`main`/`types` point there. No I/O, no UI — a pure state machine driven entirely through `dispatch`.

## What's implemented

Full turn/step loop, casting + targeting + fizzle, a LIFO stack, SBAs, full combat (first
strike/double strike/trample/deathtouch/lifelink/menace, multi-blocker damage assignment as a
player choice, a first-strike priority window, must-be-blocked), activated/triggered abilities
(intervening-ifs, `{X}` costs, loyalty abilities), the full continuous-effects layer pipeline
(1 copy, 2 control, 3 text, 4 type-change, 5 colour, 6 keywords/ability-loss, 7 P/T incl. a CDA
layer), tokens (with a `stackCount` compaction scheme so a self-replicating generator can't blow
up object count — see "Token stacking" below), Auras & Equipment (an Aura put onto the battlefield without being cast chooses what it enchants, rule 303.4f), Commander (command-zone casting
with tax, the command zone as its owner's choice — a state-based action once it's in a graveyard or exile (903.9a), a replacement for a hand or library (903.9b) — commander damage, Partner and every variant of
it — Partner with, Partner—[text]/Friends forever, Choose a Background, Doctor's companion — as a
declarative `CardDefinition.pairing`, the legend rule),
an opt-in simultaneous-mulligan phase, 2-4 player tables (APNAP ordering, per-defender blocker
declarations), a full replacement-effects pipeline (`replacements.ts`), modal/"you may"/targeted-
modal spells, mass effects (wraths, edicts) and tutors/scry/surveil, a rich effect vocabulary
(bounce/exile/mill/discard, fight, counter, control-change, clone, animate, text-change,
count-scaled and trigger-supplied amounts, token-for-target and token-copy effects, conditional
effects, sacrifice costs incl. filtered ones, additional costs & kicker), planeswalkers, alternate
casting zones (flashback, suspend, foretell, escape, disturb, adventure, MDFCs, transforming DFCs
+ Day/Night, Channel from hand, Overload, a conditional free-cast permission, Convoke), extra
turns/combats, cascade/storm/spell-copying, Sagas, station cards (Spacecraft — rule 702.184, 721), the Monarch/Energy/Emblems, damage-prevention
shields, and a color-identity-aware Commander deck validator (`identity.ts`, `deck-validation.ts`).

**Every player decision is a dispatched action**, never a synchronous controller callback. Each of the 22 kinds is a module under `decisions/` owning its whole *answer* half — offer, validator, controller arm, bot candidates — registered in a total table, so adding one fails the build at that table rather than several hundred lines away. Applying stays on `Game`. See `docs/plans/decision-registry.md`. The kinds:
`declare-attackers` / `declare-blockers` / `assign-combat-damage` / `discard` /
`choose-from-zone` / `mulligan` (answered by `mulligan`, then `put-on-bottom`) / `commander-replacement` /
`pay-life-for-untapped` / `reveal-for-untapped` (a reveal land's "you may reveal a [type] card from your hand", asked before it moves by `askEnterChoice`; the offer's `options` are redacted from other seats) / `choose-copy` / `choose-enchant` / `legend-rule` / `order-triggers` (rule 603.3b: a player who orders their own triggers — `GameState.ordersOwnTriggers`, set by `Game.setOrdersOwnTriggers` from the client's setting — is asked by `placePendingTriggers`, before any of the batch goes on the stack, when two or more of theirs wait that aren't all one ability; the answer lists them in resolution order and marks them `ordered`, so `triggerPlacement` keeps it; everyone else, bots included, gets the engine's order: `stackFirst`, then the order they triggered) / `choose-text` / `choose-creature-type` / `choose-modes` / `choose-targets` /
`sacrifice` / `scry` / `proliferate` / `choose-permanents` (a choice made as an effect resolves, no targeting — "untap up to two lands") / `enter-attacking` (what each creature put onto the battlefield attacking attacks — rule 508.4: `Game.putIntoAttack`, reached from a `create-token`'s `attacking` (`EnterAttacking`: `"choose"`, or `{ player, orTheirPlaneswalker? }` for "attacking that player", with the `for-each-player` effect for "for each opponent"), applies rule 506.3a-c — only a creature, under the attacking player, during combat — sets `attacking` to its first option, and queues the question in `pendingEnterAttacking` only where there's more than one; `promptNextEnterAttacking` asks it in the `prepareForPriority` fixpoint. It emits `entered-attacking`, never `attacker-declared`, so no attack trigger sees it (508.3a). A card enters attacking the same way through `look-and-choose`'s and `reveal-until`'s `attacking` (Kaalia, Winota, Raph & Mikey), and a token copy through `create-token-copy`'s `tapped`/`attacking`/`exileAtEndOfCombat` — the last a real delayed trigger at the new `"end-of-combat"` timing. `for-each-player` parks the players still to go when one's effect stops to ask something, and a `may` with `aboutThatPlayer` puts that player on its `choose-modes` offer (`about`): myriad (`cards/helpers.ts`'s `myriad()`) asks once per other opponent) / `cast-now` ("you may cast [a card]" during a resolution, rule 608.2g — Chandra, Acolyte of Flame's one target card; a card picked from a hand, graveyard or looked-at library top — Baral's Expertise, Diviner of Mist, Velomachus Lorehold: the offer is the `cast-spell` offers with `via: "effect"` of every card on offer (`cards`, plus `looked` — library cards shown to that player alone, castable or not), timing ignored, worked out as it's raised on its terms (`free`: "without paying its mana cost", the only way offered — an alternative cost of {0} that kicker may be paid on top of, rule 118.9d; `spell`: a filter the spell must match as it would be cast — its face, its prototype, rule 601.3e — both held to by `whyCannotCastSpell` through `Game.castNowOffer`); the answer carries one built into a `cast-spell`, or `null`, and `Game.applyCastNow` casts it through the ordinary `castSpell`; the client sends a `via: "effect"` cast as this answer, and `decisions/shared/random-cast.ts` builds the fuzzer's; the v1 bot casts the dearest card on offer) alongside the priority actions. `legalActions(player)` enumerates what's
playable right now with per-slot target options; `viewFor(player)` produces a redacted,
self-contained snapshot for one seat.

**Not modeled**, and every other known rules gap, is listed under "Engine rules gaps" in
`BACKLOG.md` — Battles, phasing, dungeons/Initiative/Ring, banding, Companion, replacement
ordering, static dependency ordering and snow sources among them.

**Token stacking** (an engine resource-safety mechanism, not a rule — added after the fuzzer hung
on a self-replicating-token card): `GameObject.stackCount` lets one object stand in for many
fully interchangeable, still-pristine token copies instead of minting one object per copy.
`Game.mintTokenBatch` folds new batches into a matching existing stack; a fresh batch only
originates a stack past `STACK_ORIGIN_THRESHOLD` (8), so ordinary "create two tokens" cards are
untouched. Only tokens with no activated ability and only count-scalable, non-targeted triggered
abilities are ever stacked (`Game.isStackableTokenName`). `Game.splitOneFromStack` peels one off
into an ordinary object the instant anything singles it out (a chosen sacrifice; a target is split
*once, as it's chosen* — `Game.lockInTargets` at cast, activation and trigger placement, after
costs are paid — so every step of a multi-step effect, and any copy of the spell, reaches the same
token); `Game.materializeStack` expands a whole stack into real objects for combat (capped at
`MAX_MATERIALIZED` = 100 — attacking/blocking are optional, so declaring a legal subset is
allowed); `recompactTokens` (end of cleanup) folds tokens back into stacks once nothing tells them apart (`tokenFoldKey`, shared with `findMergeableStack`) and nothing else names them by id (`pinnedTokenIds` — an attachment's host, a delayed trigger's target, a prevention shield's). **Anything that counts permanents counts a stack as every token in it** — `permanentCount` (`state.ts`), behind `countOf`, cost reductions, "controls N or more" conditions, count-scaled P/T and the died-this-turn count; counting objects instead had Krenko, Mob Boss making two Goblins forever. An "each **other** …" count bonus (`grantPtPerCount.excludeSelf`) beside a stacked source still counts the rest of that stack (`othersInOwnStack`), since each token in it is "other" to the rest. Because that makes counts of a million reachable, loops that mint one real thing per unit (individually made tokens, mana units, unscalable trigger copies) stop at `Game.MAX_EFFECT_INSTANCES` (1000), and a draw loop stops at the first empty-library draw. The same holds on the stack: a triggered ability that chooses no targets and isn't count-scalable, fired once per token of a stack (Authority of the Consuls seeing twenty Goblins enter), is queued once with `PendingTrigger.copies` and goes on the stack as one ability object with that `stackCount` — each copy still its own resolution, one at a time with priority between (`removeOneAbilityCopy`), a counter taking one. See
`token-stacking.test.ts`, `token-stack-counts.test.ts`, `token-stack-targets.test.ts` and `random-demo.mjs` for the original repro.

## File map

Tests live in `engine/src/test/*.test.ts` (one directory level deeper than the source they cover,
so relative imports need an extra `../`), except `cards/pool.test.ts`, which stays colocated with
the `cards/pool/`/`cards/tokens/` layout it guards. `server/src/test/*.test.ts` mirrors this. Discovery is
vitest's default glob, which finds them wherever they are; `tsconfig`'s `src/**/*.test.ts`
exclude already covers the subdirectory. `engine/vitest.config.ts` sets two things and
deliberately leaves discovery alone. It raises `testTimeout` to 30s: these are CPU-bound
simulations rather than the async I/O vitest's 5s default is sized for, and several sat close
enough to that limit to pass alone and fail on a busy machine. The two real long-runners
(`bot-plan.test.ts`, `eval-bot.test.ts`) keep their own larger per-file overrides. And it turns
off `isolate`, so each worker imports the card barrel once rather than once per test file,
which took the suite from 4m30s to under a minute. That is safe only while no engine test
mocks, spies, stubs a global or fakes timers. **While authoring, run just the files you touched**
(`npx vitest run cmdr-sokka pool.test` from `engine/`, ~15s), and the whole suite once per batch
before committing. `server` has no config — nothing there runs long, since its pacing tests
drive a fake clock.

- **`state.ts`** — `GameState` is one plain, `structuredClone`-able tree (no class instances, `Map`/`Set`, or functions inside it). Turn-scoped, so it doesn't become a permanent window into a hand), `delayedTriggers` (delayed triggered abilities — rule 603.7; they belong to no permanent, so `detectTriggers`' battlefield scan can't see them: `enterStep` fires the step-keyed ones directly, and a `permanent-left-battlefield` event fires the ones keyed to that permanent leaving (`DelayedLeaveWatch` — earthbend's "when it dies or is exiled, return it", "when that creature dies this turn"; A spell or ability object carries `lastKnownRefs` (`LastKnownRefs`: the battlefield stint — `zoneChangeCount` — of its source and triggering object when it triggered or was activated (and `triggerSpell`, a triggering spell's stint on the stack: gone from it, "that spell's mana value" is its `lastStackManaValue`, X included), the permanent it sacrificed, and the one it tapped for its cost (station's "the tapped creature"); for a trigger, also what its event was aimed at — `recipient`, the permanent (with its stint) or player dealt damage — and `player`, the player the event names: the one dealt damage or controlling the permanent dealt it, or an attack's defending player; and, for a trigger fired by its object *leaving* the battlefield, `triggerObjectAfterLeaving` — where that object went, which is as far as "return it" follows it: moved on again since, it is a new object (rule 400.7) and `ResolutionContext.triggerObjectLost` makes acting on it a no-op, while reading it stays last-known information), which is how a reader tells the departure it means from a later one; a target is known to have been a permanent from `targetZones`. Acting on an object needs it to still be the same one (rule 400.7): a stack object's `targetStints` and `sourceZoneChangeCount` record each target's and its source's `zoneChangeCount` as it went on the stack, and at resolution a target that has changed zones since (`targetsStillMeant`), or is otherwise no longer a legal target, is blanked (`targetLegality`, rule 608.2b): nothing acts on it or finds anything out about it, and the spell or ability doesn't resolve at all only when it chose a target and every one it chose is illegal — an "up to one" that chose none resolves, and each chosen mode of a modal spell applies with its own illegal targets blanked. A changed source is `sourceLost` — while reads of it, and of a target that leaves *during* the resolution (608.2h), go through last-known information. A delayed trigger chose no targets, so only its source's identity is checked (`DelayedTrigger.sourceStint`). `GameState.ceasedTokens` keeps a deleted token's snapshot for the rest of the turn (rule 111.7). Also exports pure selectors, `nameOf` among them — the name an object has, a copy exception's `setName` if one renamed it, which the legend rule and name filters read while the registry stays keyed by `printedCardName`.
- **`game.ts`** — `Game` owns the single mutable `GameState` and is the **only** writer. `dispatch(action)` handles every `Action` variant (see `actions.ts`). A 3-4 player table queues attacked defenders in `pendingBlockerDeclarations`, drained one `declare-blockers` at a time. There is no blocker-ordering step (Foundations removed damage assignment order): after blocks the active player simply gets priority. `legalDefenders(attacker)` returns every non-eliminated opponent plus their planeswalkers. `advance()`/`advanceUntil(pred)` run `tick()`. `emit()` appends an event and runs `detectTriggers` (matches against every battlefield permanent's `triggered` list — and a command-zone card's Eminence abilities, and a graveyard card's `fromGraveyard` ones, rule 113.6k, found through the per-name `graveyardTriggerNames` cache — honouring intervening-ifs via `interveningIfMet`). `prepareForPriority(player)` is the pre-priority fixpoint loop: run SBAs (not while a resolution is suspended), drain pending mass-effect/sacrifice queues, resume a suspended resolution, place pending triggers (APNAP order) — repeat until stable, then hand off priority (to `awaiting.player` if a decision got raised mid-loop). Mana is **auto-paid**: `manaSources` reports each permanent's `{T}: Add` abilities (plus an untapped once-a-turn one — Vivi Ornitier's `{0}: Add`) as `ManaOption` alternatives — a land's intrinsic ones too (rule 305.6): `effectiveActivated` lists printed abilities, then one for each basic land type the land has that no printed stand-in covers (`extraIntrinsicManaColors` — a type an effect gave it), then granted ones, and a typed land's printed `{T}: Add` stand-in lapses with its type (`inactiveStandIn`, rule 305.7), sizing a live `amount` (a power, a turn stat) against the board as it stands and compressing "X in any combination of" into one `anyColorOf` option rather than X+1 splits → `Game.payMana` hands a `ManaPlanningView` to `mana-payment.ts`'s `planPayment` (= `resolveHybridCost` → `planManaPayment`, both pure) → `executePayment` (taps/sacrifices sources, spends the pool, pays life); `castingCostOf` folds in commander tax and `costModification` statics (a `commanderTaxAsLife` card's tax is life instead, paid beside the mana and reserved out of the planning view's `life`). `payMana`'s last two arguments are the difference between a preference and a rule: `avoid` puts a source last (don't casually tap a permanent for its own ability's mana cost), while `exclude` removes it outright — an ability whose cost includes `{T}` taps its source to pay that, so it can't be tapped for mana as well (rule 602.2a). Without the latter, Mind Stone's `{1}, {T}, Sacrifice` funded its own `{1}` off an otherwise empty board. Ability objects are minted onto the stack by `mintAbilityObject` and deleted from `state.objects` on resolution. An ability that was *granted* (a `grantsActivated`/`grantsTriggered` static, or a modifier's `grantsTriggered`/`grantsActivated` — a one-shot grant, or a copy exception's "and it has …") carries a `GrantedAbilityRef` from the moment it's activated or triggers, and `stackAbilityOf` resolves from that rather than by index into its source's current abilities — the grant is often gone by then (an Aura that fell off with the creature it enchanted), and rule 113.7a says the ability doesn't care. The same rule is why a permanent that has lost all its abilities still *lists* its printed triggered abilities (`TriggeredEntry.lost` — they don't trigger, but an index into the list still names the one that triggered before the loss), and has whatever was granted it since the loss, triggered, activated and mana abilities alike (rule 613.7). All P/T reads go through `computeCharacteristics`. Combat damage runs through `combatDamageStep` → `runCombatDamageSubPass` (first-strike sub-pass, then regular, each followed by SBAs + a priority window when relevant; who deals damage in the regular one is fixed by who had first or double strike as the first began — `CombatDamageState.firstStepStrikers`, rule 510.4 — plus whoever has double strike by then) → `dealCombatDamage`, which takes a player-chosen `assign-combat-damage` split when one exists, else auto-assigns the standard split (`standardAssignment`); `dealDamage` runs deathtouch/lifelink, prevention shields, and Fog uniformly (for combat and burn alike) and returns the amount actually dealt. Damage dealt all at once (a combat damage sub-pass, `damage-all`, "each opponent") runs inside `withDamageBatch`, which settles it as one event: lifelink gains once per *source* (rule 119.9 — so "whenever you gain life" counts sources, not recipients), and a `dealt-damage` (enrage) trigger fires once per permanent for the total; a `deals-damage` trigger (the source's side) is not batched — it fires once per recipient, as rule 603.2 reads "deals damage to a permanent or player". `createTokens`/`addCounter`/`entersBattlefieldReplacement` all honour replacement multipliers (Doubling Season). `moveObject` is the single zone-transition function: it applies enters-battlefield replacements — the entering permanent's own, then every other permanent's `others-enter-battlefield` (Giada's counters, Thalia's "enter tapped", The Wandering Minstrel's "enter untapped", which beats every enters-tapped), with the moving effect's own "tapped", "under your control", "it's an enchantment" and "it's a Phyrexian in addition" (`setTypes`, `addSubtypes` — the Enduring cycle, Portal to Phyrexia) passed in as `EnterOptions` rather than applied after the move, so a replacement can see and override them (and the permanent is its entering controller's for the whole entry, so the triggers its counters set off see it as theirs; the control effect that keeps it there is still the caller's to create) — defers a commander's move to a hand or library behind a `commander-replacement` decision (903.9b), from the battlefield or, to a hand, from the stack, a graveyard or exile (a spell Remand counters into its owner's hand), and records one put into a graveyard or exile (from anywhere) for the next state-based check to offer the command zone (903.9a) — and **returns whether it moved** — `false` for that deferral, and for a card that can't enter the battlefield, which stays where it was (an instant or sorcery, rule 400.4a; an Aura with nothing to enchant, 303.4g); a caller that only announces a completed move reads that, never `awaiting`, which may be someone else's decision — redirects a graveyard-bound card to exile when a replacement or `castVia` says to, resets face/copy/modifier state on any move to a hidden zone, and emits `permanent-left-battlefield`/`permanent-destroyed` as appropriate. `runStateBasedActions` recomputes control (layer 2, every control effect in timestamp order), puts an Aura attached to nothing, or to something it can't enchant, into its owner's graveyard and unattaches an Equipment from anything it can't equip (704.5m–n), deletes tokens that have left the battlefield (only those `moveObject` recorded leaving, `GameState.tokensLeftBattlefield` — it used to walk every object in the game, library cards included, each pass), removes +1/+1 and -1/-1 counters in pairs (704.5q — not from a permanent the same check kills, which leaves with both), enforces commander-damage loss and the legend rule — the player's choice of which to keep, asked (`legend-rule`, one group at a time, APNAP) before anything moves, the answers waiting in `legendRuleKeeps` so every move the check found still happens at once — offers a commander that's arrived in a graveyard or exile the command zone (903.9a — so it has died, and every "dies" trigger saw it, before its owner is asked), and sacrifices 0-loyalty planeswalkers / completed Sagas — every graveyard-bound SBA is collected first (`stateBasedGraveyardMoves`) and performed at once (rule 704.3), so a creature that dies only because its lord did waits for the next check. `concede(player)` (rule 104.3a; `whyCannotConcede` refuses before the game begins and while they owe a decision, which the server answers first) makes them lose the same way and passes on priority they held. A player who loses **leaves the game at once** (`leaveGame`, rule 800.4a): control effects they held end and what they own leaves with them — it stays where it is to be seen but is out of the game (`inGame`, which state-based actions skip; `matchesFilter`, which finds nothing a departed player owns; `moveObject`, which won't move it) — their spells and abilities leave the stack, what they control but don't own is exiled (a spell cast from someone else's cards, a permanent put onto the battlefield under their control — `ControlEffect.entered`, default control rather than an effect), their pending and delayed triggers are dropped, the monarch passes on (725.4), and what their permanents exiled "until" they leave comes back (610.3 — `returnExiledCards`, which parks an `exiled-return` `PendingEntry` while a returning card makes its "as this enters" choice). **Simultaneous leaves are one event** (rule 603.10a): the SBA sweep, a wrath (`drainPendingDestruction`), an edict's victims (every player chooses first, then all are sacrificed) and a return-all each run inside `withLeaveBatch`, and `detectTriggers` shows each leave event to the batch's already-moved permanents too (`lookBackSources`, leaves-the-battlefield triggers only) — so every one of them sees every other one leave, whatever order they moved in. A commander whose move to a hand or library the batch deferred for 903.9b carries the list as `leftWith` and completes its move inside the same batch. **Cards leaving graveyards are batched the same way** (rule 603.10a again): `moveObject` notes each card that leaves a graveyard, with a snapshot of it as it was there, and `withGraveyardLeaveBatch` — around a whole graveyard exiled, a return-all, the moves a `choose-from-zone` answer makes, an escape cost, a `simultaneous` sequence (`ctx.simultaneously`) — announces them as one `cards-left-graveyard` event once they have all moved; outside a batch each card is its own event. A batched `leaves-graveyard` trigger ("whenever one or more cards leave your graveyard") fires once per such event, matching its filter against those snapshots. **Simultaneous entries are one event too** (rule 614.12): a token batch, a return-all, a flicker's return, a tutor's finds and an O-Ring's exiles coming back each run inside `withEnterBatch`, whose members neither apply their `others-enter-battlefield` replacements to one another nor count as "already" on the battlefield for one another — a check land's `tappedUnless` included (`ConditionOptions.notYetHere`). **"As this enters" choices are asked before the move** (rule 614.12 — `askEnterChoice`: a Clone's copy, a chosen creature type or word): a permanent spell resolving (`enterPermanentSpell`), a land played, a reanimation, a blink or its delayed return, an O-Ring's return and a tutor to the battlefield each ask first and wait — a spell or land play (or a `choose-from-zone` answer) parks a `PendingEntry` in `suspendedResolutions`, an effect step parks itself and runs again — and `moveObject` applies the answer (`GameObject.enterChoice`) as the permanent enters, before its replacements and triggers look at it. **A permanent that left is read as it last existed there** (rules 603.10a, 608.2h): `moveObject` snapshots it (`takeLastKnown` → `GameObject.lastKnown`) before resetting it, and a batch's callers snapshot all of their victims up front (`snapshotLeaving`, kept on the batch and used by `moveObject` in place of its own), so the second victim of a wrath is read before its lord left; a commander whose 903.9b move was deferred keeps the snapshot of the moment it was asked. `detectTriggers` matches a departed subject or look-back source through it — `matchesWho`/`FilterContext.lastKnown` (controller, types, subtypes, counters, keywords, power), no triggered abilities if it had lost them, and the abilities it had then (`departedTriggeredEntries`: a copied card's printed ones plus its granted ones by `GrantedAbilityRef`), recording `LastKnownRefs` on the trigger. A resolving spell or ability reads a departed source, triggering object, sacrificed permanent (by stint — `lastKnownOfStint`) or target (by `targetZones` — `lastKnownOfTarget`) through the snapshot in `makeResolutionContext`: `powerOf`/`toughnessOf`/`manaValueOf`/`manaSpentOf`/`controllerOf`/`cardTypesOf`, the `target`/`trigger-object`/`sacrificed`/`source` conditions, "trigger-controller" scopes, and the damage a departed source deals (`dealDamage`'s `sourceLastKnown`: its colours for protection, lifelink, deathtouch and controller). `choose-modes` and `unless` continuations carry the refs and target zones along, and a `choose-modes` carries `sourceLost` too, so the "you may" of an ability whose source has become a new object finds no "~" (rule 400.7). `castSpell`/`activateAbility`/`whyCannot*` thread through `via` (alt cast zone) — a card with no mana cost can't be cast for it (rule 118.6), only for an alternative cost or free — `face` (multi-face cards), `xValue`, `kicked`, `sacrifice` (additional/ability costs), and evaluate `costModification`/protection/`StaticAbility.condition` gates, and the prohibitions (`whyProhibitedFromCasting` — split second, a `prohibit` effect's `turnProhibitions`, a `prohibits` static, a card's own `castOnlyIf` — and `abilitiesProhibited`, which `manaSources` honours too, so a barred mana ability can't pay for anything). **Ward** (rule 702.21) is a real triggered ability (`cards/helpers.ts`'s `ward(cost)`: a `becomes-target` trigger with a `{ kind: "ward", cost: WardCost }` effect), so it goes on the stack above the targeting spell or ability. Every spell, activated ability, copy *and triggered ability* announces the objects it targets as it goes on the stack (`announceTargeted` → `object-targeted`, whose `stackObject` is the spell or ability object; a trigger announces from `mintTriggerAbility`, skipping event-filled `autoTargetSlots`), and a `becomes-target` trigger records that as `PendingTrigger`/`GameObject.targetedBy`. `beginWard` asks *that* player to pay the one compound cost as a `choose-modes` decision carrying `ward` (mana on the decision's `cost`, life/sacrifice/discard as the mode's effect, a `counter` of the targeting object as `onDecline`), offered only when all of it is affordable; `counterObject` removes a countered *ability* from the stack. `castCardWithoutPaying` is the shared free-cast core for suspend/cascade (a resolving effect's "you may cast it without paying its mana cost" is a free `cast-now` instead, cast through `castSpell` — see `decisions/`; cascade asks first — its `cascade` effect reveals, then raises a `may`-style `choose-modes` whose two answers are `cascade` effects carrying a `finish`, rule 702.85a; `effect-worth` prices casting at a card, so a bot takes it); it still pays any cost increase (Thalia, a Hinata per-target {1} — rule 601.2f) once targets are chosen, and a spell whose increase can't be paid isn't cast (a cascaded one goes to the bottom, 702.85e; a suspended one stays exiled). A triggered ability, or a suspended or cascaded spell, needing a real target choice parks in `pendingTargetedTrigger`/`pendingTargetedCast` and raises a `choose-targets` decision rather than picking synchronously. A copy of a spell whose effect lets its controller choose new targets (`copy-spell`'s `newTargets`, rule 707.10c) parks in `pendingCopyTargets` and raises the same decision with `current` — each slot's target now, kept even if it's no longer legal, and offered first; the copy sits on the stack meanwhile and its targets are announced once answered (`retargetCopy`). Copies made while another is being asked (storm's several — `stormCopy` copies from `lastOnStack` too, so a countered spell still storms) wait in `copyTargetsQueue`, asked one at a time in the `prepareForPriority` fixpoint (`promptNextCopyTargets`). A `discard` with `unlessOne` (Compulsive Research's "unless they discard a land card") raises the `discard` decision with `orOneOf`, any one of which is a whole answer; the `choose-from-zone` legal action carries its `destination` (and `split` for Cultivate), so a client can say where the cards go — `library-top` is the order picked. An attack tax (`attackTax` statics — Ghostly Prison) is a cost to attack, locked in before the attackers tap and paid after (rule 508.1f–j): `attackTaxPerCreature`/`attackTaxTotal`/`attackTaxPayment` (attackers that tap withheld from the payer), validated in the `attackers` decision through `DecisionReadCtx.whyCannotPayAttackTax`, and offered as `AttackOffer.attackTax` (`perCreature`, a sure-to-pay `budget` from `attackTaxBudget`) that `combat/attacking.ts`'s `withinAttackTax` trims a driver's declaration to; a creature that could attack only a taxing player isn't in `mustAttack` (508.1d). **Split cards** (rule 709, `CardDefinition.split`): `faces` is `[whole, left, right]`, face 0 the combined card off the stack (709.4) and never cast — `castableFaces` offers each half alone (709.3), and leaving the stack resets the face to the whole card. **Divided damage** (rule 601.2d): a card's `divided: { total, slot }` makes the cast carry a `division` (validated by `spellDivision`, an even split when absent), kept on the spell (`GameObject.division`, in `SpellSnapshot` so a copy keeps it) and dealt by `damage-divided`; an `any-number` group's `max` caps its members (`slotOptions`, `invalidTargetReason`). The cast offer carries `divide` for a client. **Copying a spell** (`copySpellFrom`) starts from a `SpellSnapshot` — its characteristics and every cast choice: modes, targets, X, kicker/overload/evoke paid — taken off the live spell, or off `GameObject.lastOnStack`, which `moveObject` and `forgetSpellTargets` record as a spell leaves the stack, so a copy trigger still copies a spell countered in response (Shiko and Narset, Unified). A copy of a permanent spell becomes a token as it resolves (608.3f), not "created".
- **`actions.ts`** — the `Action` union: the priority actions, plus `declare-attackers`/`declare-blockers`/`assign-combat-damage`/`discard`/`choose-from-zone`/`mulligan`/`put-on-bottom`/`commander-replacement`/`choose-copy`/`choose-enchant`/`legend-rule`/`choose-text`/`choose-modes`/`choose-targets`/`cast-now`/`sacrifice`/`scry`/`proliferate`/`suspend`/`foretell`/`cycle`. `cast-spell` carries optional `xValue`, `via?: CastVia` (`"flashback"|"escape"|"foretell"|"disturb"|"adventure"|"suspend"|"cascade"|"impulse"|"warp"|"effect"|"graveyard-permission"` — `"warp"` is the hand cast for a warp cost, rule 702.185, whose permanent is exiled at the next end step by a delayed trigger and castable again from exile through an impulse permission gated by `fromTurn`), `face?`, `modes?`, `kicked?`, `prototype?` (rule 718: cast with the prototype cost, colors and size — a copiable `PtModifier` with `setManaCost`/`setColors`/`setPt`, applied while its legality and cost are worked out (`withPrototype`/`applyPrototype`), put on as it moves to the stack, kept onto the battlefield by `moveObject`, and copied onto a copy of the spell), `overload?`, `evoke?` + `evokeCost?` (rule 702.74: cast for an evoke cost, printed or granted — `grantsEvokeToSpells` — one offer per distinct evoke cost; the permanent gets its sacrifice trigger as it enters, placed ahead of its controller's other triggers of the moment by `TriggeredAbility.stackFirst` so its enters abilities resolve first), `free?` (a `CardDefinition.freeCastIf` permission), `convoke?: ConvokePayment[]` (the creatures that convoke, a token stack named once per token; what each `pays` is optional and worked out by the engine when omitted; convoke pays for `{X}` too, and `convokeProofFor(offer, x)` fits an offer's proved payment to the X a driver picked), `sacrifice?` (an additional cost), `tap?` (what an alternative cost's "tap N untapped …" taps — Sephara), `escapeExile?` (which other graveyard cards an escape cast exiles, from the offer's `escapeExile: {count, choices}`; omitted, the oldest); `cast-spell` and `play-land` carry `graveyardGrant?: {source, asType?}` — which graveyard permission a card played from a graveyard spends (a grantor permanent, or the card itself for a one-shot "you may cast that card this turn"; Muldrotha's per-type `asType`), one `LegalAction` variant per permission that applies; `activate-ability` carries optional `sacrifice`, `xValue`, `tap` (an `AbilityCost.tapOthers` choice). `LegalAction` mirrors this — a castable/activatable option carries whatever context the client needs to build the action (`xCost: {maxX, maxXByTargetCount?}`, `targetCount: {min, max, copies?}` — the distinct-target counts (a token stack named in several slots counting once per slot, up to its size) a "for each target" cost (Hinata, or the spell's own `costPerExtraTarget` — Fireball) is affordable at, which drivers fit their picks into with `fitTargetCount`/`fitCastTargets`; with an `{X}` the two trade off, `maxXByTargetCount` holding the largest X at each count (`maxXForTargets` for a driver that picks targets first, `targetCountAtX` for one that picks X first) —, `sacrifice: {choices}`, `tapCost: {count, choices, copies?}`, `castModal {...}`, `mustBlock`, etc.), and a card playable multiple ways (kicked/unkicked, multiple faces, via different alt-zones) is enumerated once per variant. Kept out of `game.ts` to avoid a cycle with `controller.ts`.
- **`view.ts`** — `viewFor(state, registry, viewer, opts)` / `game.viewFor(player)` → a `PlayerView`: your hand in full, other hands as counts, libraries as counts (except what a pending `choose-from-zone`/`scry`, or a `cast-now`'s `looked`, reveals to that player — and a pending `cast-now`'s `cards`/`offers` are emptied for every other viewer, since they can name a hand or library), every exiled id's owner in `zones.exileOwners` (a face-down card has no object for most seats, but whose it is stays public, rule 406.3), battlefield/stack/graveyards public with **computed** characteristics baked in (power/toughness/keywords/types/subtypes/colors/restrictions/loyalty/`isToken`/`attachedTo`/`isCommander`/`xValue`/`copyOf`/`suspended`/`foretold`/`faceName`+`faces`/`stackCount`/`art`/`regenerationShields`), so a client needs neither the registry nor the layer system. `subtypes` is the type line's: without `subtypes.ts`'s every-type markers. A foretold card in exile is redacted for everyone but its owner, and a card exiled face down by an effect (`GameObject.exiledFaceDown`, rule 406.3) for everyone but the players it names. The view also carries `publicStints` (`GameState.publicStints`, kept by `Game.moveObject`'s `trackPublicity`): when each object's identity was known to every player, from entering a public zone or being revealed until it moves on from a hidden zone, its library is shuffled or it's turned face down (foretold, or exiled face down — a stint the move itself opened is dropped, not closed, so the card is never named). The history reads it through `publicNameAt` to name old lines, never the current view's hidden objects. **`state.revealedThisTurn` is the one path that puts a card in someone else's hidden zone into your view** — a reveal is to *all* players (rule 701.16), so those ids go into every seat's `objects`; a library is still never listed as a zone, so a revealed card's identity is public while its position stays hidden. A `VisibleObject` also carries its designations: `goadedBy` (`goad.ts`'s `goadersOf`) and `suspected`; and a permanent carries `holding`, the exile ids linked to it (`exileHoldings`: an O-Ring's `exiledBy`, or an impulse permission's source while it's the same object — Theater of Horrors, Maralen), face-down ones included by id only, and `chosen`, what was chosen as it entered (`chosenOnEnter` or `chosenCreatureType` — Frostcliff Siege's "Temur", Heraldic Banner's `"U"`). `PlayerView` also carries `startingPlayer`, `dayNight`, `monarch`, `emblems` (each with its owner, text and `source` — the name of the card that created it, `EmblemState.sourceName`), and `decisionSource` (the `{object, cardName}` behind `awaiting`, or `null` — a decision variant's own `source` wins over `state.decisionSource`, and `cardName` stands alone because the object can be somewhere the deciding player can't see — a spell that exiled itself, a face-down foretold card — though a spell asking as it resolves is still on the stack, rule 608.2n); `PublicPlayerInfo` carries `maxLandsThisTurn` (extra land drops included — `ViewOptions.maxLands`, supplied by `Game.viewFor`, since only `Game` can evaluate the statics), `energy`, `counters`, `commanderCastCounts`, and `commanderDamageTaken` as a list of `CommanderDamage` (`commander` id, `name`, `owner`, `art`, `amount`) — named even when that commander isn't visible to the viewer. `COMMANDER_DAMAGE_LETHAL` (21) is exported alongside. `art` is where a deck's **chosen printing** surfaces: `DeckList.printings` (card name → Scryfall card id) is stored at setup on `PlayerState.printings` and substituted here for the card's *owner*'s objects, so every device at the table draws the card its owner brought. Player-level, not per-`GameObject`, because it's a fact about the physical cards someone owns rather than any game state — so it survives zone changes and control changes for free. Keyed by the card's **front face** (`def.faces[0]`), which is the name a decklist uses, so a transformed permanent keeps wearing it. `faceIsBack` rides alongside: a card id names the whole card and serves its front image, so a client has to ask Scryfall for `face=back`, and only the registry can tell a real second image from an adventure's spell half (same two-entry `faces` shape, one printing).

- **`cards.ts`** — a thin re-export barrel; the real content lives in `cards/`: `cards/define.ts` (`CardDefinition`/`CardDraft` + `defineCard`), `cards/helpers.ts` (`basicLand`, `manaTapAbility`, `addManaAbility`, land-toolkit builders — `entersTappedStatic`, `checkLandStatic`, `painLand`, `fetchLand`, `sacrificeFetchLand`, `shockLand`), `cards/registry.ts` (`CardRegistry`, `createDefaultRegistry`), one file per card under `cards/pool/` (real cards + basics) and `cards/tokens/`. `CardDefinition` is **declarative** (`effect`, `keywords`, `activated`, `triggered`, `static: StaticAbility[]`, `supertypes`, `loyalty`, `chapters` for a Saga, `faces` for a multi-face card, `transform`/`disturb`/`adventure`/`suspend`/`foretell`/`flashback`/`escape`/`cycling`/`castModal`/`kicker`/`overload`/`freeCastIf`/`convoke`/`selfCostReduction`/`additionalCost`/`cantBeCountered`/`art`) with an imperative `resolve(ctx)` hatch. `cards/generated.ts` is the codegen'd barrel (`npm run gen:cards -w engine`, also a `prebuild`/`pretypecheck` step, checked in) — **to add a card, drop a new file in `cards/pool/` and run `gen:cards`**. It emits `POOL_CARDS` and `TOKEN_CARDS` as well as the combined `BUILTIN_CARDS`, because the directory is the only record that a definition is a *token* — nothing on `CardDefinition` says so. `cards/classify.ts` reads them back as `isTokenCard` (rule 111.1 — a token isn't a card), `isCardFront` (rule 712.3 — a DFC is one card, deck-listed under its front face) and `isDeckableCard` for the two together; `deck-validation.ts`, `card-replacer.ts`, the library page and the deck builder's pool all filter on these rather than guessing from the name. `cards/pool.test.ts` fails if a card isn't wired into `generated.ts`, or if the pool/tokens split drifts. The same run writes the pool a second way, for the web client: 32 shard modules under `cards/shards/`, each card in the shard its name hashes to (`cards/card-shards.ts`: `cardShardOf`, and `loadCardShard`, whose literal `import()` per shard is what gives each shard its own file in a bundle), plus `cards/generated-index.ts`, what a page can know without loading any card: `TOKEN_NAMES` (what `isTokenCard` reads, so classifying a definition never imports every token) and `PINNED_ART` (a card's pinned printing, for drawing a commander from its name alone). The codegen reads each card's name and art from its source — `defineCard({ name, … })`, or a helper whose first argument is the name — and `pool.test.ts` checks both, and every card's shard, against the real definitions. The engine's `package.json` declares **`"sideEffects": false`**, which is what lets a bundler leave out every card module a page never reaches: each card file's `defineCard(…)` call would otherwise count as an import-time side effect, and the whole pool would ship with any page that touched the engine's barrel. It holds because no engine module does anything at import time but define things; keep it so. **`cards/AUTHORING.md` is the hand-authoring guide** — every field, the effect/target/ability/static vocab, worked examples, current limitations; read it before authoring a new card. `Game.debugSpawn(name, player, zone)` is the sanctioned white-box "put a card straight into a zone" helper, going through the real `moveObject`.
- **`cards/edhrec-rank.ts`** — `EDHREC_RANK` / `edhrecRankOf(name)`: how popular each pool card is in Commander (1 = most played). **Generated** by `npm run gen:edhrec-rank -w engine` from Scryfall's `edhrec_rank`, batched 75 names to a request, and checked in so nothing needs the network at runtime. A card absent from the table is *unranked* rather than unpopular — basics always are — and consumers sort those last. Two consumers: the library's `Popularity` sort, and the authoring backlog's ordering (`top-commander-cards.txt` is a frozen snapshot of the same data).

- **`deck-validation.ts`** — `validateCommanderDeck({commanders, cards, size}, registry)` → `{legal, violations, identity}`: singleton (basics exempt), colour identity, deck size, a commander that may command (`canCommandAlone`, rule 903.3: a legendary creature, Vehicle, or Spacecraft with P/T, or a card whose declarative `canBeCommander` says it can be your commander — a planeswalker without it can't), a legal pair for two commanders (`pairingProblem`/`canPairCommanders` over each card's declarative `pairing` — never its rules text — and also what the deck builder's commander toggle asks: two plain Partners, two "Partner with"s naming each other, two same-text "Partner—[text]"s, "Choose a Background" + a legendary Background enchantment, "Doctor's companion" + a lone Time Lord Doctor; a Background is a commander *only* as that second half, and `canCommandAlone`/`isBackground` are exported for callers that pick commanders), and "is actually a card" (`cards/classify.ts` — a token or a DFC back face is a registered definition and would otherwise pass every other check). Only checks *implemented* cards. Lives in the engine (it originated in `server/`) because it's pure synchronous logic over `CardRegistry` data — the client's deck builder needs the same rules with no network round-trip.
- **`sample-decks.ts`** — `SAMPLE_DECKS`: the five Tarkir: Dragonstorm Commander decks (`TDC`; the 2022 Starter Commander Decks until 2026-09-30), each a legal 100-card Commander deck. Each keeps its `printed` list verbatim plus a `substitutions` table (`{original, substitute, reason}`) swapping in reviewed stand-ins for cards the engine doesn't implement yet; `cards` is the result. To revert a substitution once its card is authored, delete its entry — `test/sample-decks.test.ts` fails for any substitution whose original is now implemented, and checks legality. The record of every swap and why is `docs/plans/precon-decks.md`. One source of truth for two consumers: `server/src/decks.ts`'s `SEATS` (a seat's fallback deck — the first four, one per seat) and the client deck builder's "starter decks" (all five).
- **`card-replacer.ts`** — `suggestReplacements(target, context)` → up to three implemented `BUILTIN_CARDS` stand-ins for an unimplemented card, best first, each with a `confidence` (`high`/`medium`/`low`) and the `sharedTags` behind it. `assignReplacements` does it for a whole deck at once, and is what the import uses: the Hungarian algorithm over every missing card's candidates, so a stand-in two cards want goes to the one with the most to lose. Pure and synchronous. `target` is what Scryfall says about the missing card (name, mana cost, type line, power/toughness, keywords); `context` is the destination deck — `identity` (only cards inside it), `exclude` (never a card the deck already has, so singleton holds), `forCommander` (only legendary creatures/planeswalkers) — plus an optional `OracleTagIndex`. **Role matching runs on Scryfall Tagger oracle tags**: `createOracleTagIndex(data)` wraps the server's generated index, and similarity is an IDF-weighted cosine over the tags two cards share (a rare shared tag says more than a common one). A candidate must share a primary type with the target (instant/sorcery count as one) unless the tags say they do the same job; a land only replaces a land. Score = tags, then type, a steep mana-value closeness (so a finisher isn't replaced by a two-drop that shares a mechanic) and, for creatures, body (P/T and combat keywords). Without tags only the latter count and confidence is always `low`. The engine does no I/O; the index lives server-side. Design record and measured results: `docs/plans/card-replacer.md`. Also exports `parseTypeLine`.
- **`filter.ts`** — `CardFilter` + `matchesFilter(state, registry, id, filter, { you })`: a pure predicate over an object + its *computed* characteristics (`type`/`types`/`notTypes`/`subtype`/`subtypes`/`supertype`/`name`/`colors`/`notColors`/`colorless`/`manaValue`/`power`/`toughness`/`controlledBy`/`ownedBy`/`keyword`/`tapped`/`token`/`enteredThisTurn`/`attackedThisTurn`/`damagedThisTurnBy`/`excessDamageThisTurn`/`dealtDamageToCreatureThisTurn` (a `DamageHistory` `dealDamage` keeps on `GameObject.damageThisTurn` as it damages a permanent: each source as it was then, and whether any of it was excess, rule 120.4a)/`goaded`/`suspected`/`putIntoGraveyardFromLibraryThisTurn` — the last read off `GameObject.putIntoGraveyardFromLibraryOnTurn`, which `moveObject` sets on a library-to-graveyard move and clears on any other, ANDed). Off the battlefield it degrades to printed values — unless the caller asks for last-known information: `FilterContext.lastKnown` (a trigger filter matched as a permanent leaves — its `GameObject.lastKnown`, or `GameState.ceasedTokens` for a deleted token) or `FilterContext.snapshot` (a `LastKnownInfo` the caller picked out), and then every clause reads the snapshot through the same code path. `sharesCardTypeWith: "sacrificed" | "trigger-object"` is bound to a plain `typesAnyOf` by `bindDynamicCompares` (the sacrificed permanent's types as it last existed, or the trigger object's — Baral and Kari Zev's "shares a card type with it") and matches nothing unbound. Clauses about a card's own properties: `basePower`/`baseToughness` (after layer 7b — `Characteristics.basePower`), `hasManaAbility` and `hasAbilities` (`characteristics.ts`'s `hasManaAbility`/`hasAnyAbility`, granted abilities included), `xInManaCost`/`coloredManaSymbols` (the up face's own mana cost — a transformed back face has none), `cardTypeCount` and `nameDiffersFromEach` (an inner filter over the battlefield, rule 201.2c). Subtype clauses ask `subtypes.ts`'s `hasSubtype`, so a changeling matches every creature type, and `ofChosenType` reads the chosen creature type of the `FilterContext.source` (static scopes and trigger filters pass one). The shared "which objects" vocabulary for mass effects, tutors, and filtered triggers — `ZoneChoiceFilter` is an alias. A numeric clause's `n` may be a `DynamicOperand`: `{ own }` (the matched object's own power/toughness/mana value) or `{ amount: EffectAmount }`, answered by `FilterContext.amount` — `Game.filterAmounts` supplies it to target filters (via `TargetSource.amount`, rechecked on resolution) and trigger filters, and `applyEffectSpec` binds an effect's filters to plain numbers as that effect applies (`bindDynamicCompares`); with nothing to answer it, the comparison fails closed. Answers type/subtype/colour clauses lazily via `effectiveTypes`/`effectiveSubtypes` (layer 4 alone — `characteristics.ts`'s `layerFour`) and `effectiveColors`; only a `power`/`toughness`/`keyword` clause needs the full characteristics fold (kept cheap deliberately — a `StaticAbility.condition` re-runs `matchesFilter` over the whole battlefield on every read). `FilterContext.layered` is how a static's `filter` scope is matched from *inside* the fold computing its target: types/subtypes/keywords as folded so far, and a power/toughness clause fails closed. Also the shared **weighted** scan behind "other" and aggregates: `weightedMatches` weighs each permanent by its `stackCount` and drops one permanent per excluded id (so "other" beside a stacked source leaves the rest of the stack counted), and `AggregateSpec`/`aggregateOver` sum or max power/toughness/mana value over it — the `EffectAmount`, the `aggregate`/`source-greatest` `StaticCondition`s and the `CostReductionAmount` all read through it.
- **`goad.ts`** — `goadersOf`/`isGoaded`: every player who has goaded a creature (rule 701.15), whichever way — a one-shot goad (`GameObject.goadedBy`, until the goader's next turn), one for the rest of the game (`goadedForGameBy`), or a static one (`StaticAbility.goads` — Baeloth Barrityl, an Aura's "enchanted creature is goaded" — read live, its source's controller the goader). The attack checks, the `goaded` filter clause and last-known information (`LastKnownInfo.goaders`) all read through it, so a goad is never asked about half-way. Goaded is a designation, not an ability: nothing here is in the layer fold.
- **`subtypes.ts`** — subtype lists and their two markers, `EVERY_CREATURE_TYPE` (changeling, rule 702.73a) and `EVERY_LAND_TYPE`: one entry standing for every type of its kind, so a changeling's list is `["Shapeshifter", EVERY_CREATURE_TYPE]` rather than ~300 names in every snapshot, mana unit and type line. **Every subtype question goes through `hasSubtype(list, subtype)`, never `includes`** — filters, lords, amass, mana provenance. Asked *for* a marker it means "any type of that kind", which is how "shares a creature type with" a changeling works (Path of Ancestry). `withoutTypeMarkers` is what a type line shows (`viewFor` strips them; the changeling keyword icon says it instead). Changeling adds its marker as the first step of layer 4, in every zone (`characteristics.ts`'s `withChangeling`); an effect adds either marker as an ordinary `addSubtypes` entry.
- **`target-polarity.ts`** — which side of the table a target belongs on, for the bots. `slotPolarities(effect, count)` reads each target slot of an effect tree as `harm` (bad for whoever controls the target), `help`, `take` (yours whoever's it is — reanimation, a copied spell) or `either`, through a rule per effect kind that is **total over `EffectSpec["kind"]`**, so a new kind fails the build until someone says which side it belongs on; effects that rebind target 0 (`look-and-choose`, `reveal-top`, `reveal-until`, `choose-permanents`) or choose their own (`reflexive-trigger`) aren't descended into. The strongest effect on a slot decides: removal and theft outrank the consolation they give their victim (Swords to Plowshares' life, Generous Gift's Elephant), a major effect a minor one (Sign in Blood's cards outrank its life). Every query takes an optional `PolarityBias` (a deck's own reading of some effect kinds, from `deck-bias.ts`), which overrides the rule for each slot those kinds touch. `castPolarities`/`abilityPolarities` (memoized per definition, one memo per bias), `auraPolarity` (an Aura's `attached` statics, `controlEnchanted`, Curses), `offerPolarities` for a `legalActions` cast or activation, `pendingTargetPolarities` for a `choose-targets` decision (reflexive, chapter and announced-modal triggers included), `specSide` (a spec that names the side is the card choosing, not something to second-guess), and `targetValue`/`rankTargets`/`onlyWrongSide` — a cheap static value that orders a slot's options best-first. 98.6% of the pool's targeted slots classify. No `bot/` import, so decision modules may use it. See `docs/plans/bot-effect-knowledge.md`.
- **`effect-worth.ts`** — the other half of `target-polarity.ts`: once targets are chosen (or where there are none), what doing an effect is worth to one player, as a coarse signed number (a card about 2, a point of life a quarter of one above 15 and three quarters below, removal 4). `effectWorth(effect, {state, me, controller, targets, source?, triggerObject?, triggerPlayer?})` reads the targeted slots through `slotStrengths` against the targets as chosen, and the untargeted parts off the effect's player scope for the kinds nearly every optional clause is made of (draws — a draw the library can't cover reads as losing —, life, discards, sacrifices, tokens and token copies of our own, tutors, recursion, a sacrifice-source); anything else is 0, unknown rather than bad. Something done to an opponent is split across the opponents. `costWorth` prices a choice's mana, life and energy. What v1 answers a "you may", a punisher's "unless", a villainous or modal choice, and which activated ability to use with; it only has to get the sign and the order between a cost and what it buys right, since v2 searches each of those and keeps v1's answer only when nothing beats it. Targeted slots read with `me`'s deck bias. No runtime `bot/` import.
- **`scry-pick.ts`** — what a bot scries or surveils away (`scryAway`), judged top card first, each knowing what was kept above it: a land stays while the bot has fewer than seven among its battlefield, its hand and the lands kept above, or when it makes a colour the bot can't make (lands in hand counted as made); a spell goes when its mana value is more than three beyond the bot's lands and mana rocks (two fewer for a colour it can't make); surveil also bins a card castable from the graveyard. v1's answer, and v2's in a tie — which is nearly always, since a scry changes the next draw and a rollout to the end of the turn rarely reaches it. No `bot/` import.
- **`land-colors.ts`** — which colours a bot needs (its commander's identity, or with none the coloured pips in its hand) and has no permanent to make (`missingColors`, from printed mana abilities and basic land types), and `newColorsFirst`, which orders a choice among lands alone so those making a missing colour come first: v1's `chooseFromZone` and v2's capped candidate order (`byManaValue`) for a fetch, a Cultivate, a Farseek. No `bot/` import.
- **`deck-bias.ts`** — what a deck wants that the bots' generic card knowledge gets backwards: `COMMANDER_BIASES`, keyed by commander name, each entry a `why`, a `polarity` (`PolarityBias`: effect kinds whose target slots the deck aims the other way — Teval's `mill: "help"`) and `ownWeights` (evaluation weights for the deck's *own* features only; opponents stay on the shared ones). `deckBias(state, player)` reads the commanders the player owns off the `GameState`, merges a pair's entries, and caches the answer per `state.objects` table (once per game, once per search clone), so v1, v2, every seat of v2's rollouts and a person's own Teval deck all get it without being told; `polarityBias` is the polarity half. Each entry is pinned by a gate scenario that fails without it. Only a type import from `bot/`. See `docs/plans/deck-biases.md`.
- **`this-way.ts`** — `thisWayEntries(state, what, since?)`: what the resolution under way (`GameState.resolutionSince`) has discarded, drawn, milled, sacrificed, destroyed (a destroy effect, not a death), destroyed and put into a graveyard (`"died"`), exiled, returned to a hand, put into a graveyard or put onto the battlefield from a zone, read off its own events — each object with whose it counts as, whether it left the battlefield doing so (so it's read as it last existed there) and how many tokens a stack that went whole stood for. Pure over `GameState`, so `filter.ts` can use it too: behind the `thisWay` amount, the `this-way` condition and the `thisWay` / `notThisWay` filter clauses ("a creature card milled this way"; Martial Coup's "all other creatures" after its Soldiers).
- **`replacements.ts`** — `ReplacementSpec` (rule 614/616), a discriminated union on `StaticAbility.replacement`: `enters-battlefield { tapped?, tappedUnless?, counters?, transformed? }` (a self-replacement), `others-enter-battlefield { filter, tapped?, untapped?, counters? }` (how *other* permanents enter — never its own source, never one entering alongside it; `counters.amount` is an `EffectAmount` that never counts the entering permanent or its batch), `would-create-token { multiplier }`, `would-add-counter { multiplier, counterKind? }`, `would-be-put-into-graveyard { instead: "exile", filter?, from?: "battlefield" }` (`from` is the dies-only form), `would-draw { who: "opponent", instead: "you-draw" }` / `{ who: "you", instead: { draws } }`, `would-mill { who, multiplier?, plus? }` (multipliers then additions), `would-gain-life { who, plus?, multiplier?, prevent? }` (applied in `changeLife`, so lifelink too; additions then multipliers), `would-deal-damage { multiplier?, plus?, atLeast?, combat?, prevent?, then?, source?, to? }` (doubling, "plus 2", raising it to this permanent's power, or prevention with a follow-up, scoped by combat or noncombat, a source filter and the recipient — applied in `dealDamage`, multipliers then additions then the power floor then prevention). - **`characteristics.ts`** — `computeCharacteristics(state, registry, id)` folds printed → layer 3 (text substitution) → layer 4 (type/subtype changes) → layer 5 (colour) → layer 6 (keyword grants/ability loss, and keyword counters — rule 122.1b, `KEYWORD_COUNTERS` — in timestamp order, rule 613.7: losing all abilities takes what was granted *before* it and none of what's granted after — `abilitiesLostAt`/`grantOutlastsLoss`/`modifierGrantApplies` — a static's grant dated by its source, an Aura's or Equipment's by when it attached, a keyword counter's by the latest counter of its kind, `GameObject.counterTimestamps`, 613.7c, and every modifier that grants something by its own `timestamp`) → layer 7b (a `setBasePtFromCount` CDA — a `CountSpec` counting a `CardFilter` over the battlefield or all graveyards, applied in every zone per rule 604.3 — then `animate`'s `setPt` and statics' `setBasePt`, by timestamp) → layer 7c (counters) → layer 7d (P/T grants/modifiers), timestamp-ordered. `Characteristics.restrictions`/`.protectionFrom` collect `StaticAbility.restrictions`/`.protection`. **Layer 4 is its own fold, `layerFour`**, because statics grant types to other permanents (`StaticAbility.addTypes`/`addSubtypes` — Kudo's Bears, Ragost's Foods, Bello's creatures): the object's own type-changing modifiers (ordered by `PtModifier.timestamp`) and every type-granting static on the battlefield, in timestamp order, each static's scope matched against the types folded so far plus everything the previous pass added, repeated until the set of statics that apply settles — dependency order (rule 613.8) for effects that only add types, so Kudo still reaches a land animated after it arrived; a dependency loop settles in timestamp order. `effectiveTypes`/`effectiveSubtypes` read it (so every filter, target check and scope sees granted types); with no type-granting static on the battlefield it is the old self-contained read of the object's own modifiers. A re-entrant fold for the same object (a grant's condition or attachment clause reading back into it) answers with its own types only (`layer4InProgress`, a third re-entrancy guard beside the condition and CDA ones), which is what keeps two grants whose scopes read each other's grants from looping. `LayerFour.applied` records which statics reached the object there, and **`staticReaches`** — what the fold and `Game`'s granted-ability lookups ask — sends a static with a layer-4 part to exactly those for its later layers (rule 613.6). `staticAffects` resolves an `AffectSpec` scope (`"self"`/`"creatures-you-control"`/`"all-creatures"`/`"lands-you-control"`/`"attached"`, lord `subtype` clauses, and `"filter"` — any `CardFilter`, from the source's controller's perspective), given a `TargetView` by callers partway through the fold. Changeling (rule 702.73a) is a CDA, so `withChangeling` adds `EVERY_CREATURE_TYPE` to a creature's subtypes before any other layer-4 step, in every zone, from its copiable values — kept through a loss of abilities (layer 6 comes later), replaced by a later `setSubtypes`. `Characteristics` also carries `basePower`/`baseToughness`, the P/T after layer 7b. `hasManaAbility` (rule 605.1 — activated by rule 605.1a's own test, `isManaAbilityByRule`, or triggered, `isTriggeredManaAbility`) and `hasAnyAbility` (rule 113 — `cards/define.ts`'s `printedHasAbility`, a table over every `CardDefinition` field, plus every kind of grant) read granted abilities through the memoized `abilityGrantSources`; a scope asking about the permanent it is granting to re-enters, which the `grantedAbilitiesInProgress` guard answers conservatively (printed abilities only), never cached. Layer 1 (copy) is handled upstream via `printedCardName`. `spellHasSplitSecond`/`spellCantBeCountered` read a spell's printed split second / "can't be countered" and the `grantsToSpells` statics that give it (`spellGrantReaches` — "creature spells you control can't be countered", read by `Game.counterObject`). `staticConditionMet(state, registry, source, condition, opts?)` evaluates a `StaticAbility.condition` gate, checked *after* `staticAffects` confirms reachability, with a re-entrancy guard for mutually-conditional permanents. Dependency ordering between static effects is not implemented. **Also owns the scoped computed-value cache**: `withComputedCache(fn)` opens a region (one per `legalActions` call / SBA sweep / `detectTriggers` event / `viewFor` / bot feature scan) inside which characteristics, layer-4 results, the contributing- and type-granting-statics pre-scans and `Game.manaSources` memoize; `invalidateComputedCache()` must be called by any mutation reachable from inside a region (`emit` is the broad net; `moveObject` suspends the cache outright via `suspendComputedCache`), values computed during a condition evaluation, a CDA count or a layer-4 fold (each has a re-entrancy guard whose answers are conservative) are never cached, and `MTG_CACHE_CHECK=1` on the fuzzer turns every characteristics and layer-4 hit into a recompute-and-compare that throws on divergence. **Wrap new read-only hot paths in a region; never let a region span a mutation without an invalidate.**
- **`target.ts`/`targeting.ts`** — `TargetRef` (player or object) and `TargetSpec` (`"any-target"`/`"creature"`/`"nonblack-creature"`/`"creature-you-control"`/`"creature-an-opponent-controls"`/`"player"`/`"opponent"`/`"opponent-whose-turn-it-is"`/`"creature-or-player"`/`"permanent"`/`"nonland-permanent"`/`"nonland-permanent-an-opponent-controls"`/`"land"`/`"artifact"`/`"artifact-an-opponent-controls"`/`"artifact-or-enchantment"`/`"artifact-enchantment-or-nonbasic-land-an-opponent-controls"`/`"creature-or-enchantment"`/`"attacking-or-blocking-creature"`/`"spell"`/`"creature-spell"`/`"noncreature-spell"`/`"instant-or-sorcery-in-your-graveyard"`/`"instant-or-sorcery-spell"`, plus the structured `permanent`/`spell`/`card-in-graveyard` forms, each with a filter and a `whose` — a `permanent`'s `"trigger-player"` is "that player" of a trigger, `TargetSource.triggerPlayer`). `{ kind: "any-number", of }` is "any number of target …": a group that is always the last slot, filled with as many distinct targets as the player picks, and judged — at the cast and again on resolution — against `concreteTargetSpecs(specs, chosen.length)`, so its shape comes from the choice, never from the board; effects reach its members with `for-each-target` or a flicker's `{ from }`. `isLegalTarget`/`legalTargets` take a `forPlayer` and an optional `TargetSource` (`{colors, types}`), and enforce protection (`protectionBlocks`, also used by `dealDamage`/`whyCannotBlock`/`attachPermanent`) and a player's hexproof (`playerHasHexproof` in `characteristics.ts`: a one-shot grant, or a `playerHexproof` static — Shalai). Checked on cast and again at resolution (all-illegal ⇒ fizzle); the slots found illegal beside a legal one ride along as `ResolutionContext.illegalTargets` (rule 608.2b), honoured so far only by the control-changing effects. `target-count.ts` is the pure distinct-target arithmetic behind "for each target" costs: `distinctTargetCount`, `targetCountBounds` (fewest/most distinct targets a legal choice can have), `fitTargetCount` (an `any-number` group trimmed or grown from its end), and `maxXForTargets`/`targetCountAtX` for X against the count.
- **`mana.ts`** — `Color`/`ManaType`/`ManaPool`/`ManaUnit`, `parseManaCost` (generic, `{X}`, `{C}` colorless, hybrid `{W/U}`, twobrid `{2/W}`, Phyrexian `{W/P}`, snow `{S}` folded into generic), `manaValue`, `poolTotal`, `poolCounts`. **A player's mana pool is a list of `ManaUnit`s, not a count per colour** (`poolCounts` rebuilds the count view for the player view and the payment planner): a unit carries where it came from — a `ManaRestriction` on what it may be spent on (rule 106.6b — Cavern of Souls), a `ManaSpendRider` that fires when it's spent (Path of Ancestry), `persists` for mana that survives the end of a step (Savage Ventmaw), `uncounterable` for "and that spell can't be countered", `from` for what made it (a `ManaOrigin` — the source's types, subtypes and supertypes as it made the mana, which a spell keeps as `GameObject.manaSpentFrom` and the `manaFrom` filter clause reads: "if mana from an artifact was spent to cast it") — and a count can carry none of it. The pool is empty almost all the time, since the engine auto-pays; it fills only when someone activates a mana ability by hand, which is exactly where an untagged pool would drop the restriction. The restriction is enforced twice on purpose: `planManaPayment` won't *tap* a source whose mana couldn't pay for the thing being paid for, and `spendFromPool` won't *spend* such a unit — and the latter spends restricted units first, because an unrestricted one can pay for anything later in the same cost.
- **`controller.ts`** — `PlayerController.act(view)` is the single entry point: when `view.state.awaiting` is set it must return that declaration, otherwise any legal priority action. `AutomaticController` always passes/keeps its hand. `ScriptedController` plays a queue plus assignable `*Fn` callbacks (what tests use). `RandomController` picks uniformly from `legalActions()` — the engine's fuzzer (see `random-demo.mjs`); it builds the six priority actions itself and gets every *decision* answer from that kind's `decisions/` module via `randomAnswerFor`, handing it a `RandomSource` (`random`/`pickIndex`/`pickTargets`). **The exact sequence of draws against that source is what makes a seed replay identically**, so changing the order or count of calls in one of those arms silently re-points every fuzzer seed. `HeuristicBotController` extends `AutomaticController` with a v1 "plays a sensible game, not a good one" policy (land first, else the highest-mana-value affordable spell, else a **non-mana** ability, else pass; attack with every eligible creature, each at the lowest-life defender *it* may legally attack that can't profitably block it (`defendersFor` — goad and "can't attack you" differ per creature — and `wouldDieAttacking`, a crude "can anyone there kill it" check; a creature every defender could eat stays home); block favourable trades and chump-block lethal), owning its own `CardRegistry` so it can read mana values and computed P/T. It **aims** by `target-polarity.ts` ("v1.5"): each slot's target is the best on the side its effect belongs on — removal at the opponents' most valuable permanent, a pump at its own best creature, an "up to one" help with only opponents to point at left empty — for casts, activations, trigger targets (`chooseTargets`), an Aura entering without being cast (`chooseEnchant`) and a Clone's copy (`chooseCopy`: the most valuable, never a legend it already controls); and it leaves alone a spell or ability whose only legal targets are on the wrong side (a counterspell with only its own spell on the stack), unless the spec names that side. It used to take the first legal target — players in turn order, then the battlefield oldest-first — and hit its own side 22% of the time; aimed, it benches 30.0% against three unaimed copies at four players (even 25%). Its other choices read `effect-worth.ts`: a "you may" or punisher is taken when what it does (less its cost) beats what declining lets happen, a modal choice takes its best modes, a sacrifice or an edict gives up the cheapest permanent (`targetValue`, a token below a card), a discard throws surplus lands and what the board can't cast soon (`chooseBottomOfHand` with the lands in play), and of the abilities it could activate it takes the one worth most, never one worth less than nothing — Viscera Seer's scry for a creature, a life payment down to nothing. Mana abilities are never activated on their own (`isManaOnlyAbility`): casting auto-pays, so floating mana gains nothing, strands the source, and — once bot moves are paced out one at a time — shows up as a land flipping sideways for no reason between a spell being cast and that spell resolving. Already-attached Equipment is re-equipped only onto a creature ranking clearly above its host (`targetValue` beyond `REATTACH_MARGIN` — Greaves onto the six-drop just cast), so a move can never undo itself, and one ability of one permanent is activated at most `MAX_ACTIVATIONS_PER_TURN` (4) times a turn — without both, Lightning Greaves' Equip {0} kept a bot in one main phase forever. It's the base class of both searching bots (`bot/` below) and the fallback under them, so every decision their search doesn't improve on is still this — including, now, the opening hand: `mulligan`/`chooseBottomOfLibrary` are overridden here and delegate to `bot/mulligan.ts`. Its land drop (`bestLand`) plays the land that lets it cast the most different spells this turn, then the one unlocking the most coloured pips in hand no land in play pays; it asks the engine through `ControllerView.legalActionsAfter` (optional — what would be legal after an action, on a throwaway copy; `Game.controllerView`, the live rooms' view, offers it, and the bot tools use that view too), so a view without it falls back to pips alone. v2's land search takes v1's land first, so it wins every tie. A scry or surveil (`chooseScry`) sends away what `scry-pick.ts` says to — v2's search rarely reaches the next draw, so it ties to this too. A creature that sacrifices itself to fetch a land (Sakura-Tribe Elder) is due at the end step of the player whose turn comes right before ours, with fewer than seven lands (`isCreatureFetchDue`); v2 takes it then without weighing it, as it does a fetch land, since the evaluation kept the 0/2 over the land. `engine/src/test/heuristic-bot.test.ts` runs bot-vs-bot games to completion as a second fuzz target.
- **`bot/`** — the searching bot, **v2** (`EvalBotController`), which `Room.addBot` seats; design records `docs/plans/smarter-bots.md` (the search) and `docs/plans/bot-effect-knowledge.md` (the plan of record — read it before changing how a bot picks actions). A v3 that planned whole turns over sampled worlds was built, benched and retired (`docs/plans/bot-v3-search.md` records why); what survives of it is `determinize.ts` (sampling plausible completions of the hidden information — v2 still reads the real hands) and `simulate.ts`'s `"playing"` policy (`simulateTurns`), which `bot:audit --rollout` prices a card with. One-ply search: enumerate the concrete actions available now (`candidates.ts`), play each against a throwaway `Game.fromSnapshot` copy (`simulate.ts`), score the result and take the best. Candidates are capped (8 target combinations an action, a dozen rollouts a decision), so each slot's options are first ranked by `target-polarity.ts` (`aimOffer` in `eval-bot.ts` — the right side first, most valuable first, the wrong side last rather than dropped): unranked, the cap cut to the battlefield's oldest permanents, and on a four-player board v2 never saw a threat newer than the turn-one lands. A targeted modal spell is tried in each choice of modes (as many as allowed, each mode alone, then the other combinations, capped) with its X at the maximum; it used to be tried only as every mode at once, and without an X — which the engine reads as 0. `features.ts` computes one player's raw unweighted feature vector (for the bot's own seat, a subtracted `threat`: opponents' creatures by the combat damage they could turn on it — only those the attack rules would let attack it at their controller's next combat (`combat/eligibility.ts`'s `playersAttackableNextTurn`: tapped and summoning sickness ignored, a Vow of Duty, a goad by us or Pacifism honoured) — in full from whoever attacked it within the last round — `PlayerState.lastAttackedBy`, recorded as attacks are declared — and as a share of the life, or commander damage, it has left), `drawEngines`, priced by the cards each engine draws a round of the table (`drawRate`: Phyrexian Arena 1, Rhystic Study half a card per opponent, capped at 3), and `answers`, the counterspells in its own hand: a reserve casting one gives up, so it counters a Craw Wurm or a Rhystic Study and lets a Signet through and `evaluate.ts` is `EvalWeights` plus a dot product over it (the bot's own features scored with its deck's `ownWeights` laid over them — `outcomeOf` reads them from `deck-bias.ts`; one-shot tokens that sacrifice themselves, Treasure, Clue, Food, are `resourceTokens` at 0.5 rather than full `otherPermanents`, and a mana rock's ongoing mana counts at `nonlandMana` 0.5, since 2026-10-02's behaviour sweep found Sol Ring held rather than paid for with a Treasure) — split apart so the weights can be **fitted** by logistic regression over harvested self-play positions rather than hand-picked. Combat is built one attacker/defender pair at a time and never enumerated (`combat-math.ts`, `eval-bot.ts`), its moves ranked before simulation by arithmetic that prices life with the evaluation's bend (`features.ts`'s `lifeCost`); before the climb, `alphaStrike` looks for a kill — as many opponents as the attackers can kill at once, trying each order of the killable ones and giving each the fewest attackers its kill needs — when the attackers' total damage covers every killable opponent's life, the subset of up to 10 attackers that kills spending the least damage, so 3+2 and 3+2 kill two opponents at 5 where biggest-first 3+3 left 2+2 short — then the most kills that survives the crackback; `decisions.ts` searches the decisions the engine raises mid-resolution. `scenarios.ts` is the opponent-independent gate (hand-built positions with a known right answer, parameterised by a weight vector) — `gate` scenarios every shipped vector passes, and `training` ones it may still get wrong, kept to tune against; most are written as a `position` (the board and a judge of *any* answer) rather than a script. `scenario-fit.ts` records one: every answer v2 simulated there (`EvalBotOptions.trace`) and the state its rollout reached, read into features by `evaluate.ts`'s `outcomeOf`. A priority window's rollouts never read the weights (v1 plays them out), so its choice under any vector is replayed exactly by `scoreOutcome` — which is all `evaluateState` is — and `leversFor`/`handTune` ask what single weight would fix a wrong scenario and what that breaks. `champions/` holds the frozen gauntlet opponents, each spelling out its whole `EvalWeights` literally so it can't drift when the defaults change. `bot/mulligan.ts` is the opening-hand policy both share (hooked onto v1, since a mulligan has no board to roll forward): a hand is scored on mana sources plus its cheapest few castable spells, ramp counting for both, and the bar it has to clear *falls* as the hand it would keep gets smaller — with a free Commander mulligan raising it instead, and a floor at four cards. `EvalBotOptions.timeBudgetMs` is a wall-clock ceiling on one decision, **off by default** because a clock breaks the engine's same-seed-replays-identically guarantee that tests, the fuzzer and the tuner all rely on; only `Room.addBot` turns it on. When it expires the search plays the best candidate found so far, and `pass` plus v1's own pick are scored first precisely so that an expired search degrades to v1-quality play rather than to whatever `legalActions` happened to enumerate first. The clock stops a search *predictively* — once the running mean simulation no longer fits, but never before those two baselines — and one deadline covers a whole attack declaration. Twin targets — tokens nothing tells apart (`state.ts`'s `tokenFoldKey`, shared with the token fold, plus combat, damage and anything pending that names one) — are cut to as many as the offer has slots before the cap (`bot/twins.ts`), so seven identical Treasures are one simulation and the cap goes to real alternatives. An until-end-of-turn pump, keyword grant or animation is not a candidate where it can't matter — outside combat, outside its own first main phase, with nothing on the stack (`HeuristicBotController.wastedNow`, over `effect-worth.ts`'s `onlyUntilEndOfTurn`/`temporaryEffectCanMatter`; v1 obeys it too): the live bot was casting Unleash Fury on an opponent's creature in its own upkeep. Nor is anything that costs mana, in its own upkeep or draw step with nothing on the stack (`holdsManaForMain`): the rollouts pass at every window, so the main phase's spells never appear in them and upkeep mana looked free. Nor is a creature that counters a spell as it enters (`effect-worth.ts`' `entersToCounter` — Transcendent Dragon, Mystic Snake) with no opponent's spell on the stack (`holdsForASpell`; such a card also counts toward `answers`), nor, in our own first main phase, a board wipe that would take a creature of ours able to attack this turn (`holdsWipeForCombat`: it waits for the second main phase; a one-sided wipe, or one our attackers survive, is left alone). v1 obeys both. Help aimed at an **opponent's** creature is a candidate only while that creature attacks someone else, and then only if it ends at end of turn, the creature is goaded by us, or — for lasting help, a counter or an Aura — the player attacked dies in the rollout (`opponentPump`, the user's rule). An ability it could activate again at once is also tried as a **batch** — as many times as the mana allows, one candidate (`simulateRepeated`; a targeted one twice, every activation at the same target and each at a new one, `nextInBatch`) — and once chosen, the rest go on the stack without searching again (`continueBatch`). It doesn't search a window it has already decided either (`holdPass`): after a batch, after its own spell or ability, or after it passed, while the stack only resolves — the candidate it chose was scored as exactly that, passed through to resolution; anything new on the stack is searched. Seed 50's bench timeout (Lathliss pumps and Scavenging Ooze exiles, a full search each, on a seventy-permanent board) is what found both. Between a batch's activations it asks only that ability's offers (`Game.legalActivationsOf`, `legalActions` narrowed to one source — the whole list plans a payment for every ability on the board, and asking it was a quarter of seed 50's turn 40). A window where passing is the only move it would consider costs no simulation at all (most windows in a game; it was a third of the bot's CPU). `EvalBotController.lastDecision` records what the last decision cost, for tests and measurement. `bot/capture.ts` turns a position saved from a live game (see the server's `capture.ts`) into a training scenario: `captureOptions` (everything the player could do there, ranked as the search ranks it, described by `describeMove`), `sameMove` (action equality, whatever order the fields were built in) and `scenarioFromCapture`; `bot:scenarios` and `bot:fit-scenarios` add every open capture (`captures/*.json`) to the training scenarios and every resolved one (`captures/resolved/`, each with a `resolved` record: when, at which commit, what fixed it) to the gate, so a fixed blunder that comes back fails it (`engine/scripts/captures.mjs`). `npm run bot:captures -w engine` lists them all with v2's answer today; `-- resolve <file or name part> --note "…"` stamps and moves one once v2 gets it right (refused while wrong, unless `--force`), `-- reopen` moves one back. Captures are git-ignored, so a fix also gets a committed gate scenario.
- **`mana-payment.ts`** — the mana solver, lifted out of `game.ts`: `planPayment` (the entry point `Game.payMana` wraps) = `resolveHybridCost` (hybrid/twobrid/Phyrexian pips → a concrete cost + the life they owe) → `planManaPayment` (a greedy solver: floating mana first, then coloured pips, then `{C}`, then generic, tapping a fresh source only when the already-tapped ones can't cover it; a converter — a Signet, whose own `{1}` another source pays — is reached for last, and when that plan fails a second pass funds the converters first, so two lands and a Signet pay a `{3}`). - **`decisions/`** — one module per `AwaitingDecision` kind (22), each owning that kind's *answer* half: its `LegalAction` projection, its `whyCannot` validator, its `ask` (one arm of `controller.ts`'s `answerAwaited`), its bot `candidates`, its `randomAnswer` (the fuzzer's arm, reached via `randomAnswerFor` — `RandomController` keeps only the six priority arms), and the per-kind predicates `hasSource`/`mayAct`/`autoAnswer`. `contract.ts` holds `DecisionModule`, `DecisionReadCtx` (what a module may read), `DecisionHost` (`Game.dispatch`'s decision arms transposed — every one was already a one-line delegate, so **no `apply*` body moved**) and the two total `as const satisfies` tables `DECISION_ACTIONS`/`DECISION_OFFERS`. `registry.ts` is the table plus `decisionFor`/`decisionForAction`/`decisionForOffer`/`mayActOn`/`decisionHasSource`/`autoAnswerFor`/`randomAnswerFor`; `define.ts` holds `defineDecision` **in its own file on purpose** — the registry imports every module, so a module importing the registry back is a value cycle whose symptom is `TypeError` at module init, not a build failure. `shared/` holds `picks.ts` (the four checks a validator keeps rewriting), `subsets.ts`, `target-combos.ts`, `mulligan-math.ts`. **Nothing under `decisions/` may import `game.js`, and `state.ts` may not import from `decisions/`** (`choose-creature-type.ts` imports `printedCardName` as a value, so the reverse closes a real ESM cycle). A static's `cantBeBlockedBy`/`canBlockOnly`/`cantAttackController` are read in `whyCannotBlock`/`whyCannotAttack` rather than folded into characteristics, so their scopes may ask about power. `Game` keeps one-line delegates for its own callers.
- **`primitives.ts`** — branded `PlayerId`/`ObjectId`, seeded `Rng` (mulberry32), `shuffle`.
- **`auto-settle.ts`** — `isSettled(state)` / `autoSettle(game)`: cascades past every "dead" priority window in one go. `Room` uses `isSettled` as its per-hop predicate but deliberately never `autoSettle` — it has to stop at every bot action to publish a frame, and per-seat auto-pass/skip-mana-only are one-shot-per-call, neither of which survives a cascade. `autoSettle` itself is now only used by tests/scripts that want a game settled in one call.

Snapshot/restore: `game.snapshot()` → `cloneGameState(state)` (`state.ts` — a plain-tree deep copy, ~2× faster than `structuredClone`, which stays the reference in `test/clone-state.test.ts`; bot search clones a state per simulated candidate, so this is the "candidates per decision budget" path); `Game.fromSnapshot(snap, env)` rebuilds (re-supply `registry`/`controllers` via `env`). Determinism: same seed + same controllers ⇒ identical replay.

## Engine commands, in full

- `npm run token:art -w engine` (`-- --write` to patch) — finds a real Scryfall printing for every `cards/tokens/` entry. A token can't resolve art by name the way a card does: ours are named for the engine key ("3/3 Beast Token") and Scryfall names printings after the creature alone ("Beast"), so `CardImage` skips the lookup for a token with no `art` and draws a text panel — which made tokens render hit-or-miss. The link comes from Scryfall's `all_parts` (the "Tokens" list on a card page) reached through the pool's own `create-token` effects, then matched on P/T, colours and subtypes. Keywords **rank** rather than filter, because both directions occur: Wurmcoil Engine's two Wurms differ only by deathtouch vs lifelink, while Chandra, Acolyte of Flame's Elemental is a vanilla printing whose haste comes from the spell. A printing carrying *fewer* subtypes than the definition (Oracle errata the physical token predates — "Wurm" vs "Phyrexian Wurm") matches at a lower tier and is flagged for eyeballing.
- `npm run gen:edhrec-rank -w engine` — rebuilds `cards/edhrec-rank.ts` from Scryfall (checked in; rerun as the pool grows, or to refresh the ranking).
- `npm run card:lookup -w engine -- "Card Name"` — the card's authoritative mana cost/type line/Oracle text/rulings and the tokens it makes (`engine/scripts/scryfall-lookup.mjs`), read from the checked-in **Oracle snapshot** (`engine/data/oracle/cards.jsonl` — every Commander-legal card and token, one line each, rulings folded in), so it works offline and in cloud sessions; only a card the snapshot lacks goes to Scryfall. Run this before authoring a new card — see `cards/AUTHORING.md` §1.
- `npm run gen:oracle -w engine` — rebuilds that snapshot from Scryfall's bulk data (Oracle Cards + Rulings, downloaded whole into the git-ignored `engine/.cache/scryfall/`, ~40s); rerun when a set comes out.
- `npm run card:scaffold -w engine -- "Card Name" | --next N [--cards] | --auto-scan [--all]` — writes card files from the snapshot into `engine/src/cards/scaffold/`: the stat block, `text`, rulings, keywords, pairing and tokens, and then whatever `scripts/oracle-parse.mjs` reads of the rules text. It reads two tiers: an ability's structure (cost or trigger, targets, restrictions) and its effect, whenever a whole sentence matches a template. Each line it can't read is left as a `// TODO(scaffold):`. A card whose every line was read goes, finished, into `engine/src/cards/review/`. `--report` writes nothing and lists the unparsed lines that recur most. `npm run card:parse-check -w engine` compares every ability the parser claims to have read with the hand-authored pool, and `test/oracle-parse.test.ts` requires zero disagreements. **Neither folder is registered** — authoring (or checking, with `card:verify -- --dir review`) and then moving the file into `pool/` is what puts a card in the game. `pool.test.ts` fails on a `TODO(scaffold)` in `pool/` or `tokens/`. See `cards/AUTHORING.md` §1.
- `npm run card:verify -w engine` — diffs every `cards/pool/` card's mana cost/colors/types/subtypes/P-T/loyalty against real Scryfall data, batched (`engine/scripts/verify-cards.mjs`). Structural fields only, not ability text. See `cards/AUTHORING.md` §16. **Every card in `pool/` is a real Magic card** — the pool's 27 invented placeholders were replaced with real printings of the same mechanic (see `neededCards-features.md` "E2"), so a `NOT FOUND` from this script now means a made-up or misspelled card, not a known exception. `tokens/` is exempt (token names aren't unique on Scryfall).
- `npm run card:text -w engine` — the same script's `--text` mode: the **rules-text** audit. It splits each card's `text` and Scryfall's `oracle_text` into clauses (one per line, then per sentence), matches every clause of the real card to its closest clause in ours by a set-similarity score over normalised tokens (the card's own name, "this creature", punctuation and reminder text are all normalised away first), and reports what didn't match — `MISSING` for a clause the pool dropped, `EXTRA` for one it has that the real card doesn't; `--similar` also shows the loose matches. Two false-positive classes are suppressed: a bare keyword line already on `def.keywords` (the client renders those from the keyword list) and a typed dual land's `{T}: Add` (implicit in Scryfall's type line, rule 305.6). **`cards/AUTHORING.md` §0 ("faithful, or not at all") is the standard this measures against**: a card whose printed behaviour the engine can't run is not authored at all, so every `MISSING` line should be either a paraphrase of `text` or one of the pre-rule cards on §15's "Known exceptions" debt list — never a new omission. It is still not a hard gate, and it is **blind to a clause that is present but wrong** (Saw in Half's tokens were the wrong size inside a clause it scored as matching), so read the output rather than counting it. `--lines` is the older, narrower check that compares only the number of text lines (the client renders `text` verbatim, so a missing `\n` runs two abilities together).
- `npm run test -w engine` — vitest, single pass (CI mode); `-- path/to/file.test.ts` for one file, `-- -t "name"` for a name match
- `npm run test:watch -w engine` — vitest watch mode
- `npm run build -w engine` / `npm run typecheck -w engine` — the build is `tsc`, then `scripts/bundle-shards.mjs`: each `dist/cards/shards/shard-NN.js` bundled (rolldown, pinned as the engine's own devDependency) with its card files inlined and every shared module left an import. Vite's dev server doesn't bundle, so without it the library and deck builder made one request per card (~5,800) and took 39 s to open after the dev server started; with it, ~160 requests and under 1.5 s. A production client build comes out the same either way. Only the client loads shards, so nothing else sees the difference; a `tsc --watch` build leaves them unbundled, which still works, just slowly.
- `npm run play:random -w engine` — `engine/scripts/random-demo.mjs`: N random-vs-random games (`-- --games 300`, `-- --log`, `-- --players 3|4`, `-- --progress` to announce each seed on stderr before playing it, `-- --seed 19` to replay exactly one seed, `-- --timeout 60` to set the per-game wall-clock limit in seconds, default 30). This is the engine fuzzer — if `legalActions` ever offers something `dispatch` refuses, or an unbounded loop/object-count blowup happens, it reports `FAILED seed N` and exits non-zero. **Each game runs in a worker thread (`random-game-worker.mjs`) that's killed if it overruns the limit**: a runaway loop *inside* one `tick()` never yields, so neither a timer in the same thread nor `Game.advance`'s tick budget (which only counts ticks that return) can stop it, and before this a single stuck game stalled the whole run silently. A failure no longer aborts the run — every failing seed is collected and listed at the end. **Every seed deals each seat its own 100-card Commander deck from the whole pool** (`engine/scripts/fuzz-decks.mjs`): a commander, then the next window of a fixed walk through the pool's spells and nonbasic lands (the commander chosen, from a random dozen, as the one whose identity fits most of that window), then basics. So a run of seeds sweeps the pool, and a new card is fuzzed with no edit anywhere. A seat only takes the window's cards inside its commander's identity, so at ~5,400 deckable cards 150 two-player seeds reach all but a few dozen, and CI's 38 games about three quarters (BACKLOG). `-- --with "Card Name"` (repeatable) puts a card in every seat's deck, and `-- --coverage` plays nothing and reports how much of the pool the seeds reach. A few cards that mean nothing alone bring a partner along (`PACKAGES`: Skullbriar brings Reanimate). These replaced four hand-kept lists that had grown to 150-500 cards each, where a game drew a given card one time in six and never ran out of library.
- **Bot measurement** (all in `engine/scripts/`, all `worker_threads` pools over `SAMPLE_DECKS`; see `docs/plans/smarter-bots.md`). Seeds come in blocks of `--players` games, one seating per block with the measured seat moving round the table, so deck strength and play/draw cancel (`bot-seating.mjs`, shared). `npm run bot:bench -w engine` — a weight vector's win rate against v1 (`-- --opponent <champion id>|mixed|gauntlet`, `-- --players 4`, `-- --weights JSON`, `-- --games N`, `-- --candidate-options JSON` for `EvalBotOptions` on the measured seat only — how the `"acting"` rollout was benched against the same build). `bot:tune` — a (1+1)-ES over the weights, head-to-head against the incumbent with the gauntlet as a veto. `bot:harvest` then `bot:fit` — harvest labelled positions from self-play, then fit weights to them by logistic regression (the ES buys one accept/reject bit per 200 games; the same games hold ~150k labelled positions). A fit is a lead, not a verdict: it raised `power` to 2.03 where the four-player sweep peaked at 0.5 — a big board predicts a win, which doesn't make a bot that values power highly win more. **Shipped weights are set by four-player sweeps and benches**, or — where a term exists to cancel another, like `idlePower` against `power` — by that structure, with a scenario to show it. `bot:scenarios` — the opponent-independent gate any candidate vector must pass, exits non-zero on a failure, and reports the training scenarios beside it. `bot:fit-scenarios` — for each scenario a vector gets wrong, every single weight that would fix it, the nearest value that does and what it breaks; then the vector those levers add up to, pulled one at a time and played for real (`--out` writes it for `bot:bench --weights`; `--joint` adds a coordinate-descent fit, untrustworthy on a small corpus). **Diagnostics, which is where most of the real findings came from**: `bot:behaviour` plays a few dozen self-play games and counts what a watching player would notice — targets aimed at the wrong side of the table (judged by `target-polarity.ts` with each seat's deck bias; harm at its own permanent with a "when this dies" trigger, a Dragon Egg, is tallied apart as a play), own turns that end with a sorcery-speed spell castable and unplayed, skipped land drops, and time by kind of window against the room's budget (`--budget 300` by default, on 8 workers because contention changes what a wall-clock budget buys; `--budget none` is exact and takes every core; `--weights JSON` compares two vectors on the same seeds); `bot:audit` prices a card by spawning it on a fixed board and printing the score change (`-- --rollout` adds what it's worth once the next turns are *played out*, and the gap between the two columns is the enablement a static score can't price). Every one of these takes `--champion <id>` where it makes sense. **Across commits** (`baseline-build.mjs`: the engine at a git ref built from `git archive` into the git-ignored `.scratch/baseline/<sha>/`, beside a frozen copy of the working `dist`, one table seating both since `GameState` is plain data): `bot:ab` benches the working bot in one seat against the baseline's in the rest (`--base origin/main`, `--bot v1|v2`, resumable NDJSON in `.scratch/`), and `bot:diff` plays every seat on the working build while asking the baseline's bot each same question, listing every disagreement in words — what a change changed, where a bench only says whether it won. `bot:replay` plays one seed (`--snapshot-at TURN` saves `.scratch/replays/seed-N-tTURN.json`; `--from FILE` restarts there, from a snapshot or a `captures/` capture or bug report) logging slow decisions, activations and each turn's time. The `ab-bench`, `decision-diff` and `replay-seed` skills drive them.
