# Engine architecture reference (`engine/src/`)

Reference detail, **not loaded automatically**: read the entry for a file before changing it. The short, always-relevant version is `engine/CLAUDE.md`; this is the per-file detail it points into. Keep it current when a file's shape changes, but it is a map of the code as it is, not a changelog.

## The workspace

- `engine/` — a TypeScript library package, ESM (`"type": "module"`), NodeNext resolution. Emits to `dist/` with declarations; `package.json` `exports`/`main`/`types` point there. No I/O, no UI — a pure state machine driven entirely through `dispatch`.

## What's implemented

Full turn/step loop, casting + targeting + fizzle, a LIFO stack, SBAs, full combat (first
strike/double strike/trample/deathtouch/lifelink/menace, multi-blocker damage assignment as a
player choice, a first-strike priority window, must-be-blocked), activated/triggered abilities
(intervening-ifs, `{X}` costs, loyalty abilities), the full continuous-effects layer pipeline
(1 copy, 2 control, 3 text, 4 type-change, 5 colour, 6 keywords/ability-loss, 7 P/T incl. a CDA
layer), tokens (with a `stackCount` compaction scheme so a self-replicating generator can't blow
up object count — see "Token stacking" below), Auras & Equipment (an Aura put onto the battlefield without being cast chooses what it enchants, rule 303.4f), Commander (command-zone casting
with tax, the command zone as its owner's choice — a state-based action once it's in a graveyard or exile (903.9a), a replacement for a hand or library (903.9b) — commander damage, Partner and every variant of
it — Partner with, Partner—[text]/Friends forever, Choose a Background, Doctor's companion — as a
declarative `CardDefinition.pairing`, the legend rule),
an opt-in simultaneous-mulligan phase, 2-4 player tables (APNAP ordering, per-defender blocker
declarations), a full replacement-effects pipeline (`replacements.ts`), modal/"you may"/targeted-
modal spells, mass effects (wraths, edicts) and tutors/scry/surveil, a rich effect vocabulary
(bounce/exile/mill/discard, fight, counter, control-change, clone, animate, text-change,
count-scaled and trigger-supplied amounts, token-for-target and token-copy effects, conditional
effects, sacrifice costs incl. filtered ones, additional costs & kicker), planeswalkers, alternate
casting zones (flashback, suspend, foretell, escape, disturb, adventure, MDFCs, transforming DFCs
+ Day/Night, Channel from hand, Overload, a conditional free-cast permission, Convoke), extra
turns/combats, cascade/storm/spell-copying, Sagas, station cards (Spacecraft — rule 702.184, 721), the Monarch/Energy/Emblems, damage-prevention
shields, and a color-identity-aware Commander deck validator (`identity.ts`, `deck-validation.ts`).

**Every player decision is a dispatched action**, never a synchronous controller callback. Each of the 22 kinds is a module under `decisions/` owning its whole *answer* half — offer, validator, controller arm, bot candidates — registered in a total table, so adding one fails the build at that table rather than several hundred lines away. Applying stays on `Game`. See `docs/plans/decision-registry.md`. The kinds:
`declare-attackers` / `declare-blockers` / `assign-combat-damage` / `discard` /
`choose-from-zone` / `mulligan` (answered by `mulligan`, then `put-on-bottom`) / `commander-replacement` /
`pay-life-for-untapped` / `reveal-for-untapped` (a reveal land's "you may reveal a [type] card from your hand", asked before it moves by `askEnterChoice`; the offer's `options` are redacted from other seats) / `choose-copy` / `choose-enchant` (offering permanents, or for an "Enchant player" Aura players — rule 303.4f — answered with either) / `legend-rule` / `order-triggers` (rule 603.3b: a player who orders their own triggers — `GameState.ordersOwnTriggers`, set by `Game.setOrdersOwnTriggers` from the client's setting — is asked by `placePendingTriggers`, before any of the batch goes on the stack, when two or more of theirs wait that aren't all one ability; the answer lists them in resolution order and marks them `ordered`, so `triggerPlacement` keeps it; everyone else, bots included, gets the engine's order: `stackFirst`, then triggers that read the board (`countOf`, an `aggregate`/`controls` condition), then the rest, then those that add to it (a token, a copy, counters, P/T), each group in the order they triggered — `triggerBoardRole` — so what grows the board resolves before what counts it) / `choose-text` / `choose-creature-type` / `choose-modes` / `choose-targets` /
`sacrifice` / `scry` / `proliferate` / `choose-permanents` (a choice made as an effect resolves, no targeting — "untap up to two lands") / `enter-attacking` (what each creature put onto the battlefield attacking attacks — rule 508.4: `Game.putIntoAttack`, reached from a `create-token`'s `attacking` (`EnterAttacking`: `"choose"`, or `{ player, orTheirPlaneswalker? }` for "attacking that player", with the `for-each-player` effect for "for each opponent"), applies rule 506.3a-c — only a creature, under the attacking player, during combat — sets `attacking` to its first option, and queues the question in `pendingEnterAttacking` only where there's more than one; `promptNextEnterAttacking` asks it in the `prepareForPriority` fixpoint. It emits `entered-attacking`, never `attacker-declared`, so no attack trigger sees it (508.3a). A card enters attacking the same way through `look-and-choose`'s and `reveal-until`'s `attacking` (Kaalia, Winota, Raph & Mikey), and a token copy through `create-token-copy`'s `tapped`/`attacking`/`exileAtEndOfCombat` — the last a real delayed trigger at the new `"end-of-combat"` timing. `for-each-player` parks the players still to go when one's effect stops to ask something, and a `may` with `aboutThatPlayer` puts that player on its `choose-modes` offer (`about`): myriad (`cards/helpers.ts`'s `myriad()`) asks once per other opponent) / `cast-now` ("you may cast [a card]" during a resolution, rule 608.2g — Chandra, Acolyte of Flame's one target card; hideaway's linked card (`from: "exiled-with-source"` — `GameObject.exiledWith`, rule 607.2a), where `play: true` also offers a land card, as a `play-land` in the decision's `lands`, played on its player's own turn with a land play left, which it uses (rules 305.2a, 305.2b, 305.3 — `Game.whyCannotPlayLandNow`); a card picked from a hand, graveyard or looked-at library top — Baral's Expertise, Diviner of Mist, Velomachus Lorehold: the offer is the `cast-spell` offers with `via: "effect"` of every card on offer (`cards`, plus `looked` — library cards shown to that player alone, castable or not), timing ignored, worked out as it's raised on its terms (`free`: "without paying its mana cost", the only way offered — an alternative cost of {0} that kicker may be paid on top of, rule 118.9d; `spell`: a filter the spell must match as it would be cast — its face, its prototype, rule 601.3e — both held to by `whyCannotCastSpell` through `Game.castNowOffer`); the answer carries one built into a `cast-spell`, or `null`, and `Game.applyCastNow` casts it through the ordinary `castSpell`; the client sends a `via: "effect"` cast as this answer, and `decisions/shared/random-cast.ts` builds the fuzzer's; the v1 bot casts the dearest card on offer) alongside the priority actions. `legalActions(player)` enumerates what's
playable right now with per-slot target options; `viewFor(player)` produces a redacted,
self-contained snapshot for one seat.

**Not modeled**, and every other known rules gap, is listed under "Engine rules gaps" in
`BACKLOG.md` — Battles, phasing, dungeons/Initiative/Ring, banding, Companion, replacement
ordering, static dependency ordering and snow sources among them.

**Token stacking** (an engine resource-safety mechanism, not a rule — added after the fuzzer hung
on a self-replicating-token card): `GameObject.stackCount` lets one object stand in for many
fully interchangeable, still-pristine token copies instead of minting one object per copy.
`Game.mintTokenBatch` folds new batches into a matching existing stack; a fresh batch only
originates a stack past `STACK_ORIGIN_THRESHOLD` (8), so ordinary "create two tokens" cards are
untouched. Only tokens with no activated ability and only count-scalable, non-targeted triggered
abilities are ever stacked (`Game.isStackableTokenName`). `Game.splitOneFromStack` peels one off
into an ordinary object the instant anything singles it out (a chosen sacrifice; a target is split
*once, as it's chosen* — `Game.lockInTargets` at cast, activation and trigger placement, after
costs are paid — so every step of a multi-step effect, and any copy of the spell, reaches the same
token); `Game.materializeStack` expands a whole stack into real objects for combat (capped at
`MAX_MATERIALIZED` = 100 — attacking/blocking are optional, so declaring a legal subset is
allowed); `recompactTokens` (end of cleanup) folds tokens back into stacks once nothing tells them apart (`tokenFoldKey`, shared with `findMergeableStack`) and nothing else names them by id (`pinnedTokenIds` — an attachment's host, a delayed trigger's target, a prevention shield's) — a group of eight or more, one holding a stack, or one holding a token split off a stack (`GameObject.splitFromStack`, set by `splitOneFromStack` on the token it peels off and on a stack drained to its last). Mid-turn, `refoldSplitTokens` does the same as soon as nothing is waiting (run by `prepareForPriority` just before priority is granted, with an empty stack and no trigger or decision pending), so a trigger that fires once per token and puts counters on "it" (Tribute to the World Tree) leaves one stack once its last copy resolves, not one object per token: it folds only tokens the same in *everything* (`token-fold.ts`'s `exactTokenShape` — per-turn records included), only groups holding a split-off token, and never folds away a token the rest of the state names (`referencedObjectIds` — the turn's history of what entered keeps counting it), folding the others into it instead, and leaves a token that attacked this turn to cleanup (`turnHistory.attackers` counts by object). Counters put on a whole stack were put on each token: a `counters-put` watcher fires once per token (`counter-added`'s `count` when a batch entering with counters joins a stack already there). **Anything that counts permanents counts a stack as every token in it** — `permanentCount` (`state.ts`), behind `countOf`, cost reductions, "controls N or more" conditions, count-scaled P/T and the died-this-turn count; counting objects instead had Krenko, Mob Boss making two Goblins forever. An "each **other** …" count bonus (`grantPtPerCount.excludeSelf`) beside a stacked source still counts the rest of that stack (`othersInOwnStack`), since each token in it is "other" to the rest. Because that makes counts of a million reachable, loops that mint one real thing per unit (individually made tokens, mana units, unscalable trigger copies) stop at `Game.MAX_EFFECT_INSTANCES` (1000), and a draw loop stops at the first empty-library draw. The same holds on the stack: a triggered ability that chooses no targets and isn't count-scalable, fired once per token of a stack (Authority of the Consuls seeing twenty Goblins enter), is queued once with `PendingTrigger.copies` and goes on the stack as one ability object with that `stackCount` — each copy still its own resolution, one at a time with priority between (`removeOneAbilityCopy`), a counter taking one. See
`token-stacking.test.ts`, `token-stack-counts.test.ts`, `token-stack-refold.test.ts`, `token-stack-targets.test.ts` and `random-demo.mjs` for the original repro.

## File map

Tests live in `engine/src/test/*.test.ts` (one directory level deeper than the source they cover,
so relative imports need an extra `../`), except `cards/pool.test.ts`, which stays colocated with
the `cards/pool/`/`cards/tokens/` layout it guards. `server/src/test/*.test.ts` mirrors this. Discovery is
vitest's default glob, which finds them wherever they are; `tsconfig`'s `src/**/*.test.ts`
exclude already covers the subdirectory. `engine/vitest.config.ts` sets two things and
deliberately leaves discovery alone. It raises `testTimeout` to 30s: these are CPU-bound
simulations rather than the async I/O vitest's 5s default is sized for, and several sat close
enough to that limit to pass alone and fail on a busy machine. The two real long-runners
(`bot-plan.test.ts`, `eval-bot.test.ts`) keep their own larger per-file overrides. And it turns
off `isolate`, so each worker imports the card barrel once rather than once per test file,
which took the suite from 4m30s to under a minute. That is safe only while no engine test
mocks, spies, stubs a global or fakes timers. **While authoring, run just the files you touched**
(`npx vitest run cmdr-sokka pool.test` from `engine/`, ~15s), and the whole suite once per batch
before committing. `server` has no config — nothing there runs long, since its pacing tests
drive a fake clock.

A spell or ability object carries `lastKnownRefs` (`LastKnownRefs`: the battlefield stint — `zoneChangeCount` — of its source and triggering object when it triggered or was activated (and `triggerSpell`, a triggering spell's stint on the stack: gone from it, "that spell's mana value" is its `lastStackManaValue`, X included), the permanent it sacrificed, and the one it tapped for its cost (station's "the tapped creature"); for a trigger, also what its event was aimed at — `recipient`, the permanent (with its stint) or player dealt damage — and `player`, the player the event names: the one dealt damage or controlling the permanent dealt it, or an attack's defending player; and, for a trigger fired by its object *leaving* the battlefield, `triggerObjectAfterLeaving` — where that object went, which is as far as "return it" follows it: moved on again since, it is a new object (rule 400.7) and `ResolutionContext.triggerObjectLost` makes acting on it a no-op, while reading it stays last-known information), which is how a reader tells the departure it means from a later one; a target is known to have been a permanent from `targetZones`. Acting on an object needs it to still be the same one (rule 400.7): a stack object's `targetStints` and `sourceZoneChangeCount` record each target's and its source's `zoneChangeCount` as it went on the stack, and at resolution a target that has changed zones since (`targetsStillMeant`), or is otherwise no longer a legal target, is blanked (`targetLegality`, rule 608.2b): nothing acts on it or finds anything out about it, and the spell or ability doesn't resolve at all only when it chose a target and every one it chose is illegal — an "up to one" that chose none resolves, and each chosen mode of a modal spell applies with its own illegal targets blanked. A changed source is `sourceLost` — while reads of it, and of a target that leaves *during* the resolution (608.2h), go through last-known information. One-off designations on a `GameObject`: `monstrous` (rule 701.37b — cleared by any zone change), `exertedBy` / `exertedOnTurn` (rule 701.43 — the exerter whose next untap step it skips, cleared as that untap step happens), and `enterChoice.riot` (rule 702.136, asked before it moves). `GameState.pendingExerts` queues the attackers whose "you may exert this creature as it attacks" is still to be asked; a `choose-targets` awaiting may carry `divide` (a triggered ability's divided amount, its group's place in the answer), a `choose-from-zone` one `enterUnder` / `enterAs` (a `look-and-choose` over every graveyard), and a `choose-creature-type` one `riot`. `PlayerEffect` also carries the game-outcome locks — `cantLoseGame`, `cantWinGame`, `cantLoseLife` and `damageLifeFloor` (Angel's Grace, Everybody Lives!), each a list of players fixed as it resolved — and `PlayerState.spellNamesCastThisGame` counts the spells a player has cast this game by name (Approach of the Second Sun), never reset. The `choose-from-zone` awaiting's `order`/`thenOrder` (library ordering) and `priorityTo` (a cost's choice — priority back to the activator, as the `discard` awaiting's `priorityTo` is), its `"exile"` destination and `"bottom-any-order"` leftover. `PtModifier.setToughness` is a layer-7b set of toughness alone (an exchange with a life total, rule 701.12g — Tree of Redemption). `TurnHistory` also counts `toGraveyardFromHandOrLibrary` and `leftGraveyard` (Welcome the Dead's X, Essence Anchor's condition). `PlayerState.attackedByOnTurn` (the last turn each player declared a creature attacking this player — the player, not a planeswalker) and `lastTurnTaken` are what `attackedYouDuringTheirLastTurn` reads (Weathered Sentinels). `GameObject.exiledWithCount` is how many cards an `exile { linked }` has ever exiled with a permanent's stint (Colfenor's Urn), and `abilitiesUsedThisTurn` is cleared as every turn begins, anyone's ("activate only once each turn" — Wall of Roots on an opponent's turn). `GrantedAbilityRef`'s `{ kind: "cycling", cardName }` names a card's cycling ability on the stack. `PlayerEffect.tokenMultiplier` doubles the tokens its owner creates for a while (Kaya, Geist Hunter's −2), multiplied into `tokenCreationMultiplier` with any Doubling Season. `PtModifier.untilEndOfCombat` ends with the combat phase (rule 500.5a); `GameObject.copyRestore` holds what a `become-copy` set aside until cleanup. `tokenFoldKey` includes the turn a token entered, so tokens made on different turns never share a stack ("entered this turn" is exact per token), and the awaiting `choose-permanents` carries `priorityTo` when it pays an activation cost. `PlayerState.currentCombat`/`previousCombat` (`CombatId`) and `GameObject.lastAttack` answer "didn't attack during your last combat"; `mustAttackPlayerThisCombat` ends a `mustAttackPlayer` with the combat. A spell's `convokedBy` records the creatures that convoked it, by stint; its `SpellSnapshot` carries them, so a copy's "each creature that convoked this spell" is the original's (rule 707.10). `LastKnownRefs.arrivedTogether` holds the cards a batched `put-into-graveyard` trigger fired on (Colossal Grave-Reaver). `PlayerState.attackedWithCommanderOnTurn` answers "during any turn you attacked with a commander". `GrantedAbilityRef`'s `card-activated` names another card's own printed activated ability (a linked exiled land's, granted by Steward of the Harvest). "For as long as [this] remains on the battlefield" (rule 611.2b): `PtModifier.whileSource` / `ControlEffect.whileSource` name the source and its stint, and `GameState.whileSourceIds` lists the sources such effects are waiting on, so a permanent leaving is checked against a short list rather than every modifier. `GameState.combatDamagePreventedBy` (turn-scoped source filters for prevented combat damage — Arachnogenesis) and `GameObject.skipsNextUntap` ("doesn't untap during its controller's next untap step", following the permanent, not its controller). `GameObject.attachedToPlayer` is the player a Curse is attached to (rule 303.4 — "Enchant player"; never set with `attachedTo`, cleared by any zone change, kept in `LastKnownInfo`), and `enterChoice.enchantPlayer` the player an Aura is entering attached to (its spell's player target, or the 303.4f choice); the `choose-enchant` awaiting's `players` are the players such an Aura could enchant.
- **`game.ts`** — `Game` owns the single mutable `GameState` and is the **only** writer. `dispatch(action)` handles every `Action` variant (see `actions.ts`). After each, it answers any trigger's "you may" a standing "same for all" covers (`GameState.standingModeAnswers`): a `choose-modes` raised as a triggered ability resolves carries `trigger` (its `triggerSignature` — controller, card name and ability index, or the granting static — and the identical triggers still under it, offered as `sameForAll`); answering with `forAll` records the answer, which `standingAnswer` replays for each of those as it resolves while nothing new has gone on the stack (a shortcut, rules 732.2a–b). Only the yes-or-no is shared — each trigger chose its own targets going on the stack. A 3-4 player table queues attacked defenders in `pendingBlockerDeclarations`, drained one `declare-blockers` at a time. There is no blocker-ordering step (Foundations removed damage assignment order): after blocks the active player simply gets priority. `legalDefenders(attacker)` returns every non-eliminated opponent plus their planeswalkers. `advance()`/`advanceUntil(pred)` run `tick()`. `emit()` appends an event and runs `detectTriggers` (matches against every battlefield permanent's `triggered` list — and a command-zone card's Eminence abilities, and a graveyard card's `fromGraveyard` ones, rule 113.6k, found through the per-name `graveyardTriggerNames` cache — honouring intervening-ifs via `interveningIfMet`). `prepareForPriority(player)` is the pre-priority fixpoint loop: run SBAs (not while a resolution is suspended), drain pending mass-effect/sacrifice queues, resume a suspended resolution, place pending triggers (APNAP order) — repeat until stable, then hand off priority (to `awaiting.player` if a decision got raised mid-loop). A sacrifice *cost* of several permanents (an ability’s `{filter, count}` or `{each}`, a spell’s `additionalCost.sacrificeCount` or `flashback.sacrifice`) is paid after the rest of its cost, the spell or ability already on the stack (rules 601.2h, 602.2b): `beginCostSacrifice` records `GameState.pendingCostSacrifice` and asks each part with the ordinary `sacrifice` decision (`continueCostSacrifice` — only what leaves the later parts payable, nothing asked where exactly enough is there), `applySacrifice` routes the answer there rather than to the edict queue, and `finishCostSacrifice` sacrifices every pick as one leave batch. The mana is planned with what could pay the sacrifice tried last, and a Treasure the plan sacrifices for mana doesn’t count towards it (`costSacrificeRemaining`, `spellSacrificeParts`). Mana is **auto-paid**: `manaSources` reports each permanent's `{T}: Add` abilities (plus an untapped once-a-turn one — Vivi Ornitier's `{0}: Add`) as `ManaOption` alternatives — a land's intrinsic ones too (rule 305.6): `effectiveActivated` lists printed abilities, then one for each basic land type the land has that no printed stand-in covers (`extraIntrinsicManaColors` — a type an effect gave it), then granted ones, and a typed land's printed `{T}: Add` stand-in lapses with its type (`inactiveStandIn`, rule 305.7), sizing a live `amount` (a power, a turn stat) against the board as it stands and compressing "X in any combination of" into one `anyColorOf` option rather than X+1 splits, resolving a list read off the board (`manaOneOf` — rule 106.7's "could produce" is `couldProduce`, which asks through other such lands, never back to one already asking), an option per colour for an amount read for "that color" (Nykthos), a `tap-for-mana` multiplier (`tapManaMultiplier`) and each triggered mana ability's extra on top (`withManaExtra` — the extras are `ManaOption.extras`, which the planner keeps apart so `useManaSource` stamps none of the source's restriction or rider on them) → `Game.payMana` hands a `ManaPlanningView` to `mana-payment.ts`'s `planPayment` (= `resolveHybridCost` → `planManaPayment`, both pure) → `executePayment` (taps/sacrifices sources, spends the pool, pays life); `castingCostOf` folds in commander tax and `costModification` statics (a `commanderTaxAsLife` card's tax is life instead, paid beside the mana and reserved out of the planning view's `life`). `payMana`'s last two arguments are the difference between a preference and a rule: `avoid` puts a source last (don't casually tap a permanent for its own ability's mana cost), while `exclude` removes it outright — an ability whose cost includes `{T}` taps its source to pay that, so it can't be tapped for mana as well (rule 602.2a). Without the latter, Mind Stone's `{1}, {T}, Sacrifice` funded its own `{1}` off an otherwise empty board. Ability objects are minted onto the stack by `mintAbilityObject` and deleted from `state.objects` on resolution. An ability that was *granted* (a `grantsActivated`/`grantsTriggered` static, or a modifier's `grantsTriggered`/`grantsActivated` — a one-shot grant, or a copy exception's "and it has …") carries a `GrantedAbilityRef` from the moment it's activated or triggers, and `stackAbilityOf` resolves from that rather than by index into its source's current abilities — the grant is often gone by then (an Aura that fell off with the creature it enchanted), and rule 113.7a says the ability doesn't care. The same rule is why a permanent that has lost all its abilities still *lists* its printed triggered abilities (`TriggeredEntry.lost` — they don't trigger, but an index into the list still names the one that triggered before the loss), and has whatever was granted it since the loss, triggered, activated and mana abilities alike (rule 613.7). All P/T reads go through `computeCharacteristics`. Combat damage runs through `combatDamageStep` → `runCombatDamageSubPass` (first-strike sub-pass, then regular, each followed by SBAs + a priority window when relevant; who deals damage in the regular one is fixed by who had first or double strike as the first began — `CombatDamageState.firstStepStrikers`, rule 510.4 — plus whoever has double strike by then) → `dealCombatDamage`, which takes a player-chosen `assign-combat-damage` split when one exists, else auto-assigns the standard split (`standardAssignment`); `dealDamage` runs deathtouch/lifelink, prevention shields, and Fog uniformly (for combat and burn alike) and returns the amount actually dealt. From a source with infect (rule 702.90) or wither (702.80) — `sourceHasDamageKeyword`, any zone, or its last-known information — damage to a creature is that many -1/-1 counters put by the source's controller (`addCounter`, so counter replacements and "you put" triggers see it) rather than marked damage (120.3d), and infect's to a player is poison counters rather than life lost (120.3b); the deathtouch state-based action reads `markedByDeathtouch` alone, since infect damage marks nothing (704.5h). Damage dealt all at once (a combat damage sub-pass, `damage-all`, "each opponent", the steps of a `simultaneous` sequence — `ctx.simultaneously`) runs inside `withDamageBatch`, which settles it as one event: lifelink gains once per *source* (rule 119.9 — so "whenever you gain life" counts sources, not recipients), and a `dealt-damage` (enrage) trigger fires once per permanent for the total; a `deals-damage` trigger (the source's side) is not batched — it fires once per recipient, as rule 603.2 reads "deals damage to a permanent or player". `createTokens`/`addCounter`/`entersBattlefieldReplacement` all honour replacement multipliers (Doubling Season). `moveObject` is the single zone-transition function: it applies enters-battlefield replacements — the entering permanent's own, then every other permanent's `others-enter-battlefield` (Giada's counters, Thalia's "enter tapped", The Wandering Minstrel's "enter untapped", which beats every enters-tapped), with the moving effect's own "tapped", "under your control", "it's an enchantment" and "it's a Phyrexian in addition" (`setTypes`, `addSubtypes` — the Enduring cycle, Portal to Phyrexia) passed in as `EnterOptions` rather than applied after the move, so a replacement can see and override them (and the permanent is its entering controller's for the whole entry, so the triggers its counters set off see it as theirs; the control effect that keeps it there is still the caller's to create) — defers a commander's move to a hand or library behind a `commander-replacement` decision (903.9b), from the battlefield or, to a hand, from the stack, a graveyard or exile (a spell Remand counters into its owner's hand), and records one put into a graveyard or exile (from anywhere) for the next state-based check to offer the command zone (903.9a) — and **returns whether it moved** — `false` for that deferral, and for a card that can't enter the battlefield, which stays where it was (an instant or sorcery, rule 400.4a; an Aura with nothing to enchant, 303.4g); a caller that only announces a completed move reads that, never `awaiting`, which may be someone else's decision — redirects a graveyard-bound card to exile when a replacement or `castVia` says to, resets face/copy/modifier state on any move to a hidden zone, and emits `permanent-left-battlefield`/`permanent-destroyed` as appropriate. `runStateBasedActions` recomputes control (layer 2, every control effect in timestamp order), puts an Aura attached to nothing, or to something it can't enchant, into its owner's graveyard and unattaches an Equipment from anything it can't equip (704.5m–n), deletes tokens that have left the battlefield (only those `moveObject` recorded leaving, `GameState.tokensLeftBattlefield` — it used to walk every object in the game, library cards included, each pass), removes +1/+1 and -1/-1 counters in pairs (704.5q — not from a permanent the same check kills, which leaves with both), enforces commander-damage loss and the legend rule — over the permanents `filter.ts`'s `supertypesOf` still calls legendary (a copy "except it isn't legendary", Aeve as a token) and no "the legend rule doesn't apply" reaches (`characteristics.ts`'s `exemptFromLegendRule`) — the player's choice of which to keep, asked (`legend-rule`, one group at a time, APNAP) before anything moves, the answers waiting in `legendRuleKeeps` so every move the check found still happens at once — offers a commander that's arrived in a graveyard or exile the command zone (903.9a — so it has died, and every "dies" trigger saw it, before its owner is asked), and sacrifices 0-loyalty planeswalkers / completed Sagas — every graveyard-bound SBA is collected first (`stateBasedGraveyardMoves`) and performed at once (rule 704.3), so a creature that dies only because its lord did waits for the next check. `concede(player)` (rule 104.3a; `whyCannotConcede` refuses before the game begins and while they owe a decision, which the server answers first) makes them lose the same way and passes on priority they held. **Winning and losing by effect** (rules 104.2b, 104.3e): `winGame` ends the game at once with the winner (104.1 — `endGame`, which also takes priority away; a multiplayer win ends it for everyone, nobody else "losing") unless `playerCantWinGame`; `loseGame` makes every player it names who can lose (`playerCantLoseGame`) lose at once (`eliminate`, the same path a state-based loss takes) and then ends the game if one player or none is left (`endIfOnePlayerLeft`, 104.2a/104.4a — only after the whole SBA sweep for state-based losses, so two at 0 life draw). Every state-based loss skips a player who can't lose. Once the game is over `applyEffectSpec` does nothing more (`ResolutionContext.gameOver`), so a resolution stops where it won. `drawCard` applies a `would-draw` `"win-game"` replacement (Laboratory Maniac — `drawWinSourceFor`, through `drawWonInstead`) before any redirect when the library is empty, winning or (unable to win) simply not drawing — and again to each draw a replacement turns it into (rule 616.2): the Notion Thief controller's draw an opponent's becomes, each of a "draw N instead". The redirects themselves are a chain (`drawRedirectFor`, `eventualDrawer` for the effect loop's empty-library stop): each Notion Thief applies to a draw once, the draw handed on to whoever it reaches next, sparing the first card a player draws in their own draw step (`exceptFirstInDrawStep`, read off `drewInDrawStepThisTurn`). `affordableTargetOptions` drops a target whose spell would cost life (Terror of the Peaks) the caster can't pay (`canPayLife`), so a cast that would be refused is never offered. `canPayLife` is the one life-payment check (rule 119.4, and 119.8's "can't lose life", which `changeLife` also honours for losses), used by every life cost; `lifeLossFromDamage` applies a `damageLifeFloor` (Angel's Grace) to damage dealt to a player. `maxHandSizeOf` folds `noMaxHandSize` and every `maxHandSize` in timestamp order (rule 613.11). `recordCastName` keeps `PlayerState.spellNamesCastThisGame`. `devotionTo` counts each token in a stack and a copiable mana-cost override (prototype, embalm). A player who loses **leaves the game at once** (`leaveGame`, rule 800.4a) and never receives priority again (`grantPriority` passes it on); during their own turn the turn goes on without an active player (800.4j: `activeHasLeft` skips their draw, attack declaration and cleanup discard): control effects they held end and what they own leaves with them — it stays where it is to be seen but is out of the game (`inGame`, which state-based actions skip; `matchesFilter`, which finds nothing a departed player owns; `moveObject`, which won't move it) — their spells and abilities leave the stack, what they control but don't own is exiled (a spell cast from someone else's cards, a permanent put onto the battlefield under their control — `ControlEffect.entered`, default control rather than an effect), their pending and delayed triggers are dropped, the monarch passes on (725.4), and what their permanents exiled "until" they leave comes back (610.3 — `returnExiledCards`, which parks an `exiled-return` `PendingEntry` while a returning card makes its "as this enters" choice). **Simultaneous leaves are one event** (rule 603.10a): the SBA sweep, a wrath (`drainPendingDestruction`), an edict's victims (every player chooses first, then all are sacrificed) and a return-all each run inside `withLeaveBatch`, and `detectTriggers` shows each leave event to the batch's already-moved permanents too (`lookBackSources`, leaves-the-battlefield triggers only) — so every one of them sees every other one leave, whatever order they moved in. A commander whose move to a hand or library the batch deferred for 903.9b carries the list as `leftWith` and completes its move inside the same batch. **Cards leaving graveyards are batched the same way** (rule 603.10a again): `moveObject` notes each card that leaves a graveyard, with a snapshot of it as it was there, and `withGraveyardLeaveBatch` — around a whole graveyard exiled, a return-all, the moves a `choose-from-zone` answer makes, an escape cost, a `simultaneous` sequence (`ctx.simultaneously`) — announces them as one `cards-left-graveyard` event once they have all moved; outside a batch each card is its own event. A batched `leaves-graveyard` trigger ("whenever one or more cards leave your graveyard") fires once per such event, matching its filter against those snapshots. **Simultaneous entries are one event too** (rule 614.12): a token batch, a return-all, a flicker's return, a tutor's finds and an O-Ring's exiles coming back each run inside `withEnterBatch`, whose members neither apply their `others-enter-battlefield` replacements to one another nor count as "already" on the battlefield for one another — a check land's `tappedUnless` included (`ConditionOptions.notYetHere`). **"As this enters" choices are asked before the move** (rule 614.12 — `askEnterChoice`: a Clone's copy, a chosen creature type or word): a permanent spell resolving (`enterPermanentSpell`), a land played, a reanimation, a blink or its delayed return, an O-Ring's return and a tutor to the battlefield each ask first and wait — a spell or land play (or a `choose-from-zone` answer) parks a `PendingEntry` in `suspendedResolutions`, an effect step parks itself and runs again — and `moveObject` applies the answer (`GameObject.enterChoice`) as the permanent enters, before its replacements and triggers look at it. **A permanent that left is read as it last existed there** (rules 603.10a, 608.2h): `moveObject` snapshots it (`takeLastKnown` → `GameObject.lastKnown`) before resetting it, and a batch's callers snapshot all of their victims up front (`snapshotLeaving`, kept on the batch and used by `moveObject` in place of its own), so the second victim of a wrath is read before its lord left; a commander whose 903.9b move was deferred keeps the snapshot of the moment it was asked. `detectTriggers` matches a departed subject or look-back source through it — `matchesWho`/`FilterContext.lastKnown` (controller, types, subtypes, counters, keywords, power), no triggered abilities if it had lost them, and the abilities it had then (`departedTriggeredEntries`: a copied card's printed ones plus its granted ones by `GrantedAbilityRef`), recording `LastKnownRefs` on the trigger. A resolving spell or ability reads a departed source, triggering object, sacrificed permanent (by stint — `lastKnownOfStint`) or target (by `targetZones` — `lastKnownOfTarget`) through the snapshot in `makeResolutionContext`: `powerOf`/`toughnessOf`/`manaValueOf`/`manaSpentOf`/`colorsSpentOf`/`controllerOf`/`cardTypesOf`/`subtypesOf`, the `target`/`trigger-object`/`sacrificed`/`source` conditions, "trigger-controller" scopes, and the damage a departed source deals (`dealDamage`'s `sourceLastKnown`: its colours for protection, lifelink, deathtouch and controller). `choose-modes` and `unless` continuations carry the refs and target zones along, and a `choose-modes` carries `sourceLost` too, so the "you may" of an ability whose source has become a new object finds no "~" (rule 400.7). `castSpell`/`activateAbility`/`whyCannot*` thread through `via` (alt cast zone) — a card with no mana cost can't be cast for it (rule 118.6), only for an alternative cost or free — `face` (multi-face cards), `xValue`, `kicked`, `sacrifice` (additional/ability costs), and evaluate `costModification`/protection/`StaticAbility.condition` gates, and the prohibitions (`whyProhibitedFromCasting` — split second, a `prohibit` effect's `turnProhibitions`, a `prohibits` static, a card's own `castOnlyIf` — and `abilitiesProhibited`, which `manaSources` honours too, so a barred mana ability can't pay for anything). **Ward** (rule 702.21) is a real triggered ability (`cards/helpers.ts`'s `ward(cost)`: a `becomes-target` trigger with a `{ kind: "ward", cost: WardCost }` effect), so it goes on the stack above the targeting spell or ability. Every spell, activated ability, copy *and triggered ability* announces the objects it targets as it goes on the stack (`announceTargeted` → `object-targeted`, whose `stackObject` is the spell or ability object; a trigger announces from `mintTriggerAbility`, skipping event-filled `autoTargetSlots`), and a `becomes-target` trigger records that as `PendingTrigger`/`GameObject.targetedBy`. `beginWard` asks *that* player to pay the one compound cost as a `choose-modes` decision carrying `ward` (mana on the decision's `cost`, life/sacrifice/discard as the mode's effect, a `counter` of the targeting object as `onDecline`), offered only when all of it is affordable; `counterObject` removes a countered *ability* from the stack. Cascade's and suspend's free casts are whole casts offered as a `cast-now` (`raiseCastNow` with `freeCastOf`): modes, kicker, a gift, targets and costs chosen as any cast's are, or declined; `castSpell` records `castVia` (and the `spell-cast` event's `via`) as `"cascade"`/`"suspend"` and gives suspend's spell `hastyUntilItLeaves`, cost increases still apply (Thalia — rule 601.2f) and a card that can't be paid for isn't offered. Cascade's `cascade` effect reveals (`Game.cascade`), then runs as a `sequence` — `offer` (the `cast-now`, its spell filter "mana value less than the cascade spell's", rule 702.85a) and `finish` (`finishCascade`: what's still exiled goes to the bottom in a random order); a suspended card's offer comes from `castSuspendedCard` at upkeep, `applyCastNow` draining `pendingSuspendedCasts` and leaving a declined card exiled, no longer suspended (702.62a). A triggered ability needing a real target choice parks in `pendingTargetedTrigger` and raises a `choose-targets` decision rather than picking synchronously. A copy of a spell whose effect lets its controller choose new targets (`copy-spell`'s `newTargets`, rule 707.10c) parks in `pendingCopyTargets` and raises the same decision with `current` — each slot's target now, kept even if it's no longer legal, and offered first; the copy sits on the stack meanwhile and its targets are announced once answered (`retargetCopy`). A copy of an activated or triggered ability (`copyStackAbility`, from `copy-ability`) asks the same way, its slots the ability's own specs judged from its source for the copy's controller (never offering a copy itself, rule 115.5); an ability countered while an `activates-ability` trigger waits on it is kept as it last was in `GameState.departedAbilities` (emptied as each turn begins). Copies made while another is being asked (storm's several — `stormCopy` copies from `lastOnStack` too, so a countered spell still storms) wait in `copyTargetsQueue`, asked one at a time in the `prepareForPriority` fixpoint (`promptNextCopyTargets`). A `discard` with `unlessOne` (Compulsive Research's "unless they discard a land card") raises the `discard` decision with `orOneOf`, any one of which is a whole answer; the `choose-from-zone` legal action carries its `destination` (and `split` for Cultivate), so a client can say where the cards go — `library-top` is the order picked. An attack tax (`attackTax` statics — Ghostly Prison) is a cost to attack, locked in before the attackers tap and paid after (rule 508.1f–j): `attackTaxPerCreature`/`attackTaxTotal`/`attackTaxPayment` (attackers that tap withheld from the payer), validated in the `attackers` decision through `DecisionReadCtx.whyCannotPayAttackTax`, and offered as `AttackOffer.attackTax` (`perCreature`, a sure-to-pay `budget` from `attackTaxBudget`) that `combat/attacking.ts`'s `withinAttackTax` trims a driver's declaration to; a creature that could attack only a taxing player isn't in `mustAttack` (508.1d). **Split cards** (rule 709, `CardDefinition.split`): `faces` is `[whole, left, right]`, face 0 the combined card off the stack (709.4) and never cast — `castableFaces` offers each half alone (709.3), and leaving the stack resets the face to the whole card. **Divided damage** (rule 601.2d): a card's `divided: { total, slot }` makes the cast carry a `division` (validated by `spellDivision`, an even split when absent), kept on the spell (`GameObject.division`, in `SpellSnapshot` so a copy keeps it) and dealt by `damage-divided`; an `any-number` group's `max` caps its members (`slotOptions`, `invalidTargetReason`). The cast offer carries `divide` for a client. **Copying a spell** (`copySpellFrom`) starts from a `SpellSnapshot` — its characteristics and every cast choice: modes, targets, X, kicker/overload/evoke paid — taken off the live spell, or off `GameObject.lastOnStack`, which `moveObject` and `forgetSpellTargets` record as a spell leaves the stack, so a copy trigger still copies a spell countered in response (Shiko and Narset, Unified). A copy of a permanent spell becomes a token as it resolves (608.3f), not "created". A copy aimed by its effect (`retargetedSnapshot`, rules 707.10d–e) is the snapshot with every non-automatic target replaced, built only if that one is legal for each slot as the copy's controller would choose it (`castTargetSpecs` reads a snapshot's specs as `spellTargetSpecs` does a live spell's); `copySpellForEachItCouldTarget` makes one per permanent it could target (Zada), splitting token stacks, and with two or more raises a `choose-permanents` whose order is the stack order. **Leaving the stack after resolving** (`leaveStackAfterResolving`, 608.2n) honours `GameObject.exileAsItResolves` (Feather): exiled instead of put into its owner's graveyard, then a `next-end-step` delayed trigger returns it (`exileAsItResolved`); beside flashback, an exile-afterwards permission, a graveyard-to-exile static or an Adventure it asks the owner which applies first (rule 616.1) as a `choose-modes` raised there — the spell waits on the stack, and `resumeSuspendedResolution` holds the resolution open around it. **Cast and play permissions from exile and the library top** (rule 601.3): `exilePermissionsFor` collects the `playFromExile` statics a card in exile answers to (Grolnok's croak counters, Haldan's fetch counters with `exiledByYou`, Tinybones' stash counters during your turn), `mayPlayFromExile` combines them with the card's own `impulse` for a land play or a `via: "impulse"` cast, and `libraryTopCastPermissions` the `castFromLibraryTop` statics the top card answers to as the spell it would be, at the X announced (`libraryTopMinX` gives an X spell's offer its `xCost.minX`, and floors every count's least X when its targets are tied to X — `xGroupOffer`); a `gainsHaste` one puts a `castRider` haste modifier on the spell, which `moveObject` keeps onto the battlefield like a prototype's. `spendAsFor` is each payment's `SpendAs` (see `mana-payment.ts`). Toxic's poison counters are given in `dealDamage`, for combat damage to a player (`toxicOf`, rule 120.3g). Casualty (rule 702.153): `queueCasualty` lists a spell's instances — printed `casualty`, granted `grantsToSpells.casualty` — once it's on the stack, from `castSpell` and `commitFreeCast` alike; `promptNextCasualty` (in the `prepareForPriority` fixpoint) asks each as a `choose-permanents` of up to one creature with power N or greater, the awaiting's `casualty`; `applyCasualty` sacrifices the one chosen, takes back the cast triggers that creature fired (`dropCastTriggersOf` — it left before the spell became cast, rule 601.2i; a token off a stack takes only its share), and queues the copy as a self-contained trigger record (a `copy-spell` of `trigger-spell`), and priority then goes to the caster. Gift (rule 702.174a) is the kicked variant of a `kicker.keyword: "gift"` card: `castSpell` queues `queueGift` (its opponents still in the game, in turn order from the caster), and `promptNextGift` (in the same fixpoint, before casualty) promises it to the only one without asking, or raises a yes-or-no `choose-modes` `about` the first candidate, the awaiting's `giftAsk` — `applyGiftChoice` promises it or asks about the next, the last one left taking it (`promiseGift` sets `giftTo` and emits `gift-promised`). The `giveGift` resolution hook reads `giftTo` / `enteredGiftTo` (as the source last existed, if it has left) and gives the `GiftKind`. Cascade's and suspend's free casts offer kicker and a gift as any cast does. `endStep` takes `phasesAfterThisCombat` front first, at the end of a combat phase or of an added upkeep step, which then goes on to the postcombat main phase. Riot is one more `nextEnterChoice` kind, applied in `enteringReplacementOf` (the counter) or as a permanent haste modifier (`gainRiotHaste`). Exert: `applyAttackerDeclarations` queues `pendingExerts`, which `prepareForPriority` asks (`promptNextExert`) before placing any trigger; `untapStep` skips and then clears the active player's `exertedBy`. An ability's divided amount is split at activation (`activateAbility`'s `division`) or as a trigger goes on the stack (`applyChooseTargets`, or evenly when nothing is asked), stored as the ability object's `division`, and passed to its resolution. `targetLegality` rechecks the relations among targets at resolution: two "controlled by different players" targets one player controls are both illegal, and a group over its `maxTotalPower` is wholly illegal. An Omen spell (one with an `omen` card's Omen face as its characteristics — the card cast as its Omen, or a copy of one) leaves the stack for its owner's library, shuffled, a copy ceasing to exist as its owner shuffles (`leaveStackAfterResolving`); a graveyard permission's `filter` and the flash check judge the face being cast (`withFace`). **Library ordering** (rule 401.4): `beginLibraryOrder` asks the order of cards going onto the top or bottom of a library together as a `choose-from-zone` with `order: true` (every card picked, the first nearest the top), skipped when there's nothing to choose between (one card, or copies of one); `applyScry` asks it for a scry's or surveil's kept cards and then a scry's bottomed ones (`thenOrder` — rules 701.22a, 701.25a), parking its `then`; a `look-and-choose`'s `"bottom-any-order"` leftover asks it once the chosen cards have moved, before `then`; a chosen card's `"library-bottom"` destination is placed in pick order, and cards it takes from a hand are announced as `cards-put-on-bottom`. A chosen card that is its owner's commander, bound from their hand for their library (Brainstorm, Valakut Awakening, Teferi's Puzzle Box), is offered the command zone first (rule 903.9b): `finishZoneChoice` parks the choice (`PendingEntry`'s `commanderAnswers`) behind a `commander-replacement` decision whose `deferredCommanderMove` is `heldByZoneChoice`, so `applyCommanderChoice` only records the answer, and the choice then moves it with the rest, to the command zone or to its picked place. An activated ability's `exileFromGraveyard` cost is `payGraveyardExileCost`: a `choose-from-zone` (`destination: "exile"`, the matching cards eligible) raised as the ability goes on the stack, whose `priorityTo` hands priority back to the activator (rule 117.3c) — as a cost's `discard` decision's does too (`costDiscardPriorityTo`, a spell's additional discard included); no more matching cards than it takes are exiled at once. `flicker`'s `tapped` returns the card tapped (`completeFlickerReturn`). A `becomes-untapped` trigger matches `permanent-untapped` but not a shock land's `asItEntered` one, its trigger object is the untapped permanent, and a token stack untapping fires it once per token; so does a `counters-put` trigger for counters put on a stack (`counter-added`'s optional `count` names how many tokens of it got them, for a batch that entered with counters and folded into a stack, and then the stack's own "counters put on this" fires for those tokens only — `mintTokenBatch` announces it, and gives a fresh stack its `stackCount` before its entering counters are announced). Tokens split off a stack fold back mid-turn once identical (`refoldSplitTokens`, see "Token stacking" above). A modal spell's chosen modes resolve in printed order as a `sequence`'s steps do: a mode that stops to ask something (a search, a discard, a choice) parks the modes after it in `suspendedResolutions`, each with its own target slice, so they wait for the answer (rules 608.2c, 700.2 — Insatiable Avarice's draw finds the card its search put on top). `exchangeLifeToughness` is rule 701.12g's exchange (neither half when a can't-gain or can't-lose effect stops the life half, 701.12a); `putCostCounters` pays an `AbilityCost.addCounter` — straight on, no counter replacement — by hand and through `useManaSource`, where `manaSources` admits such an untapped once-a-turn mana ability as a last-resort source (a plan step's `counterCost`); a cast records its `castFrom` as soon as it's on the stack, before its costs are paid, so `manaUnitCanPay` can answer a `fromYourGraveyard` restriction (Lord of the Forsaken). Cycling (`cycleCard`) is an activated ability from the hand (rule 702.29a) — so `whyCannotCycle` refuses it under a split-second spell (702.61a) or a can't-activate prohibition, as for any non-mana ability: cost paid and card discarded as it's activated, then an ability object sourced from the cycled card — its `grantedAbility` a `cycling` ref, resolved through `cyclingAbilityOf` (the draw, or landcycling's revealed search) — goes on the stack, so it can be responded to, and a `this-cycled` trigger (the card the event's subject, wherever it went, contributing only those abilities) goes on above it and resolves first (rule 702.29c). `graveyardGrantsFor` offers a card's own `castFromGraveyardIf` permission (Gravecrawler) as it does a one-shot one, spending nothing. `beginZoneChoice`'s `"command"` zone is the chooser's own commanders in the command zone (Command Beacon, Hellkite Courser), and `putInCommandZone` returns a commander still on the battlefield there. `putArrivedOntoBattlefield` puts a batched graveyard trigger's cards onto the battlefield; `beginZoneChoice` takes a `picker` who chooses from another player's zone (Tasigur). `payExileFromGraveyardCost` asks with a `choose-from-zone` (`destination: "exile"`, `priorityTo` the activator); an activated ability's "X target …" group is offered once per X and checked at the X activated with (`specsAtX`). `votesFor` counts this resolution's `modes-chosen` answers for its source; `revealUntilCount` and `putOntoBattlefieldTogether` serve `reveal-until-count`. `activatedGrantSources` also reads a `grantsActivatedOfLinkedExile` static: the activated abilities of the cards exiled with that stint, each with a `card-activated` ref. `endWhileSourceEffects(ids)` ends every modifier and control effect that lasted while one of `ids` remained on the battlefield; `moveObject` calls it as the source leaves — or, inside `withLeaveBatch`, once the whole batch has left (`leaveBatch.endsWhileSource`), so the event's look back (rule 603.10a) still sees the effects. It ends what lasted for the stint that left even if the source is back by then (a blink within one event — a new object, rule 400.7). `lastingHere(duration)` (in the resolution context) turns a `PtDuration` into the stored `EffectDuration` with the resolving source's stint for `"while-source"`; `gainControlByEffect`'s `opts.whileSource` drops only the same player's effects that end no later than the new one. `untapUnlessStunned(id)` is every untap — the untap step's, `untapAll`'s, `setTapped`'s — so a stun counter is removed instead (rule 122.1d). It emits `POOL_CARDS` and `TOKEN_CARDS` as well as the combined `BUILTIN_CARDS`, because the directory is the only record that a definition is a *token* — nothing on `CardDefinition` says so. `cards/classify.ts` reads them back as `isTokenCard` (rule 111.1 — a token isn't a card), `isCardFront` (rule 712.3 — a DFC is one card, deck-listed under its front face) and `isDeckableCard` for the two together; `deck-validation.ts`, `card-replacer.ts`, the library page and the deck builder's pool all filter on these rather than guessing from the name. `cards/pool.test.ts` fails if a card isn't wired into `generated.ts`, or if the pool/tokens split drifts. The same run writes the pool a second way, for the web client: 32 shard modules under `cards/shards/`, each card in the shard its name hashes to (`cards/card-shards.ts`: `cardShardOf`, and `loadCardShard`, whose literal `import()` per shard is what gives each shard its own file in a bundle), plus `cards/generated-index.ts`, what a page can know without loading any card: `TOKEN_NAMES` (what `isTokenCard` reads, so classifying a definition never imports every token) and `PINNED_ART` (a card's pinned printing, for drawing a commander from its name alone). The codegen reads each card's name and art from its source — `defineCard({ name, … })`, or a helper whose first argument is the name — and `pool.test.ts` checks both, and every card's shard, against the real definitions. The engine's `package.json` declares **`"sideEffects": false`**, which is what lets a bundler leave out every card module a page never reaches: each card file's `defineCard(…)` call would otherwise count as an import-time side effect, and the whole pool would ship with any page that touched the engine's barrel. It holds because no engine module does anything at import time but define things; keep it so. **`cards/AUTHORING.md` is the hand-authoring guide** — every field, the effect/target/ability/static vocab, worked examples, current limitations; read it before authoring a new card. `Game.debugSpawn(name, player, zone)` is the sanctioned white-box "put a card straight into a zone" helper, going through the real `moveObject`. `Game.debugMove(id, zone)` moves an object that already exists the same way, announcing nothing (the scenario builder laying out a board, `server/src/builder.ts`). `CardDefinition.toxic` is Toxic N as a number, not a `Keyword` (it's cumulative), and `casualty` is Casualty N. `CardDefinition.omen` marks an omen card (rule 720, `faces: [creature, Omen]`), resolved as an Omen into its owner's library. Keywords `infect` and `wither` (rules 702.90, 702.80 — damage as -1/-1 counters and poison, in `Game.dealDamage`), `skulk`, `flanking` (with the `flanking()` helper for its trigger) and `riot` are in the union; `StaticAbility.exertAsItAttacks` is "you may exert this creature as it attacks", and `castFromGraveyard.exileOthers` a permission's "by exiling N other cards from your graveyard". `helpers.ts`'s `GIFT_KICKER` (`{ cost: "", keyword: "gift" }`) and `giftTrigger(gift)` ("when this permanent enters, if its gift cost was paid, …") are gift, rule 702.174. `CardDefinition.castFromGraveyardIf` is "you may cast this card from your graveyard as long as …" (Gravecrawler — rule 113.6f).

- **`identity.ts`** — `colorIdentityOf(def)` (rule 903.4 — a lexical `{…}`-symbol scan of the mana cost + all rules/ability text) + `withinIdentity`/`identityString`. Consumed by `deck-validation.ts`.
- **`deck-validation.ts`** — `validateCommanderDeck({commanders, cards, size}, registry)` → `{legal, violations, identity}`: singleton (basics exempt), colour identity, deck size, a commander that may command (`canCommandAlone`, rule 903.3: a legendary creature, Vehicle, or Spacecraft with P/T, or a card whose declarative `canBeCommander` says it can be your commander — a planeswalker without it can't), a legal pair for two commanders (`pairingProblem`/`canPairCommanders` over each card's declarative `pairing` — never its rules text — and also what the deck builder's commander toggle asks: two plain Partners, two "Partner with"s naming each other, two same-text "Partner—[text]"s, "Choose a Background" + a legendary Background enchantment, "Doctor's companion" + a lone Time Lord Doctor; a Background is a commander *only* as that second half, and `canCommandAlone`/`isBackground` are exported for callers that pick commanders), and "is actually a card" (`cards/classify.ts` — a token or a DFC back face is a registered definition and would otherwise pass every other check). Only checks *implemented* cards. Lives in the engine (it originated in `server/`) because it's pure synchronous logic over `CardRegistry` data — the client's deck builder needs the same rules with no network round-trip.
- **`sample-decks.ts`** — `SAMPLE_DECKS`: fourteen real Commander precons, each a legal 100-card deck — first the five Tarkir: Dragonstorm decks (`TDC`, the bots' defaults since 2026-09-30, so the server's seats take the first four), then the five 2022 Starter Commander Decks and Tramplesaurus Rex, Reign of Dragons (`FDC`), Family Matters (`BLC`) and World Shaper (`EOC`). The record of every swap and why is `docs/plans/precon-decks.md`. One source of truth for two consumers: `server/src/decks.ts`'s `SEATS` (a seat's fallback deck — the first four, one per seat) and the client deck builder's "starter decks" (all five).
- **`card-replacer.ts`** — `suggestReplacements(target, context)` → up to three implemented `BUILTIN_CARDS` stand-ins for an unimplemented card, best first, each with a `confidence` (`high`/`medium`/`low`) and the `sharedTags` behind it. `assignReplacements` does it for a whole deck at once, and is what the import uses: the Hungarian algorithm over every missing card's candidates, so a stand-in two cards want goes to the one with the most to lose. Pure and synchronous. `target` is what Scryfall says about the missing card (name, mana cost, type line, power/toughness, keywords); `context` is the destination deck — `identity` (only cards inside it), `exclude` (never a card the deck already has, so singleton holds), `forCommander` (only legendary creatures/planeswalkers) — plus an optional `OracleTagIndex`. **Role matching runs on Scryfall Tagger oracle tags**: `createOracleTagIndex(data)` wraps the server's generated index, and similarity is an IDF-weighted cosine over the tags two cards share (a rare shared tag says more than a common one). A candidate must share a primary type with the target (instant/sorcery count as one) unless the tags say they do the same job; a land only replaces a land. Score = tags, then type, a steep mana-value closeness (so a finisher isn't replaced by a two-drop that shares a mechanic) and, for creatures, body (P/T and combat keywords). Without tags only the latter count and confidence is always `low`. The engine does no I/O; the index lives server-side. Design record and measured results: `docs/plans/card-replacer.md`. Also exports `parseTypeLine`.
- **`zone-choice-together.ts`** — `ZoneChoiceTogether` (`rule: "share" | "one-each"`, per-card `tags`, a client `text`) and the pure `fitsTogether` / `togetherViolation` / `completeTogether` over it: a rule a `choose-from-zone`'s picks must obey as a set, raised by a `search-library`'s `together` (`SearchTogether` in `effects.ts` — Myriad Landscape's "that share a land type", Krosan Verge's "a Forest card and a Plains card"). `Game.searchTogether` works the tags out as the search is raised (each card's land types, or the slots whose filter it matches), so checking a set needs no registry — the validator, the bots and the client (`engine/client` exports `fitsTogether`) share it. `view.ts` empties `tags` for every viewer but the searcher: they say what kind of card each library card is.
- **`filter.ts`** — `CardFilter` + `matchesFilter(state, registry, id, filter, { you })`: a pure predicate over an object + its *computed* characteristics (`targets` — a `SpellTargetsFilter` on what a spell on the stack targets: one target, or with `only` every target, being a player (`player`) or a battlefield permanent matching `permanent` and being or not being the filter's `source`, `single` for all one object; a target that has changed zones since it was targeted no longer counts, rule 400.7 — used by cast triggers, a `deals-damage` source filter and `spell` target specs; `type`/`types`/`notTypes`/`subtype`/`subtypes`/`supertype`/`name`/`colors`/`notColors`/`colorless`/`manaValue`/`power`/`toughness`/`controlledBy`/`ownedBy`/`keyword`/`tapped`/`token`/`enteredThisTurn`/`attackedThisTurn`/`damagedThisTurnBy`/`excessDamageThisTurn`/`dealtDamageToCreatureThisTurn` (a `DamageHistory` `dealDamage` keeps on `GameObject.damageThisTurn` as it damages a permanent: each source as it was then, and whether any of it was excess, rule 120.4a)/`goaded`/`suspected`/`putIntoGraveyardFromLibraryThisTurn` — the last read off `GameObject.putIntoGraveyardFromLibraryOnTurn`, which `moveObject` sets on a library-to-graveyard move and clears on any other, ANDed). Off the battlefield it degrades to printed values — unless the caller asks for last-known information: `FilterContext.lastKnown` (a trigger filter matched as a permanent leaves — its `GameObject.lastKnown`, or `GameState.ceasedTokens` for a deleted token) or `FilterContext.snapshot` (a `LastKnownInfo` the caller picked out), and then every clause reads the snapshot through the same code path. `FilterContext.castX` judges a card not on the stack as the spell it would be with `{X}` announced at that value (rules 601.3e, 202.3e): its mana value counts it — a cast permission's filter, Glarb, Calamity's Augur's "mana value 4 or greater". `sharesCardTypeWith: "sacrificed" | "trigger-object"` is bound to a plain `typesAnyOf` by `bindDynamicCompares` (the sacrificed permanent's types as it last existed, or the trigger object's — Baral and Kari Zev's "shares a card type with it") and matches nothing unbound; `sharesCreatureTypeWith: "trigger-object"` the same way, to a `subtypes` of the trigger object's creature types, changeling marker included (Heirloom Blade). Clauses about a card's own properties: `basePower`/`baseToughness` (after layer 7b — `Characteristics.basePower`), `hasManaAbility` and `hasAbilities` (`characteristics.ts`'s `hasManaAbility`/`hasAnyAbility`, granted abilities included), `xInManaCost`/`coloredManaSymbols` (the up face's own mana cost — a transformed back face has none), `cardTypeCount` and `nameDiffersFromEach` (an inner filter over the battlefield, rule 201.2c). Subtype clauses ask `subtypes.ts`'s `hasSubtype`, so a changeling matches every creature type, and `ofChosenType` reads the chosen creature type of the `FilterContext.source` (static scopes, trigger filters and a `look-and-choose`'s filter pass one — Herald's Horn); a source that has left the battlefield is read through `lastKnown.chosenCreatureType` (rule 608.2h), since the move cleared its choice. The shared "which objects" vocabulary for mass effects, tutors, and filtered triggers — `ZoneChoiceFilter` is an alias. A numeric clause's `n` may be a `DynamicOperand`: `{ own }` (the matched object's own power/toughness/mana value) or `{ amount: EffectAmount }`, answered by `FilterContext.amount` — `Game.filterAmounts` supplies it to target filters (via `TargetSource.amount`, rechecked on resolution) and trigger filters, and `applyEffectSpec` binds an effect's filters to plain numbers as that effect applies (`bindDynamicCompares`); with nothing to answer it, the comparison fails closed. Answers type/subtype/colour clauses lazily via `effectiveTypes`/`effectiveSubtypes` (layer 4 alone — `characteristics.ts`'s `layerFour`) and `effectiveColors`; only a `power`/`toughness`/`keyword` clause needs the full characteristics fold (kept cheap deliberately — a `StaticAbility.condition` re-runs `matchesFilter` over the whole battlefield on every read). `FilterContext.layered` is how a static's `filter` scope is matched from *inside* the fold computing its target: types/subtypes/keywords as folded so far, and a power/toughness clause fails closed. Also the shared **weighted** scan behind "other" and aggregates: `weightedMatches` weighs each permanent by its `stackCount` and drops one permanent per excluded id (so "other" beside a stacked source leaves the rest of the stack counted), and `AggregateSpec`/`aggregateOver` sum or max power/toughness/mana value over it — the `EffectAmount`, the `aggregate`/`source-greatest`/`controls-greatest` `StaticCondition`s and the `CostReductionAmount` all read through it. `greatestAmongItsController: { of, among }` is "with the greatest power among creatures that player controls" — a per-controller maximum, ties all matching, never inside the fold (Crackling Doom, Soul Shatter, Will of the Abzan).
- **`goad.ts`** — `goadersOf`/`isGoaded`: every player who has goaded a creature (rule 701.15), whichever way — a one-shot goad (`GameObject.goadedBy`, until the goader's next turn), one for the rest of the game (`goadedForGameBy`), or a static one (`StaticAbility.goads` — Baeloth Barrityl, an Aura's "enchanted creature is goaded" — read live, its source's controller the goader). The attack checks, the `goaded` filter clause and last-known information (`LastKnownInfo.goaders`) all read through it, so a goad is never asked about half-way. Goaded is a designation, not an ability: nothing here is in the layer fold.
- **`subtypes.ts`** — subtype lists and their two markers, `EVERY_CREATURE_TYPE` (changeling, rule 702.73a) and `EVERY_LAND_TYPE`: one entry standing for every type of its kind, so a changeling's list is `["Shapeshifter", EVERY_CREATURE_TYPE]` rather than ~300 names in every snapshot, mana unit and type line. **Every subtype question goes through `hasSubtype(list, subtype)`, never `includes`** — filters, lords, amass, mana provenance. Asked *for* a marker it means "any type of that kind", which is how "shares a creature type with" a changeling works (Path of Ancestry). `withoutTypeMarkers` is what a type line shows (`viewFor` strips them; the changeling keyword icon says it instead). Changeling adds its marker as the first step of layer 4, in every zone (`characteristics.ts`'s `withChangeling`); an effect adds either marker as an ordinary `addSubtypes` entry.
- **`target-polarity.ts`** — which side of the table a target belongs on, for the bots. `slotPolarities(effect, count)` reads each target slot of an effect tree as `harm` (bad for whoever controls the target), `help`, `take` (yours whoever's it is — reanimation, a copied spell) or `either`, through a rule per effect kind that is **total over `EffectSpec["kind"]`**, so a new kind fails the build until someone says which side it belongs on; effects that rebind target 0 (`look-and-choose`, `reveal-top`, `reveal-until`, `choose-permanents`) or choose their own (`reflexive-trigger`) aren't descended into. The strongest effect on a slot decides: removal and theft outrank the consolation they give their victim (Swords to Plowshares' life, Generous Gift's Elephant), a major effect a minor one (Sign in Blood's cards outrank its life). Every query takes an optional `PolarityBias` (a deck's own reading of some effect kinds, from `deck-bias.ts`), which overrides the rule for each slot those kinds touch. `castPolarities`/`abilityPolarities` (memoized per definition, one memo per bias), `auraPolarity` (an Aura's `attached` statics, `controlEnchanted`, Curses), `offerPolarities` for a `legalActions` cast or activation, `pendingTargetPolarities` for a `choose-targets` decision (reflexive, chapter and announced-modal triggers included), `specSide` (a spec that names the side is the card choosing, not something to second-guess), and `targetValue`/`rankTargets`/`onlyWrongSide` — a cheap static value that orders a slot's options best-first (a targeted `lose-game` harms its target). 98.6% of the pool's targeted slots classify. No `bot/` import, so decision modules may use it. See `docs/plans/bot-effect-knowledge.md`. A `look-and-choose` over `"targets"` and a `cast-now` from them take every slot; a `damage`'s or `damage-all`'s `from` target is the caster's (help).
- **`effect-worth.ts`** — the other half of `target-polarity.ts`: once targets are chosen (or where there are none), what doing an effect is worth to one player, as a coarse signed number (a card about 2, a point of life a quarter of one above 15 and three quarters below, removal 4). `effectWorth(effect, {state, me, controller, targets, source?, triggerObject?, triggerPlayer?})` reads the targeted slots through `slotStrengths` against the targets as chosen, and the untargeted parts off the effect's player scope for the kinds nearly every optional clause is made of (draws — a draw the library can't cover reads as losing —, life, discards, sacrifices, tokens and token copies of our own, tutors, recursion, a sacrifice-source); anything else is 0, unknown rather than bad. Something done to an opponent is split across the opponents. `costWorth` prices a choice's mana, life and energy. What v1 answers a "you may", a punisher's "unless", a villainous or modal choice, and which activated ability to use with; it only has to get the sign and the order between a cost and what it buys right, since v2 searches each of those and keeps v1's answer only when nothing beats it. Targeted slots read with `me`'s deck bias. No runtime `bot/` import. `win-game` and an untargeted `lose-game` outweigh everything (±100, as decking does), so a pact's upkeep payment is paid whenever it can be.
- **`scry-pick.ts`** — what a bot scries or surveils away (`scryAway`), judged top card first, each knowing what was kept above it: a land stays while the bot has fewer than seven among its battlefield, its hand and the lands kept above, or when it makes a colour the bot can't make (lands in hand counted as made); a spell goes when its mana value is more than three beyond the bot's lands and mana rocks (two fewer for a colour it can't make); surveil also bins a card castable from the graveyard. v1's answer, and v2's in a tie — which is nearly always, since a scry changes the next draw and a rollout to the end of the turn rarely reaches it. No `bot/` import.
- **`land-colors.ts`** — which colours a bot needs (its commander's identity, or with none the coloured pips in its hand) and has no permanent to make (`missingColors`, from printed mana abilities and basic land types), and `newColorsFirst`, which orders a choice among lands alone so those making a missing colour come first: v1's `chooseFromZone` and v2's capped candidate order (`byManaValue`) for a fetch, a Cultivate, a Farseek; and `colorToName`, the colour v1 names for "as this enters, choose a colour" (Valgavoth's Lair, the Thriving lands — asked as a creature-type choice over colours, `allColors`): within the commander's identity, the one the hand's pips want most, ten times over when nothing in play makes it. A permanent that taps for its chosen colour reads as making that colour once it has one. No `bot/` import.
- **`deck-bias.ts`** — what a deck wants that the bots' generic card knowledge gets backwards: `COMMANDER_BIASES`, keyed by commander name, each entry a `why`, a `polarity` (`PolarityBias`: effect kinds whose target slots the deck aims the other way — Teval's `mill: "help"`) and `ownWeights` (evaluation weights for the deck's *own* features only; opponents stay on the shared ones). `deckBias(state, player)` reads the commanders the player owns off the `GameState`, merges a pair's entries, and caches the answer per `state.objects` table (once per game, once per search clone), so v1, v2, every seat of v2's rollouts and a person's own Teval deck all get it without being told; `polarityBias` is the polarity half. Each entry is pinned by a gate scenario that fails without it. Only a type import from `bot/`. See `docs/plans/deck-biases.md`.
- **`this-way.ts`** — `thisWayEntries(state, what, since?)`: what the resolution under way (`GameState.resolutionSince`) has discarded, drawn, milled, sacrificed, destroyed (a destroy effect, not a death), destroyed and put into a graveyard (`"died"`), exiled, returned to a hand, put into a graveyard or put onto the battlefield from a zone, read off its own events — each object with whose it counts as, whether it left the battlefield doing so (so it's read as it last existed there) and how many tokens a stack that went whole stood for. Pure over `GameState`, so `filter.ts` can use it too: behind the `thisWay` amount, the `this-way` condition and the `thisWay` / `notThisWay` filter clauses ("a creature card milled this way"; Martial Coup's "all other creatures" after its Soldiers). `"put-on-bottom"` reads `cards-put-on-bottom`: the cards a choice put from a hand on the bottom of a library (Valakut Awakening's "draw that many"). `"tapped"` reads `permanent-tapped` events, a stack tapped whole as each of its tokens.
- **`token-fold.ts`** — the pure half of `Game.refoldSplitTokens`, folding tokens split off a stack back together mid-turn (docs/plans/token-stack-choices.md, "Folding back"). `exactTokenShape(o)`: a token object as one key-sorted JSON string minus `id`, `stackCount` and `splitFromStack` — stricter than `state.ts`'s `tokenFoldKey`, which the end-of-turn fold compares, because mid-turn what happened to a token this turn (attacked, damage dealt to it, abilities used) still tells it apart. `referencedObjectIds(state)`: every object id the rest of the state names — other objects' fields, delayed triggers, shields, anything waiting, and the `turnHistory` lists read by matching each entry's object (what entered, attacked, died, was sacrificed, exiled) — leaving out the zone lists, the event log, each object's own `id`, cards in a library, the snapshots of things that left a zone (`lastOnStack`, `lastKnown`, `earlierLastKnown`, `ceasedTokens`, `departedAbilities`: read only by something already waiting, and the fold runs once nothing is) and the history kept only to count (`damageDealt`). A named token is never folded away, only into; and a token that attacked this turn isn't folded mid-turn at all, since `turnHistory.attackers` counts each creature once by object and a second combat would count a token split off a folded stack again (Windbrisk Heights). Tested by `token-stack-refold.test.ts`.

- **`mana.ts`** — `Color`/`ManaType`/`ManaPool`/`ManaUnit`, `parseManaCost` (generic, `{X}`, `{C}` colorless, hybrid `{W/U}`, twobrid `{2/W}`, Phyrexian `{W/P}`, snow `{S}` folded into generic), `manaValue`, `poolTotal`, `poolCounts`. **A player's mana pool is a list of `ManaUnit`s, not a count per colour** (`poolCounts` rebuilds the count view for the player view and the payment planner): a unit carries where it came from — a `ManaRestriction` on what it may be spent on (rule 106.6b — Cavern of Souls; or, with `notSpell`, a deny-list — "can't be spent to cast nonartifact spells", which pays for anything but such a spell, abilities and ward costs included), a `ManaSpendRider` that fires when it's spent (Path of Ancestry — its trigger object the spell it paid for, "that spell" as a `"trigger-spell"` fixed as the rider is placed: Primal Wellspring copies it even once countered), `persists` for mana that survives the end of a step (Savage Ventmaw), `uncounterable` for "and that spell can't be countered", `from` for what made it (a `ManaOrigin` — the source's types, subtypes and supertypes as it made the mana, which a spell keeps as `GameObject.manaSpentFrom` and the `manaFrom` filter clause reads: "if mana from an artifact was spent to cast it") — and a count can carry none of it. The pool is empty almost all the time, since the engine auto-pays; it fills only when someone activates a mana ability by hand, which is exactly where an untagged pool would drop the restriction. The restriction is enforced twice on purpose: `planManaPayment` won't *tap* a source whose mana couldn't pay for the thing being paid for, and `spendFromPool` won't *spend* such a unit — and the latter spends restricted units first, because an unrestricted one can pay for anything later in the same cost. `ManaRestriction.fromYourGraveyard` is "spend this mana only to cast a spell from your graveyard" (Lord of the Forsaken).
- **`controller.ts`** — `PlayerController.act(view)` is the single entry point: when `view.state.awaiting` is set it must return that declaration, otherwise any legal priority action. `AutomaticController` always passes/keeps its hand. `ScriptedController` plays a queue plus assignable `*Fn` callbacks (what tests use). `RandomController` picks uniformly from `legalActions()` — the engine's fuzzer (see `random-demo.mjs`); it builds the six priority actions itself and gets every *decision* answer from that kind's `decisions/` module via `randomAnswerFor`, handing it a `RandomSource` (`random`/`pickIndex`/`pickTargets`). One fuzzing guard, not a rule (`idleRepeat`): an `{X}` ability that can only be activated for X = 0 isn't activated again while one is on the stack — Helix Pinnacle's is free and legal any number of times, and uniform picks stacked it without end. **The exact sequence of draws against that source is what makes a seed replay identically**, so changing the order or count of calls in one of those arms silently re-points every fuzzer seed. `HeuristicBotController` extends `AutomaticController` with a v1 "plays a sensible game, not a good one" policy (land first, else the highest-mana-value affordable spell, else a **non-mana** ability, else pass; attack with every eligible creature, each at the lowest-life defender *it* may legally attack that can't profitably block it (`defendersFor` — goad and "can't attack you" differ per creature — and `wouldDieAttacking`, a crude "can anyone there kill it" check; a creature every defender could eat stays home — unless everything at one player is lethal through their blockers, `wideLethal`, when it all goes there); block favourable trades and chump-block lethal), owning its own `CardRegistry` so it can read mana values and computed P/T. It **aims** by `target-polarity.ts` ("v1.5"): each slot's target is the best on the side its effect belongs on — removal at the opponents' most valuable permanent, a pump at its own best creature, an "up to one" help with only opponents to point at left empty — for casts, activations, trigger targets (`chooseTargets`), an Aura entering without being cast (`chooseEnchant`) and a Clone's copy (`chooseCopy`: the most valuable, never a legend it already controls); and it leaves alone a spell or ability whose only legal targets are on the wrong side (a counterspell with only its own spell on the stack), unless the spec names that side. It used to take the first legal target — players in turn order, then the battlefield oldest-first — and hit its own side 22% of the time; aimed, it benches 30.0% against three unaimed copies at four players (even 25%). Its other choices read `effect-worth.ts`: a "you may" or punisher is taken when what it does (less its cost) beats what declining lets happen, a modal choice takes its best modes, a sacrifice or an edict gives up the cheapest permanent (`targetValue`, a token below a card), a discard throws surplus lands and what the board can't cast soon (`chooseBottomOfHand` with the lands in play), and of the abilities it could activate it takes the one worth most, never one worth less than nothing — Viscera Seer's scry for a creature, a life payment down to nothing. Mana abilities are never activated on their own (`isManaOnlyAbility`): casting auto-pays, so floating mana gains nothing, strands the source, and — once bot moves are paced out one at a time — shows up as a land flipping sideways for no reason between a spell being cast and that spell resolving. Already-attached Equipment is re-equipped only onto a creature ranking clearly above its host (`targetValue` beyond `REATTACH_MARGIN` — Greaves onto the six-drop just cast), so a move can never undo itself, and one ability of one permanent is activated at most `MAX_ACTIVATIONS_PER_TURN` (4) times a turn — without both, Lightning Greaves' Equip {0} kept a bot in one main phase forever. It's the base class of both searching bots (`bot/` below) and the fallback under them, so every decision their search doesn't improve on is still this — including, now, the opening hand: `mulligan`/`chooseBottomOfLibrary` are overridden here and delegate to `bot/mulligan.ts`. Its land drop (`bestLand`) plays the land that lets it cast the most different spells this turn (looking past a colour the land asks for as it enters), then one that enters tapped as things stand (`entersTapped`: always, or a check land whose condition fails now — a tapped land costs nothing on a turn the untapped one casts nothing more); "cast" counts only what it would cast (`wouldCast`, the filter `act` casts from — Sticky Fingers with only an opponent's creature to enchant doesn't count), then the one unlocking the most coloured pips in hand no land in play pays; it asks the engine through `ControllerView.legalActionsAfter` (optional — what would be legal after an action, or several in order, on a throwaway copy; `Game.controllerView`, the live rooms' view, offers it, and the bot tools use that view too), so a view without it falls back to pips alone. v2's land search takes v1's land first, so it wins every tie. A scry or surveil (`chooseScry`) sends away what `scry-pick.ts` says to — v2's search rarely reaches the next draw, so it ties to this too. A creature that sacrifices itself to fetch a land (Sakura-Tribe Elder) is due at the end step of the player whose turn comes right before ours, with fewer than seven lands (`isCreatureFetchDue`); v2 takes it then without weighing it, as it does a fetch land, since the evaluation kept the 0/2 over the land. A land that taps for mana and also fetches (Bountiful Landscape, `isManaLandFetch`) is held until that same end step and cracked there, both bots: cracked in its own turn, it cost that turn's mana and its fetched land sat tapped (a live capture). `engine/src/test/heuristic-bot.test.ts` runs bot-vs-bot games to completion as a second fuzz target. `ControllerView.targetFacts` (built by `Game.controllerView`) is what the choosers narrow relations among targets by; `RandomController.pickTargets` keeps a group within its `min` (topped up in order, no extra draws) and its `maxTotalPower`. - **`bot/`** — the searching bot, **v2** (`EvalBotController`), which `Room.addBot` seats; design records `docs/plans/smarter-bots.md` (the search) and `docs/plans/bot-effect-knowledge.md` (the plan of record — read it before changing how a bot picks actions). A v3 that planned whole turns over sampled worlds was built, benched and retired (`docs/plans/bot-v3-search.md` records why); what survives of it is `determinize.ts` (sampling plausible completions of the hidden information — v2 still reads the real hands) and `simulate.ts`'s `"playing"` policy (`simulateTurns`), which `bot:audit --rollout` prices a card with. One-ply search: enumerate the concrete actions available now (`candidates.ts`), play each against a throwaway `Game.fromSnapshot` copy (`simulate.ts`), score the result and take the best. Candidates are capped (8 target combinations an action, a dozen rollouts a decision), so each slot's options are first ranked by `target-polarity.ts` (`aimOffer` in `eval-bot.ts` — the right side first, most valuable first, the wrong side last rather than dropped): unranked, the cap cut to the battlefield's oldest permanents, and on a four-player board v2 never saw a threat newer than the turn-one lands. A targeted modal spell is tried in each choice of modes (as many as allowed, each mode alone, then the other combinations, capped) with its X at the maximum; it used to be tried only as every mode at once, and without an X — which the engine reads as 0. `features.ts` computes one player's raw unweighted feature vector (for the bot's own seat, `untappedCreatures` counts only creatures that would hold an attack off — able to block one an opponent could attack it with and kill it or survive it (`deterringBlockers`), so a lone 2/2 isn't kept home against nothing or against 3/3s it could only chump — and blockers too small to hold one off alone count in gangs that kill an attacker together (two 1/1s against a 2/2), as many as the one opponent with the most attackers would take, since opponents attack on separate turns and blocking taps nothing; and a subtracted `threat`: opponents' creatures by the combat damage they could turn on it — only those the attack rules would let attack it at their controller's next combat (`combat/eligibility.ts`'s `playersAttackableNextTurn`: tapped and summoning sickness ignored, a Vow of Duty, a goad by us or Pacifism honoured) — in full from whoever attacked it within the last round — `PlayerState.lastAttackedBy`, recorded as attacks are declared — and as a share of the life, or commander damage, it has left, with this turn's damage credited back as far as the life above 20; the worst commander damage taken itself counts squared over 21, so 21 is still 21 and a first hit is cheap), `drawEngines`, priced by the cards each engine draws a round of the table (`drawRate`: Phyrexian Arena 1, Rhystic Study half a card per opponent, capped at 3), `tokenEngines`, the creature tokens a round its permanents keep making, rated the same way (`tokenRate`: Hero of Bladehold 2, Elspeth, Sun's Champion's +1 3; not a one-shot like Beetleback Chief, nor an ability that costs loyalty), and `answers`, the counterspells in its own hand that its untapped mana could cast: a reserve casting one (or tapping out) gives up, so it counters a Craw Wurm or a Rhystic Study and lets a Signet through and `evaluate.ts` is `EvalWeights` plus a dot product over it (the bot's own features scored with its deck's `ownWeights` laid over them — `outcomeOf` reads them from `deck-bias.ts`; one-shot tokens that sacrifice themselves, Treasure, Clue, Food, are `resourceTokens` at 0.5 rather than full `otherPermanents`, and a mana rock's ongoing mana counts at `nonlandMana` 0.5, since 2026-10-02's behaviour sweep found Sol Ring held rather than paid for with a Treasure) — split apart so the weights can be **fitted** by logistic regression over harvested self-play positions rather than hand-picked. Combat is built one attacker/defender pair at a time — a token stack in parts: one more token, the fewest that finish a planeswalker, or all it has left, smallest first — and never enumerated (`combat-math.ts`, `eval-bot.ts`), its moves ranked before simulation by arithmetic that prices life with the evaluation's bend (`features.ts`'s `lifeCost`); before the climb, `alphaStrike` looks for a kill — as many opponents as the attackers can kill at once, trying each order of the killable ones and giving each the fewest attackers its kill needs, a token stack counted token by token and split between defenders where that kills more — when the attackers' total damage covers every killable opponent's life, the subset of up to 10 attackers that kills spending the least damage, so 3+2 and 3+2 kill two opponents at 5 where biggest-first 3+3 left 2+2 short — then the most kills that survives the crackback; blocks are climbed one blocker at a time from v1's, plus two kinds of paired move — two blockers at once against menace, and a double block where neither blocker kills the attacker alone but the two together do (the estimate letting the attacker kill only what its damage reaches, best first); `decisions.ts` searches the decisions the engine raises mid-resolution. `scenarios.ts` is the opponent-independent gate (hand-built positions with a known right answer, parameterised by a weight vector) — `gate` scenarios every shipped vector passes, and `training` ones it may still get wrong, kept to tune against; most are written as a `position` (the board and a judge of *any* answer) rather than a script. `scenario-fit.ts` records one: every answer v2 simulated there (`EvalBotOptions.trace`) and the state its rollout reached, read into features by `evaluate.ts`'s `outcomeOf`. A priority window's rollouts never read the weights (v1 plays them out), so its choice under any vector is replayed exactly by `scoreOutcome` — which is all `evaluateState` is — and `leversFor`/`handTune` ask what single weight would fix a wrong scenario and what that breaks. `champions/` holds the frozen gauntlet opponents, each spelling out its whole `EvalWeights` literally so it can't drift when the defaults change. `bot/mulligan.ts` is the opening-hand policy both share (hooked onto v1, since a mulligan has no board to roll forward): a hand is scored on mana sources plus its cheapest few castable spells, ramp counting for both, and the bar it has to clear *falls* as the hand it would keep gets smaller — with a free Commander mulligan raising it instead, and a floor at four cards. `EvalBotOptions.timeBudgetMs` is a wall-clock ceiling on one decision, **off by default** because a clock breaks the engine's same-seed-replays-identically guarantee that tests, the fuzzer and the tuner all rely on; only `Room.addBot` turns it on. When it expires the search plays the best candidate found so far, and `pass` plus v1's own pick are scored first precisely so that an expired search degrades to v1-quality play rather than to whatever `legalActions` happened to enumerate first. The clock stops a search *predictively* — once the running mean simulation no longer fits, but never before those two baselines — and one deadline covers a whole attack declaration. Twin targets — tokens nothing tells apart (`state.ts`'s `tokenFoldKey`, shared with the token fold, plus combat, damage and anything pending that names one) — are cut to as many as the offer has slots before the cap (`bot/twins.ts`), so seven identical Treasures are one simulation and the cap goes to real alternatives. An until-end-of-turn pump, keyword grant or animation is not a candidate where it can't matter — outside combat, outside its own first main phase, with nothing on the stack (`HeuristicBotController.wastedNow`, over `effect-worth.ts`'s `onlyUntilEndOfTurn`/`temporaryEffectCanMatter`; v1 obeys it too): the live bot was casting Unleash Fury on an opponent's creature in its own upkeep. Nor is anything that costs mana (cycling included) in its own upkeep or draw step with nothing on the stack, or in its own main phase with only its own abilities on the stack (`holdsManaForMain`): the rollouts pass at every window, so the main phase's spells never appear in them and upkeep mana looked free. Nor is a creature that counters a spell as it enters (`effect-worth.ts`' `entersToCounter` — Transcendent Dragon, Mystic Snake) with no opponent's spell on the stack (`holdsForASpell`; such a card also counts toward `answers`), nor, in our own first main phase, a board wipe that would take a creature of ours able to attack this turn (`holdsWipeForCombat`: it waits for the second main phase; a one-sided wipe, or one our attackers survive, is left alone) — though v2 still scores it, and if it scores best passes to combat with its mana intact (`lastHeldForCombat`) rather than letting a cheaper play spend it. A counter-creature is held only until the end of the turn before ours, then cast for its body. v1's blocks, which v2's attack planner predicts every defender with, take worthwhile trades and gang blocks (`blockWorth`, `gangLoss`), skip deathtouch attackers and block with one token of a stack; v1's attack check sees evasion and gang blocks. v1 obeys both. Help aimed at an **opponent's** creature is a candidate only while that creature attacks someone else, and then only if it ends at end of turn, the creature is goaded by us, or — for lasting help, a counter or an Aura — the player attacked dies in the rollout (`opponentPump`, the user's rule). An ability it could activate again at once is also tried as a **batch** — as many times as the mana allows, one candidate (`simulateRepeated`; a targeted one twice, every activation at the same target and each at a new one, `nextInBatch`) — and once chosen, the rest go on the stack without searching again (`continueBatch`). It doesn't search a window it has already decided either (`holdPass`): after a batch, after its own spell or ability, or after it passed, while the stack only resolves — the candidate it chose was scored as exactly that, passed through to resolution; anything new on the stack is searched — except our own board wipe about to take a creature of ours (`ownWipeOnStack`), searched again since the cast was scored with no answer of ours to it (Yahenni sacrificing into its own Blasphemous Act). Seed 50's bench timeout (Lathliss pumps and Scavenging Ooze exiles, a full search each, on a seventy-permanent board) is what found both. Between a batch's activations it asks only that ability's offers (`Game.legalActivationsOf`, `legalActions` narrowed to one source — the whole list plans a payment for every ability on the board, and asking it was a quarter of seed 50's turn 40). A **cantrip** — a spell that only draws and filters (or grants an extra land drop, which the rollouts never use: Explore, Urban Evolution) and leaves us a card up for it (`isCardFlow`, counting net cards: Opt, Ponder, Brainstorm, Expressive Iteration, Compulsive Research aimed at ourselves; not Faithless Looting) — or a suspend (`isSuspendDue`) scores a wash against passing, since seeing and choosing cards leaves nothing in the state, so when the search would pass it is cast anyway at its moment (`isCantripDue`): an instant at the end of the turn before ours (`isEndOfTurnBeforeOurs`, shared with `isCreatureFetchDue`), a sorcery in our own main phase. A window where passing is the only move it would consider costs no simulation at all (most windows in a game; it was a third of the bot's CPU). `EvalBotController.lastDecision` records what the last decision cost, for tests and measurement. `bot/capture.ts` turns a position saved from a live game (see the server's `capture.ts`) into a training scenario: `captureOptions` (everything the player could do there, ranked as the search ranks it, described by `describeMove`), `sameMove` (action equality, whatever order the fields were built in) and `scenarioFromCapture`; `bot:scenarios` and `bot:fit-scenarios` add every open capture (`captures/*.json`) to the training scenarios and every resolved one (`captures/resolved/`, each with a `resolved` record: when, at which commit, what fixed it) to the gate, so a fixed blunder that comes back fails it (`engine/scripts/captures.mjs`). `npm run bot:captures -w engine` lists them all with v2's answer today; `-- resolve <file or name part> --note "…"` stamps and moves one once v2 gets it right (refused while wrong, unless `--force`), `-- reopen` moves one back. Captures are git-ignored, so a fix also gets a committed gate scenario. `castCandidates` tries only a spree offer's `modeSets`, the largest set of fillable modes first. `combat-math.ts`'s `canBlock` reads shadow the same way.
- **`mana-payment.ts`** — the mana solver, lifted out of `game.ts`: `planPayment` (the entry point `Game.payMana` wraps) = `resolveHybridCost` (hybrid/twobrid/Phyrexian pips → a concrete cost + the life they owe) → `planManaPayment` (a greedy solver: floating mana first, then coloured pips, then `{C}`, then generic, tapping a fresh source only when the already-tapped ones can't cover it; a converter — a Signet, whose own `{1}` another source pays — is reached for last, and when that plan fails a second pass funds the converters first, so two lands and a Signet pay a `{3}`). Where a cost leaves the colour open (a generic pip off a dual land, an "any colour" unit), it makes the first of `ManaPlanningView.preferred` — `Game.deckColors`, the payer's colours most-played first, held to their commander's identity — and an "any colour" unit is always a colour, never `{C}`. A generic cost reduction that outran the generic part rides on `ManaCost.twobridReduction` (`mana.ts`'s `reduceManaCost`, which `castingCostOf` applies) and comes off only the twobrid pips `resolveHybridCost` ends up paying generically — the Spectral Procession ruling. Also `ManaOption`/`ManaSource`/`ManaPlanStep`/`ManaPayment`/`ManaPurpose` (`ManaOption.extras`: the units triggered mana abilities add, the planner tracking each through `Tapped` so a step lists its own units first and the extras — `extraFrom` — last), `multipliedManaOption` (a `tap-for-mana` replacement on one option) and the `standaloneManaChoices`/`manaCombinations` enumerators `Game.manaSources` builds options with. **Everything here is pure** — it returns a *plan* and never applies one, so `Game` stays the only writer of `GameState` (`useManaSource`/`executePayment` are still methods). What the planner may read is declared by `ManaPlanningView` (pool, life, sources, a `canPay` closure for rule 106.6b, and `spendAs` — `SpendAs`, "spend mana as though it were mana of any color" / "mana of any type can be spent", rules 118.14 and 609.4b: `costAsSpendable` folds the pips any unit may pay into generic, every coloured pip and with `"any-type"` every `{C}` too, as `planManaPayment` starts and on the `resolved` cost `spendFromPool` deducts, so the planner and the spend agree and the mana actually spent is still recorded as itself; `Game.spendAsFor` works it out per payment, from the payer's `spendManaAs` statics and, for a cast, the permission it's cast under — read while the card is still where it's cast from, and as the face being cast, `ManaPurpose.face`) rather than being whatever `this` exposed; `Game.manaPlanningView` builds it, which also resolves `manaSources` once per payment instead of once per hybrid-pip trial. `cantPayLife` (rule 119.8 — "can't lose life") stops the planner paying a Phyrexian pip with life or taking a `Pay N life` mana option; a painland's damage is still allowed. An option's (and a step's) `counterCost` is an `AbilityCost.addCounter` the payment pays (Wall of Roots).
- **`decisions/`** — one module per `AwaitingDecision` kind (22), each owning that kind's *answer* half: its `LegalAction` projection, its `whyCannot` validator, its `ask` (one arm of `controller.ts`'s `answerAwaited`), its bot `candidates`, its `randomAnswer` (the fuzzer's arm, reached via `randomAnswerFor` — `RandomController` keeps only the six priority arms), and the per-kind predicates `hasSource`/`mayAct`/`autoAnswer`. `contract.ts` holds `DecisionModule`, `DecisionReadCtx` (what a module may read), `DecisionHost` (`Game.dispatch`'s decision arms transposed — every one was already a one-line delegate, so **no `apply*` body moved**) and the two total `as const satisfies` tables `DECISION_ACTIONS`/`DECISION_OFFERS`. `registry.ts` is the table plus `decisionFor`/`decisionForAction`/`decisionForOffer`/`mayActOn`/`decisionHasSource`/`autoAnswerFor`/`randomAnswerFor`; `define.ts` holds `defineDecision` **in its own file on purpose** — the registry imports every module, so a module importing the registry back is a value cycle whose symptom is `TypeError` at module init, not a build failure. `shared/` holds `picks.ts` (the four checks a validator keeps rewriting), `subsets.ts`, `target-combos.ts`, `mulligan-math.ts`. `choose-from-zone` also checks an offer's `together` — a rule over the picks as a set, from `../zone-choice-together.ts` — in `whyCannot`, keeps only legal sets in `candidates`, and turns a controller's or a random pick into the nearest legal one (`completeTogether`) in `ask` and `randomAnswer`. **Nothing under `decisions/` may import `game.js`, and `state.ts` may not import from `decisions/`** (`choose-creature-type.ts` imports `printedCardName` as a value, so the reverse closes a real ESM cycle). To add a kind: write the module (including a `randomAnswer` — optional on the contract, but the fuzzer stalls without one, so `registry.test.ts` requires it), register it, add it to both tables, add a fixture to `test/decisions/registry.test.ts` — the compiler names every step you skip, but not the raise, which is still hand-placed (`pay-life-for-untapped` has no `begin*` at all; its raise is inlined in `moveObject`). `choose-targets` validates and applies a triggered ability's `division` (`divisionOf`) when its offer has a `divide`; `shared/target-combos.ts` leaves out an empty tail for a group with a `min`. A `choose-from-zone` offer carries `order: true` when only an order is asked (library ordering — every card picked, in the order they go); its bot candidates for an `"exile"` destination (a graveyard-exile cost) rank the least valuable first, as a sacrifice's and a discard's do. `shared/random-cast.ts` casts a spree offer with one of its `castModal.modeSets`.
- **`combat/`** — the combat predicates as free functions over `(state, registry, …)`, so decision modules and the client's public seam can ask without holding a `Game`. `eligibility.ts`: `whyCannotAttack`, `whyCannotBlock`, `legalDefenders`, `creatureDef`, `attackRequirementsForbid` (rule 508.1d — the most attack requirements obeyed, per creature: a goad's "a player other than [the goader]", which a planeswalker doesn't satisfy, encore's "that opponent", an `attack-requirement` rule's; `mustAttack` is whether any can be), and **`defendersForAttacker`** — which defenders *this* attacker may be sent at, not the union, a distinction goad (701.15b) and Vow of Duty make load-bearing. `whyCannotAttack`'s `AttackAsOf.nextTurn` asks as of its controller's next combat instead of now, for `playersAttackableNextTurn`. `damage.ts`: `standardAssignment` (the one copy of the default split — kill as many blockers as possible, the ones needing least first and indestructible ones last, then trample the rest over or leave it on a blocker — shared by `Game`, every controller and the client's damage bar), `lethalFor`, `liveBlockersOf`, `needsDamageAssignmentChoice`, `damageAssignmentViolations` (rule 510.1c). `blocking.ts`: `blockingViolations` — the set-level rules (menace, Lure, "must be blocked if able" via `ifAblePlan`) that can only be judged once a whole declaration is known, checked **against the offer** rather than the board so the engine's validator and the client's Confirm button cannot disagree; `obeyingLure` is the fix-up every bot policy finishes its blocks with. `attacking.ts` is its attack-side twin: `attackingViolations` — a creature that must attack if able ("attacks each combat if able", goad, encore — the offer's `mustAttack`) left out of the declaration, which the validator refuses (rule 508.1d) and the client won't confirm — and `withRequiredAttackers`, which sends a left-out one at its first defender for a driver that doesn't choose (a bot, a test's scripted player, via the decision's `ask`). `stack-counts.ts`: a declaration's `count` — how many of a compacted token stack attack or block with one entry (rules 508.1a / 509.1a: each token's choice), several entries naming one stack when each gives a count, an entry without one the whole stack; `whyCountsInvalid` is both validators' check, `declaredTokens` what the must-attack check reads (a stack that must attack attacks whole), and `blockingViolations` weighs an entry by its count for menace and Lure. `Game.materializeStack` wakes exactly that many and leaves the rest compacted. A static's `cantBeBlockedBy`/`canBlockOnly`/`cantAttackController` are read in `whyCannotBlock`/`whyCannotAttack` rather than folded into characteristics, so their scopes may ask about power; a block filter's `{ amount }` operands read its static's own source (`goad.ts`'s `sourceAmount` — Champion of Lambholt's "power less than this creature's power"). `Game` keeps one-line delegates for its own callers. Skulk (rule 702.118b: no blocker with greater power) is in `whyCannotBlock` and the bot's `combat-math.ts` `canBlock`. `whyCannotAttack` hands `canAttackDespiteDefender` the defender, so a permission that names only some defenders (Weathered Sentinels) is judged per defender. Shadow (rule 702.28b) is one of the block checks: a creature with it blocks and is blocked only by creatures with it.
- **`primitives.ts`** — branded `PlayerId`/`ObjectId`, seeded `Rng` (mulberry32), `shuffle`.
- **`auto-settle.ts`** — `isSettled(state)` / `autoSettle(game)`: cascades past every "dead" priority window in one go. `Room` uses `isSettled` as its per-hop predicate but deliberately never `autoSettle` — it has to stop at every bot action to publish a frame, and per-seat auto-pass/skip-mana-only are one-shot-per-call, neither of which survives a cascade. `autoSettle` itself is now only used by tests/scripts that want a game settled in one call.

Snapshot/restore: `game.snapshot()` → `cloneGameState(state)` (`state.ts` — a plain-tree deep copy, ~2× faster than `structuredClone`, which stays the reference in `test/clone-state.test.ts`; bot search clones a state per simulated candidate, so this is the "candidates per decision budget" path); `Game.fromSnapshot(snap, env)` rebuilds (re-supply `registry`/`controllers` via `env`). Determinism: same seed + same controllers ⇒ identical replay.

## Engine commands, in full

- `npm run token:art -w engine` (`-- --write` to patch) — finds a real Scryfall printing for every `cards/tokens/` entry. A token can't resolve art by name the way a card does: ours are named for the engine key ("3/3 Beast Token") and Scryfall names printings after the creature alone ("Beast"), so `CardImage` skips the lookup for a token with no `art` and draws a text panel — which made tokens render hit-or-miss. The link comes from Scryfall's `all_parts` (the "Tokens" list on a card page) reached through the pool's own `create-token` effects, then matched on P/T, colours and subtypes. Keywords **rank** rather than filter, because both directions occur: Wurmcoil Engine's two Wurms differ only by deathtouch vs lifelink, while Chandra, Acolyte of Flame's Elemental is a vanilla printing whose haste comes from the spell. A printing carrying *fewer* subtypes than the definition (Oracle errata the physical token predates — "Wurm" vs "Phyrexian Wurm") matches at a lower tier and is flagged for eyeballing.
- `npm run gen:edhrec-rank -w engine` — rebuilds `cards/edhrec-rank.ts` from Scryfall (checked in; rerun as the pool grows, or to refresh the ranking).
- `npm run gen:flavor-names -w engine` — rebuilds `cards/flavor-names.ts` from Scryfall (checked in; rerun when a set with flavor names comes out).
- `npm run card:lookup -w engine -- "Card Name"` — the card's authoritative mana cost/type line/Oracle text/rulings and the tokens it makes (`engine/scripts/scryfall-lookup.mjs`), read from the checked-in **Oracle snapshot** (`engine/data/oracle/cards.jsonl` — every Commander-legal card and token, one line each, rulings folded in), so it works offline and in cloud sessions; only a card the snapshot lacks goes to Scryfall. Run this before authoring a new card — see `cards/AUTHORING.md` §1.
- `npm run gen:oracle -w engine` — rebuilds that snapshot from Scryfall's bulk data (Oracle Cards + Rulings, downloaded whole into the git-ignored `engine/.cache/scryfall/`, ~40s); rerun when a set comes out.
- `npm run card:scaffold -w engine -- "Card Name" | --next N [--cards] | --auto-scan [--all]` — writes card files from the snapshot into `engine/src/cards/scaffold/`: the stat block, `text`, rulings, keywords, pairing and tokens, and then whatever `scripts/oracle-parse.mjs` reads of the rules text. It reads two tiers: an ability's structure (cost or trigger, targets, restrictions) and its effect, whenever a whole sentence matches a template. Each line it can't read is left as a `// TODO(scaffold):`. A card whose every line was read goes, finished, into `engine/src/cards/review/`. `--report` writes nothing and lists the unparsed lines that recur most. `npm run card:parse-check -w engine` compares every ability the parser claims to have read with the hand-authored pool, and `test/oracle-parse.test.ts` requires zero disagreements. **Neither folder is registered** — authoring (or checking, with `card:verify -- --dir review`) and then moving the file into `pool/` is what puts a card in the game. `pool.test.ts` fails on a `TODO(scaffold)` in `pool/` or `tokens/`. See `cards/AUTHORING.md` §1.
- `npm run card:verify -w engine` — diffs every `cards/pool/` card's mana cost/colors/types/subtypes/P-T/loyalty against real Scryfall data, batched (`engine/scripts/verify-cards.mjs`). Structural fields only, not ability text. See `cards/AUTHORING.md` §16. **Every card in `pool/` is a real Magic card** — the pool's 27 invented placeholders were replaced with real printings of the same mechanic (see `neededCards-features.md` "E2"), so a `NOT FOUND` from this script now means a made-up or misspelled card, not a known exception. `tokens/` is exempt (token names aren't unique on Scryfall).
- `npm run card:text -w engine` — the same script's `--text` mode: the **rules-text** audit. It splits each card's `text` and Scryfall's `oracle_text` into clauses (one per line, then per sentence), matches every clause of the real card to its closest clause in ours by a set-similarity score over normalised tokens (the card's own name, "this creature", punctuation and reminder text are all normalised away first), and reports what didn't match — `MISSING` for a clause the pool dropped, `EXTRA` for one it has that the real card doesn't; `--similar` also shows the loose matches. Two false-positive classes are suppressed: a bare keyword line already on `def.keywords` (the client renders those from the keyword list) and a typed dual land's `{T}: Add` (implicit in Scryfall's type line, rule 305.6). **`cards/AUTHORING.md` §0 ("faithful, or not at all") is the standard this measures against**: a card whose printed behaviour the engine can't run is not authored at all, so every `MISSING` line should be either a paraphrase of `text` or one of the pre-rule cards on §15's "Known exceptions" debt list — never a new omission. It is still not a hard gate, and it is **blind to a clause that is present but wrong** (Saw in Half's tokens were the wrong size inside a clause it scored as matching), so read the output rather than counting it. `--lines` is the older, narrower check that compares only the number of text lines (the client renders `text` verbatim, so a missing `\n` runs two abilities together).
- `npm run test -w engine` — vitest, single pass (CI mode); `-- path/to/file.test.ts` for one file, `-- -t "name"` for a name match
- `npm run test:watch -w engine` — vitest watch mode
- `npm run build -w engine` / `npm run typecheck -w engine` — the build is `tsc`, then `scripts/bundle-shards.mjs`: each `dist/cards/shards/shard-NN.js` bundled (rolldown, pinned as the engine's own devDependency) with its card files inlined and every shared module left an import. Vite's dev server doesn't bundle, so without it the library and deck builder made one request per card (~5,800) and took 39 s to open after the dev server started; with it, ~160 requests and under 1.5 s. A production client build comes out the same either way. Only the client loads shards, so nothing else sees the difference; a `tsc --watch` build leaves them unbundled, which still works, just slowly.
- `npm run play:random -w engine` — `engine/scripts/random-demo.mjs`: N random-vs-random games (`-- --games 300`, `-- --log`, `-- --players 3|4`, `-- --progress` to announce each seed on stderr before playing it, `-- --seed 19` to replay exactly one seed, `-- --timeout 60` to set the per-game wall-clock limit in seconds, default 30). This is the engine fuzzer — if `legalActions` ever offers something `dispatch` refuses, or an unbounded loop/object-count blowup happens, it reports `FAILED seed N` and exits non-zero. **Each game runs in a worker thread (`random-game-worker.mjs`) that's killed if it overruns the limit**: a runaway loop *inside* one `tick()` never yields, so neither a timer in the same thread nor `Game.advance`'s tick budget (which only counts ticks that return) can stop it, and before this a single stuck game stalled the whole run silently. A failure no longer aborts the run — every failing seed is collected and listed at the end. **Every seed deals each seat its own 100-card Commander deck from the whole pool** (`engine/scripts/fuzz-decks.mjs`): a commander, then the next window of a fixed walk through the pool's spells and nonbasic lands (the commander chosen, from a random dozen, as the one whose identity fits most of that window), then basics. So a run of seeds sweeps the pool, and a new card is fuzzed with no edit anywhere. A seat only takes the window's cards inside its commander's identity, so at ~5,400 deckable cards 150 two-player seeds reach all but a few dozen, and CI's 38 games about three quarters (BACKLOG). `-- --with "Card Name"` (repeatable) puts a card in every seat's deck, and `-- --coverage` plays nothing and reports how much of the pool the seeds reach. A few cards that mean nothing alone bring a partner along (`PACKAGES`: Skullbriar brings Reanimate). These replaced four hand-kept lists that had grown to 150-500 cards each, where a game drew a given card one time in six and never ran out of library.
- **Bot measurement** (all in `engine/scripts/`, all `worker_threads` pools over `SAMPLE_DECKS`; see `docs/plans/smarter-bots.md`). Seeds come in blocks of `--players` games, one seating per block with the measured seat moving round the table, so deck strength and play/draw cancel (`bot-seating.mjs`, shared). `npm run bot:bench -w engine` — a weight vector's win rate against v1 (`-- --opponent <champion id>|mixed|gauntlet`, `-- --players 4`, `-- --weights JSON`, `-- --games N`, `-- --candidate-options JSON` for `EvalBotOptions` on the measured seat only — how the `"acting"` rollout was benched against the same build). `bot:tune` — a (1+1)-ES over the weights, head-to-head against the incumbent with the gauntlet as a veto. `bot:harvest` then `bot:fit` — harvest labelled positions from self-play, then fit weights to them by logistic regression (the ES buys one accept/reject bit per 200 games; the same games hold ~150k labelled positions). A fit is a lead, not a verdict: it raised `power` to 2.03 where the four-player sweep peaked at 0.5 — a big board predicts a win, which doesn't make a bot that values power highly win more. **Shipped weights are set by four-player sweeps and benches**, or — where a term exists to cancel another, like `idlePower` against `power` — by that structure, with a scenario to show it. `bot:scenarios` — the opponent-independent gate any candidate vector must pass, exits non-zero on a failure, and reports the training scenarios beside it. `bot:fit-scenarios` — for each scenario a vector gets wrong, every single weight that would fix it, the nearest value that does and what it breaks; then the vector those levers add up to, pulled one at a time and played for real (`--out` writes it for `bot:bench --weights`; `--joint` adds a coordinate-descent fit, untrustworthy on a small corpus). **Diagnostics, which is where most of the real findings came from**: `bot:behaviour` plays a few dozen self-play games and counts what a watching player would notice — targets aimed at the wrong side of the table (judged by `target-polarity.ts` with each seat's deck bias; harm at its own permanent with a "when this dies" trigger, a Dragon Egg, is tallied apart as a play), own turns that end with a sorcery-speed spell castable and unplayed, skipped land drops, and time by kind of window against the room's budget (`--budget 300` by default, on 8 workers because contention changes what a wall-clock budget buys; `--budget none` is exact and takes every core; `--weights JSON` compares two vectors on the same seeds); `bot:crackback` (`bot-crackback.mjs`, 2026-10-05) logs every v2 self-play attack declaration — everything able to attack sent, some or none — with what the table showed (the next opponent, every opponent all-in, and the bot's own check, through `combat-math.ts`) on three boards (holding everything back, the declaration, and the handoff: the board the opponents got once its turn ended), and whether it died before its next turn and to what (creatures on the board at the swing or arriving after, noncombat, haste native or granted, haste enablers showing); `--weights JSON` plays every seat on another vector, resumable NDJSON in `.scratch/crackback-v2-<n>p.ndjson`, `--report FILE` reprints one; `bot:audit` prices a card by spawning it on a fixed board and printing the score change (`-- --rollout` adds what it's worth once the next turns are *played out*, and the gap between the two columns is the enablement a static score can't price). Every one of these takes `--champion <id>` where it makes sense. **Across commits** (`baseline-build.mjs`: the engine at a git ref built from `git archive` into the git-ignored `.scratch/baseline/<sha>/`, beside a frozen copy of the working `dist`, one table seating both since `GameState` is plain data): `bot:ab` benches the working bot in one seat against the baseline's in the rest (`--base origin/main`, `--bot v1|v2`, resumable NDJSON in `.scratch/`), and `bot:diff` plays every seat on the working build while asking the baseline's bot each same question, listing every disagreement in words — what a change changed, where a bench only says whether it won. `bot:replay` plays one seed (`--snapshot-at TURN` saves `.scratch/replays/seed-N-tTURN.json`; `--from FILE` restarts there, from a snapshot or a `captures/` capture or bug report) logging slow decisions, activations and each turn's time. **Deck strength** (2026-10-02): `bot:decks` (`deck-winrates.mjs`) seats the same bot in every seat over all of `SAMPLE_DECKS` — each round deals every deck once into tables, each table played once per seat rotation — and prints each deck's win rate (Wilson interval), average finish and winning turn; resumable NDJSON in `.scratch/deck-winrates-<bot>-<n>p.ndjson`. It's what decides a deck's `bench` flag, and beside a v1 run, which decks the search helps. `bot:autopsy` (`deck-autopsy.mjs`) replays one of its games exactly and prints each turn: every player's life, hand, library, graveyard, lands and board (`--hands` adds the hands), and the plays — lands, spells, activations, attacks and their targets, damage to players, mills, mulligans.
